# AI Factory Studio · Decision UI V3

## V3의 설계 전환

V2가 전체 제품의 통일된 디자인 언어를 만들었다면, V3는 사용자가 실제로 **판단하고 클릭하는 순간**을 제품의 중심에 둔다.

| V2 | V3 |
|---|---|
| 화면별 정보와 기능 탐색 | 화면당 핵심 결정 1개를 중앙에 배치 |
| 작은 상단/우측 액션 | 선택지 바로 아래의 큰 실행 버튼 |
| 카드·메뉴 중심 구조 | 결정 → 선택지 → 영향·근거 → 확정 구조 |
| 정보 상태 표시 | 판단 대기함과 고정 Decision Dock |

## 공통 UX 규칙

1. 한 화면에는 우선순위가 가장 높은 의사결정 하나만 크게 보여 준다.
2. 선택지는 최대 3개이며, 추천안·범위·비용·데이터 영향이 함께 보인다.
3. 사용자가 누르는 핵심 버튼은 선택지 바로 아래와 화면 하단 Decision Dock에 중복 배치한다.
4. “승인”은 단순 진행이 아니라 어떤 작업·범위·근거를 남기는지 설명한다.
5. Atlas는 별도 채팅으로 밀어내지 않고, 결정이 어려운 순간 바로 도움을 요청할 수 있게 한다.

## 화면 목록

| 파일 | 중심 의사결정 |
|---|---|
| `index.html` | 사업계획 시뮬레이터의 제품 방향 선택 |
| `factory-decision.html` | SW 생성 아키텍처 승인과 WBS 시작 |
| `twin-decision.html` | 원가 상승 대응 시나리오 선택과 실행 |
| `data-decision.html` | 지식 팩의 조직 범위 승인과 색인 |

## 확인 방법

```powershell
python -m http.server 8091 --directory uiux-prototypes/v3
```

브라우저에서 `http://localhost:8091`을 열면 된다.

## 실제 구현 시 반영 대상

- `ControlPanel`: 핵심 실행 버튼을 상단 외곽이 아니라 결정 카드 하단으로 이동
- `HOTLInput`: 자유입력 중심에서 선택지 기반의 승인 카드로 전환
- `PreviewPanel`: 결과 미리보기와 영향·근거를 동일 맥락으로 연결
- `KnowledgeHubPanel`: 문서 목록 중심에서 승인 결정·범위 영향 비교 중심으로 전환
- `MegaBoardroomPanel`: 진행률 나열보다 경영진의 판단 대기함과 드릴다운으로 재구성
