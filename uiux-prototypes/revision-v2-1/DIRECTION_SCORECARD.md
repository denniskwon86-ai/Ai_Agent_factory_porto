# Revision V2-1 방향성 평가표

이 세트는 화면 수를 늘리기 전에 AI Factory Studio만의 제품 세계관이 실제로 보이는지 검증하기 위한 대표 화면 3종이다. 화면별로 `채택`, `부분 채택`, `재설계` 중 하나를 판정한 뒤 나머지 기능 화면으로 확장한다.

## 공통 판정 기준

| 기준 | 확인 질문 | 통과 기준 |
|---|---|---|
| 독창성·세계관 | 제품명을 다른 이름으로 바꿔도 흔한 SaaS 화면처럼 보이는가? | 회사·SW 생성·경영 Twin이라는 고유 개념이 공간 자체에서 읽힌다. |
| 업무 적합성 | 사용자가 이 화면에서 무엇을 하는지 5초 안에 이해하는가? | 주 작업과 다음 행동이 설명 없이 드러난다. |
| 핵심 행동 | 중요한 버튼이 작거나 외곽으로 밀려 있지 않은가? | 화면의 중심 동선에서 주 행동을 발견하고 실행할 수 있다. |
| 가독성 | 정보량이 많아도 작은 글자와 장식에 의존하지 않는가? | 본문 14px 이상, 제목·수치·상태의 위계가 분명하다. |
| 제품 사상 | 실제 데이터, 회사 범위, 권한, 근거, 에이전트 협업이 보이는가? | 단순 AI 생성기가 아니라 기업 운영체계라는 점이 전달된다. |
| 사업 매력 | 경영진·투자자가 결과와 확장성을 직관적으로 이해하는가? | 왜 필요한지와 어떤 가치가 만들어지는지가 한 화면에 연결된다. |
| 구현 현실성 | 현재 React·API·상태 모델로 단계적 이식이 가능한가? | 시각 은유를 유지하면서도 기존 기능과 명확히 매핑된다. |

## 01. Enterprise World

- 목적: 로그인 이후 회사·사업부·공장·가상회사를 선택하고, 해당 권한과 산업 특성 위에서 전체 제품 기능으로 진입한다.
- 차별점: 좌측 메뉴와 카드 목록 대신 회사를 중심으로 지식·운영·SW·Agent·Twin·릴리스가 연결된 기업 세계를 보여준다.
- 반드시 확인할 것: 조직 계층이 커졌을 때 탐색이 가능한가, 권한 범위와 현재 회사가 충분히 선명한가, 주요 기능 진입이 지도 장식에 묻히지 않는가.
- 현재 판정 제안: **채택 후보**. 홈·전체 기능 사이트맵의 중심 언어로 발전시킨다.

## 02. Software Production Line

- 목적: 현업의 요구가 명확화·데이터 접지·설계·WBS/Agent 조립·구현·검증·릴리스로 진행되는 과정을 통제한다.
- 차별점: 일반 프로젝트 칸반이 아니라 실제 제품을 조립하는 생산라인으로 AI Factory Studio의 핵심 기능을 설명한다.
- 반드시 확인할 것: 장시간 진행·재작업·HOTL·실패 인계가 같은 라인에서 이해되는가, 사용자가 현재 병목과 다음 행동을 즉시 찾는가.
- 현재 판정 제안: **채택 후보**. 기존 Control/Timeline/Preview의 정보를 생산라인 상세 패널에 매핑한다.

## 03. Future Scenario Room

- 목적: 대외지표와 내부 운영 조건을 조정하고 손익·현금·생산·납기·리스크 변화 및 의사결정 대안을 비교한다.
- 차별점: KPI 카드 모음이 아니라 미래 궤적을 직접 움직이는 경영 의사결정 공간이다.
- 반드시 확인할 것: 가정과 실제 데이터가 구분되는가, 결과 근거와 신뢰도가 함께 보이는가, 시나리오 비교·저장·승인 동선이 충분한가.
- 현재 판정 제안: **채택 후보**. 경영 Digital Twin의 대표 데모 화면으로 발전시킨다.

## 채택 이후 확장 순서

1. 세 화면의 공간 모델과 공통 글꼴·상태·접근성 규칙을 확정한다.
2. Atlas 상담, 데이터·MDM, 운영 그리드, 개인화 포털, Agent 관리 화면에 가장 가까운 공간 모델을 배정한다.
3. 기존 React 화면·API·상태 필드와 1:1 매핑한 화면 기능 명세를 작성한다.
4. 컴포넌트화 전에 대표 화면 한 개를 실제 프론트엔드에 카나리 이식한다.
5. 사용자 과업 테스트 후 나머지 화면으로 확장한다.
