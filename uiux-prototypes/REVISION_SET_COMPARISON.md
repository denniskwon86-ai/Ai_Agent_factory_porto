# UI/UX 후보 비교 이력 · Set A vs Set B

> **2026-07-30 판정 변경:** Supervisor의 시각 검토 결과 Set B(Revision V3)는 기능별 이름만 다르고 일반적인 AI/SaaS 관리자 화면 문법을 반복해 최종 후보에서 제외했다. Set B의 공통 글꼴 원칙만 유지하며, 현재 권고안은 Set A의 독창성을 제품화한 `revision-v2-1/` 대표 화면 3종이다. 아래 내용은 판단 이력으로만 보존한다.

## 세트 성격

| 구분 | Set A · Revision V2 | Set B · Revision V3 |
|---|---|---|
| 목표 | 화면별 개성과 새로운 경험을 최대화 | 하나의 상용 제품처럼 통일성과 학습 용이성 확보 |
| 글꼴 | 화면 콘셉트에 따라 변화 | Pretendard/Noto Sans KR로 통일, 숫자·코드만 고정폭 |
| 색상 | 기능 콘셉트마다 크게 변화 | 회사 Shell·상태색·버튼 공통 토큰 사용 |
| 장점 | 강한 인상, 기능별 최적 경험, 외부 데모 차별성 | 일관성, 구현 효율, 사용자 학습, 유지보수 |
| 위험 | 하나의 제품처럼 보이지 않을 수 있음 | 안전하지만 개성이 약해질 수 있음 |

## 당시 통합 권고 원칙 · 현재 폐기

1. 최종 제품의 공통 글꼴·Shell·상태색·버튼은 Set B를 기본으로 한다.
2. 특정 기능의 핵심 경험이 명확히 좋아지는 경우에만 Set A의 구조를 적용한다.
3. 다른 글꼴은 V3의 중요 의사결정 제목, V5 문서 표지 등 제한된 표현 포인트에만 허용한다.
4. V4·V5·V7·V9·V10처럼 사용 목적이 다른 두 안은 하나를 폐기하기보다 기본 보기와 상세 보기로 결합할 수 있다.
5. 실제 적용 전 주요 사용자 역할별로 5개 과업을 수행하게 하고 완료 시간·오류·주관 만족도를 비교한다.

## 이전 검토 권고 · 현재 폐기

- Set A: 제품의 독창성과 기능별 강한 경험을 평가한다.
- Set B: 실제 상용 제품으로서 일관성·가독성·구현성을 평가한다.
- 당시 최종안: Set B 디자인 시스템 위에 선택된 Set A 경험을 이식하는 방식이었다.

## 현재 진행 방향

1. 공통 Shell을 먼저 강제하지 않고 회사 세계·SW 생산라인·경영 시나리오룸의 고유 공간을 보존한다.
2. UI·본문은 Pretendard/Noto Sans KR 계열로 통일하고 수치·코드만 고정폭 글꼴을 사용한다.
3. 대표 화면 3종을 먼저 시각 검토한 뒤 채택된 문법만 나머지 기능에 확장한다.
4. 기능 누락은 `revision-v2-1/CONTENT_COVERAGE.md`, 채택 판단은 `revision-v2-1/DIRECTION_SCORECARD.md`로 통제한다.
