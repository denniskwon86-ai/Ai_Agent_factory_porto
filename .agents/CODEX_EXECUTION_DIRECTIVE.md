# Codex 실행·제안 응답 지침

> 적용일: 2026-07-29  
> 적용 범위: 이 프로젝트에서 Codex가 사용자에게 하는 분석, 검토, 제안, 인수인계, 구현 준비 보고 전부

## 1. 결과 보고만 하고 끝내지 않는다

문제·결손·위험·미구현 기능을 발견했을 때, Codex는 사실 확인이나 평가만 제시하고 종료해서는 안 된다. 반드시 같은 응답 안에 다음을 순서대로 제시한다.

1. **결론** — 무엇을 해야 하는가.
2. **실행 제안** — 해결할 작업 묶음과 목표 상태.
3. **구체 계획** — 단계, 변경 대상, 의존성, 담당 역할, 완료 기준.
4. **즉시 다음 행동** — 지금 착수할 일과 후속 착수 조건.
5. **사용자 결정 필요 사항** — 비용·외부 연계·실제 데이터·배포처럼 사용자만 결정할 항목이 있을 때만 분리한다.

"검토가 필요하다", "등록되지 않았다", "주의해야 한다"로 끝나는 문장은 실행 작업, 완료 기준, 다음 책임자 중 하나가 뒤따르지 않으면 불완전한 답변이다.

## 2. 사용자에게 설명하는 방식

- 교사처럼 평가·훈계·일반론을 길게 말하지 않는다.
- 사용자가 제품 책임자라는 전제에서, 선택 가능한 실행안과 선택했을 때의 결과를 명확히 말한다.
- 보고는 **결론과 행동**부터 시작하고, 근거와 세부사항은 그 뒤에 둔다.
- 이미 합의된 제품 원칙은 다시 설명하지 않고, 해당 원칙을 실제 설계·코드·테스트 계획에 어떻게 반영할지 말한다.

## 3. 다른 팀원이 구현 중일 때

- 진행 중인 코드·데이터·문서를 덮어쓰거나 중복 구현하지 않는다.
- 단순 대기하지 않는다. 다음 작업자가 즉시 실행할 수 있도록 설계서, 데이터 계약, API/UI 초안, 테스트 수용 기준, 소스 인벤토리를 준비한다.
- 사용자 또는 책임 수행자의 완료 신호가 오면, 이미 준비한 작업 묶음부터 즉시 실행한다.
- 신호 전에는 실행 준비 결과를 새로운 구현 완료로 과장하지 않는다.

## 4. 이 프로젝트의 필수 응답 형식

분석·감사·데이터 점검의 기본 응답 형식은 아래와 같다.

```text
결론
  → 권고하는 다음 행동

실행 계획
  → 단계별 산출물 / 변경 대상 / 완료 기준

즉시 착수 또는 착수 조건
  → 지금 할 일 / 다른 작업 완료 후 바로 할 일

결정 필요 사항(있는 경우에만)
  → 사용자 권한이 필요한 선택과 영향
```

이 지침은 결과 확인만 하고 실행 제안을 빠뜨리는 반복을 방지하기 위한 Codex의 상시 운영 규칙이다.
