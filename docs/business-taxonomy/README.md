## 이 폴더가 존재하는 이유

기업을 **사업 기준으로 찾고**, 찾은 사업에 **업무키트를 자동으로 붙이기** 위한 분류 체계를 정의한다.
KSIC 단일 트리로 좁혀 보려던 초기 시도를 폐기하고, 다면분류(faceted classification)로 전환했다.

### 왜 단일 트리를 버렸나

트리는 부모가 하나뿐이다. "리튬 화합물을 제조하면서 동시에 상사 기능으로 원료를 유통하는 회사"를
트리에 넣으면 둘 중 하나를 버리게 된다. 그러나 이 회사는 **제조 페인포인트와 유통 페인포인트를 둘 다 갖는다.**

더 결정적인 것은 검색 요건이다. 실제로 나올 질의는 이런 모양이다.

- "배치 생산 + 화학 + B2B소수고객" → 어떤 기업들?
- 업태 무관하게 "고온 공정을 다루는 모든 사업" → ?

이는 트리 탐색이 아니라 **다축 필터링**이다. 애초에 축으로 저장돼 있어야 가능하다.

## 핵심 구조 요약

### 사업 "유형" 과 사업 "인스턴스" 를 가른다

|  | 사업 인스턴스 | 사업 유형 |
|---|---|---|
| 소유 | 기업 고유 | 전체 공통 어휘 |
| 예 | "○○社 양극재사업부" | `소재제조 / 화학 / 배치 / B2B소수` |
| 개수 | 기업 수만큼 | 관리 가능한 유한 집합 |
| 역할 | 실체 | **검색 키 · 업무키트가 붙는 자리** |

관계는 다대다다. 한 인스턴스가 여러 유형에 걸칠 수 있고, 한 유형에 수백 개 인스턴스가 매달린다.

**업무키트는 인스턴스가 아니라 유형에 붙는다.** 그래야 신규 기업이 들어와도 유형만 판정하면
키트가 자동으로 따라붙는다. 이것이 AX 플랫폼 뎁스의 실질적 메커니즘이 된다.

### 축 4개 (초안)

| 축 | 성격 | 값 예시 |
|---|---|---|
| **A. 업태** (가치사슬 위치) | 무엇을 하는가 | 자원채취 / 소재제조 / 부품제조 / 완제품제조 / 시공 / 유통·상사 / 물류 / 서비스 / 지식·용역 / 임대·자산 |
| **B. 업종** (대상 영역) | 무엇을 다루는가 | 화학 / 금속 / 전자 / 기계 / 식품 / 섬유 / 건설자재 / 의약 / 에너지 / 정보 / 금융 / 사람 … |
| **C. 운영 모델** | 어떻게 돌리는가 | 연속공정 / 배치공정 / 개별수주 / 반복조립 / 프로젝트 / 상시운영 |
| **D. 고객 구조** | 누구에게 파는가 | B2B소수 / B2B다수 / B2C / B2G |

A·B가 곧 업태·업종이고, C·D가 페인포인트를 실제로 가르는 축이다.
**A·B만으로는 업무가 안 갈린다** — 같은 "화학 소재제조"라도 연속공정이냐 배치냐에 따라
품질관리·추적성·재고 구조가 전혀 다르다.

축은 4개에서 멈춘다. 5개를 넘으면 판정 비용이 급증하고 실무자가 값을 못 채운다.

### 셀 3-상태 — "채울 수 있는 칸인가"

| 상태 | 의미 | 처리 |
|---|---|---|
| **유효·충족** | 실존 + 키트 있음 | 정상 서비스 |
| **유효·공백** | 실존 확인 + 키트 없음 | **작업 대기열** |
| **무효** | 조합 자체가 현실에 없음 | 제외, 재검토 안 함 |

이 셋을 구분하면 "우리가 모르는 분야"가 **명시적 재고**가 된다. 몇 칸이 비었고 어느 순서로
채울지가 숫자로 보인다.

⚠️ 조합 폭발 주의 — 10×12×6×4 = 2,880칸이 나오는데 대부분 무효다. 그래서 **전 조합을 미리 만들지 않는다.**
실제 관측이 최초로 들어올 때 그 셀을 `유효·공백`으로 등록한다. **셀은 데이터가 만들고, 사람은 무효 판정만 한다.**
