# 판정 엔진

> ⚠️ **검토 중 — 확정된 설계가 아니다.** 현재 시스템에 연결·연계하지 않는다.
> 자세한 조건은 [../README.md](../README.md).

**AI 가 매번 판정하지 않도록** KSIC 코드에서 A·B 축을 규칙으로 판정한다.

## 구성

| 파일 | 역할 |
|---|---|
| `ksic_rules.py` | **법인 판정** — KSIC → (A 업태, B 업종, B 2단) 매핑 + 모수·묶음 판정 |
| `segment_rules.py` | **세그먼트 판정** — 영업부문명 → 축. 법인 1건을 사업 n 건으로 나눈다 |
| `fetch_ftc.py` | **수집기** — 공정위 기업집단포털에서 소속회사를 받아 판정까지 붙인다 |
| `fetch_dart.py` | **세그먼트 수집기** — DART 사업보고서에서 주석 파일을 골라낸다 |
| `parse_segment.py` | **세그먼트 파서** — 주석의 영업부문 표에서 부문명·주요제품·매출 |

## 쓰는 법

```bash
python fetch_ftc.py ALL affiliates.csv
```

기업집단 코드를 주면 그 집단만 받는다(엘지 `K1000051`, 에스케이 `K1000050`,
현대자동차 `K3000027`, HD현대 `K3000052`, 신세계 `K1000042`).

판정만 따로 쓰려면:

```python
from ksic_rules import classify
classify('C2020', 18216499)   # → 소재제조 / 화학·소재 / 석유화학·기초
classify('K6499', 884989)     # → 지주·투자 / 다품목·범용, 묶음노드 Y
classify('L6821', 0)          # → 모수밖 (매출 0)
```

## 판정 순서

규칙이 매핑보다 앞선다.

| 순서 | 규칙 | 근거 |
|---|---|---|
| ① | **매출 0 → 모수 밖** | 사업 실질이 없는 껍데기. SPC·청산·준비 단계 |
| ② | **KSIC `K6499`·`M7151` → 지주·투자 + 묶음 노드** | 그 매출이 모수 안 다른 인스턴스 매출을 포함한다 |
| ③ | KSIC 매핑 (5 → 4 → 3 → 1자리) | 긴 접두사 우선. 중분류에서 대부분 결정된다 |
| ④ | 못 찾으면 **미판정** | 억지로 채우지 않고 사람이 본다 |

⚠️ SK·현대차는 **전수 대조가 아니라 KSIC 별 검수**다. 같은 KSIC 는 같은 판정을 받으므로
코드 종류만큼만 보면 되지만, 법인별 실질 차이는 이 방식으로 못 잡는다.

남은 1건은 `C2842`(조명장치 제조업)로, KSIC 만으로는 **차량용 부품인지 일반 조명 완제품인지
갈리지 않는다.** 규칙으로 100% 를 만들 수 없고 이 정도가 현실적 상한이다 —
**나머지는 사람이 검토한다.**

## 규칙을 고치는 방법

1. 사람 판정과 대조해 불일치를 찾는다
2. `MAP` 에 **더 긴 접두사**로 예외를 추가한다 (짧은 규칙은 그대로 둔다)
3. 다시 대조한다

LG 전수 대조에서 95% → 98% 가 됐고, SK·현대차 검수에서 8곳을 더 보완했다.
보완 후 LG 재대조에서 **회귀 없이 98% 를 유지**했다.

| 보완한 것 | 이유 |
|---|---|
| `R9119` → 인적서비스 | 스포츠단은 선수 활동이 본체. `R91`(골프장) 은 시설 운영 |
| `S9531` → 전자·정밀 | 가전 수리. `S9521`(자동차 수리) 과 대상이 다르다 |
| `C2842` → 전자·정밀 | 조명장치는 전기·전자 제품 |
| `C2411~2422` → 금속 2단 | 철강 / 강관·형강·선재 / 비철금속 |
| `C3120` → 철도·특수차량 | `C31` 폴백(항공·우주·방산)이 철도차량에 붙었다 |
| `G4731`·`G4771` → 전자·정밀 / 에너지 | 휴대폰 판매 · 주유소가 `다품목·범용` 으로 갔다 |
| `N7629` → 생활용품·가구 | `N76` 폴백(기계·운송기기)이 가전 렌탈에 붙었다 |
| `M7011` → 의약·바이오 | **신약개발사가 「자연과학 연구개발업」으로 신고한다** |

## 세그먼트 분할 — `segment_rules.py`

법인 1건을 **사업 n 건**으로 나눈다. 삼성전자를 DS/DX/SDC/Harman 으로 가르는 일이다.

### 왜 별도 규칙인가

**세그먼트에는 KSIC 가 없다.** 사업보고서에 이름과 매출만 실린다.
법인은 KSIC 로 판정하지만 세그먼트는 **이름으로 판정할 수밖에 없다.**

### 판정 순서

| 순서 | 규칙 |
|---|---|
| ① | **지역 세그먼트는 버린다** (국내/북미/유럽…) — 사업 구분이 아니다 |
| ② | **회사 고유 약어** — 삼성전자 `DS`·`SDC`, LG전자 `HS`·`VS` 등 |
| ③ | **키워드 사전** — 「석유화학」「배터리」「할인점」… 긴 키워드 우선 |
| ④ | 없으면 **모법인 판정을 상속**하고 `상속` 으로 표시 |

키워드가 A 축까지 바꾸는 경우가 있다 — 현대자동차 「금융」 부문은 모법인이 제조여도
`금융` 이 된다. 반대로 「석유화학」은 B 만 바꾸고 A 는 모법인을 따른다.

### 예시

```
(주)엘지화학 [C2020] → 소재제조 / 화학·소재
   / 석유화학    소재제조  화학·소재     석유화학·기초   키워드
   / 첨단소재    소재제조  화학·소재     전자·전지소재   키워드
   / 생명과학    소재제조  의약·바이오               키워드

현대자동차(주) [C3012] → 완제품제조 / 기계·운송기기
   / 차량       완제품제조 기계·운송기기  완성차·부품    키워드
   / 금융       금융      금융                    키워드 (A 축까지 바뀐다)
   / 국내·북미                                    지역 — 제외
```

### 세그먼트 수집 — 주석을 읽는다

**DART Open API 에 세그먼트 전용 API 가 없다.** 재무정보 그룹 7개 API 는 회사 단위
계정만 준다. 그래서 사업보고서를 직접 파싱한다. 인증키는 `DART_API_KEY` 환경변수
또는 `engine/.env` 에 둔다(`.gitignore` 에 걸려 커밋되지 않는다).

**본문이 아니라 주석을 읽는다.** 본문의 부문 표는 서식이 회사마다 달라 커버리지가
26% 였다. 본문에도 「부문별 정보」 섹션이 있지만 그건 XBRL 뷰어용이라 부문명이 열
헤더가 아니라 축 레이블(「기업 전체 총계」)로 들어가 못 쓴다. 반면 **재무제표 주석**의
영업부문 공시는 K-IFRS 서식을 따라 훨씬 표준적이다.

```bash
python fetch_dart.py 051910        # 종목코드 또는 고유번호
```

공시 ZIP 안에서 주석 파일을 내용으로 골라낸다 — 파일명 접미사(`_00760`)는 회사마다
번호가 다르므로, **본문만 접미사가 없다**는 규칙으로 본문을 뺀 뒤 남은 후보를 파싱해
부문이 나오는 파일을 쓴다. 연결·별도가 함께 오면 연결이 정본이다.

#### 서식 차이를 흡수한 곳

| 함정 | 대응 |
|---|---|
| 헤더가 2단이고 「구 분」이 rowspan → 헤더가 데이터보다 한 칸 짧다 | 앞이 아니라 **뒤에서부터** 맞춘다 |
| 부문마다 당기·전기 **두 칸**을 쓴다(에쓰오일) | stride 1·2 를 시도하고 **합계 = 나머지 합**인 쪽을 택한다 |
| 수익 행이 한 표에 넷이다(SK이노베이션의 총·내부·순·기타영업) | 「외부고객 > 순매출 > 총매출」 우선순위, 내부거래 행 제외 |
| 값이 없는 라벨 행(LG생활건강 「매출액:」) | 값이 하나도 없는 행은 후보에서 뺀다 |
| 부문이 **행**에 있는 세로형(LS·LS일렉트릭) | 부문명 = 숫자가 아닌 마지막 칸, 매출 = 그 다음 칸 |
| 단위가 회사마다 다르다(CJ제일제당은 천원) | 표 **바로 앞** 캡션을 읽어 백만원으로 통일한다 |
| 지역별 정보 표가 부문 표보다 열이 많다 | 지역명은 완전일치로 막는다 — 「해외」는 빼고 「해외사업」은 살린다 |
| 종속기업 목록이 제품 표로 보인다(SK하이닉스 18곳) | 「지분율·소재지」 열이 있으면 뺀다. 매출 없는 부문은 인정하지 않는다 |
| 「하나의 보고부문」인데 아래에 지역 표가 있다(기아) | 단일 보고부문 문구를 인식해 **0 건이 정답**으로 둔다. 문서 단위로 본다 — 섹션별로 보면 그 문구가 없는 섹션에서 엉뚱한 표를 읽는다 |
| 헤더가 **3단**이다(KB금융의 은행부문이 다시 기업금융/가계금융으로) | 합계 검증이 소계 열을 집어낸다 |
| 부문 표가 회계정책 섹션에서 22 만자 떨어져 있다(KB금융) | 번호 없는 문장형 제목(「사업부문별 정보는 다음과 같습니다」)도 섹션으로 인식한다 |
| 「법인세비용(수익)」·「이연대출부대수익」이 「수익」 글자로 뽑힌다 | 비용·법인세·충당·이연·기초/증감 행을 수익 후보에서 뺀다 |
| **금융권 부문 표에 총수익 행이 없다**(신한지주는 순이자손익·순수수료손익을 따로 싣는다) | 종류별 수익은 후순위로 밀고, 총액 행이 없으면 **부문명만** 담는다 |

검증했다 — 현대자동차 175.9 조, 에쓰오일 34.2 조, CJ제일제당 27.3 조,

**금융권은 매출 지표가 통일되지 않는다.** 은행은 영업수익, 증권은 순영업수익을
쓰고, 아예 총액 행 없이 순이자손익·순수수료손익만 싣는 곳도 있다. 하나를 골라
쓰면 부분값이 되고(신한지주 은행 부문이 수수료만 잡아 1.25 조가 됐다), 합산은
회계 판단이라 파서가 할 일이 아니다. 사업 분류에 필요한 건 부문 이름이므로
그때는 **이름만 담고 매출은 비운다.** 어느 행에서 읽었는지는 `수익행` 에 남긴다.

이름만 담을 때는 **교차 확인**으로 안전을 잡는다 — 세로형 부문 정의 표와 가로형
표 헤더에 둘 다 나오는 이름만 인정한다. 정의 표가 없는 회사는 헤더만 쓰되
부문명 3개 이상 · 「합 계」 열 존재 · 손익 행 존재를 요구한다. 종속기업 목록은
이 문턱을 넘지 못한다.
