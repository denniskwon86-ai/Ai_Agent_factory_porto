# 판정 엔진

> ⚠️ **검토 중 — 확정된 설계가 아니다.** 현재 시스템에 연결·연계하지 않는다.
> 자세한 조건은 [../README.md](../README.md).

**AI 가 매번 판정하지 않도록** KSIC 코드에서 A·B 축을 규칙으로 판정한다.

## 구성

| 파일 | 역할 |
|---|---|
| `ksic_rules.py` | **법인 판정** — KSIC → (A 업태, B 업종, B 2단) 매핑 + 모수·묶음 판정 |
| `segment_rules.py` | **세그먼트 판정** — 영업부문명 → 축. 법인 1건을 사업 n 건으로 나눈다 |
| `fetch_ftc.py` | **수집기** — 공정위 기업집단포털에서 소속회사를 받아 판정까지 붙인다 |

## 쓰는 법

```bash
python fetch_ftc.py ALL affiliates.csv
```

기업집단 코드를 주면 그 집단만 받는다(엘지 `K1000051`, 에스케이 `K1000050`,
현대자동차 `K3000027`, HD현대 `K3000052`, 신세계 `K1000042`).

판정만 따로 쓰려면:

```python
from ksic_rules import classify
classify('C2020', 18216499)   # → 소재제조 / 화학·소재 / 석유화학·기초
classify('K6499', 884989)     # → 지주·투자 / 다품목·범용, 묶음노드 Y
classify('L6821', 0)          # → 모수밖 (매출 0)
```

## 판정 순서

규칙이 매핑보다 앞선다.

| 순서 | 규칙 | 근거 |
|---|---|---|
| ① | **매출 0 → 모수 밖** | 사업 실질이 없는 껍데기. SPC·청산·준비 단계 |
| ② | **KSIC `K6499`·`M7151` → 지주·투자 + 묶음 노드** | 그 매출이 모수 안 다른 인스턴스 매출을 포함한다 |
| ③ | KSIC 매핑 (5 → 4 → 3 → 1자리) | 긴 접두사 우선. 중분류에서 대부분 결정된다 |
| ④ | 못 찾으면 **미판정** | 억지로 채우지 않고 사람이 본다 |

## 검증 결과

**공정위 2026년 5월 공개분 — 102개 기업집단 전체 3,539개사**

| | 결과 |
|---|---|
| **미판정** | **0건** |
| 인스턴스 | 2,939건 |
| 모수 밖 (매출 0) | 600건 (17%) |
| 묶음 노드 (지주) | 214건 |
| 사용된 셀 | 72개 / 490칸 |

판정 결과는 [../samples/ftc-all-2026-classified.csv](../samples/ftc-all-2026-classified.csv) 에 있다.

**사람 판정과 대조**

| 대상 | 방식 | 결과 |
|---|---|---|
| LG 63개사 | 전수 대조 | **98% (62/63)** |
| SK 151 + 현대차 74 | **KSIC 별 검수** | 보완 지점 8곳 발견 → 규칙 반영 |

⚠️ SK·현대차는 **전수 대조가 아니라 KSIC 별 검수**다. 같은 KSIC 는 같은 판정을 받으므로
코드 종류만큼만 보면 되지만, 법인별 실질 차이는 이 방식으로 못 잡는다.

남은 1건은 `C2842`(조명장치 제조업)로, KSIC 만으로는 **차량용 부품인지 일반 조명 완제품인지
갈리지 않는다.** 규칙으로 100% 를 만들 수 없고 이 정도가 현실적 상한이다 —
**나머지는 사람이 검토한다.**

## 규칙을 고치는 방법

1. 사람 판정과 대조해 불일치를 찾는다
2. `MAP` 에 **더 긴 접두사**로 예외를 추가한다 (짧은 규칙은 그대로 둔다)
3. 다시 대조한다

LG 전수 대조에서 95% → 98% 가 됐고, SK·현대차 검수에서 8곳을 더 보완했다.
보완 후 LG 재대조에서 **회귀 없이 98% 를 유지**했다.

| 보완한 것 | 이유 |
|---|---|
| `R9119` → 인적서비스 | 스포츠단은 선수 활동이 본체. `R91`(골프장) 은 시설 운영 |
| `S9531` → 전자·정밀 | 가전 수리. `S9521`(자동차 수리) 과 대상이 다르다 |
| `C2842` → 전자·정밀 | 조명장치는 전기·전자 제품 |
| `C2411~2422` → 금속 2단 | 철강 / 강관·형강·선재 / 비철금속 |
| `C3120` → 철도·특수차량 | `C31` 폴백(항공·우주·방산)이 철도차량에 붙었다 |
| `G4731`·`G4771` → 전자·정밀 / 에너지 | 휴대폰 판매 · 주유소가 `다품목·범용` 으로 갔다 |
| `N7629` → 생활용품·가구 | `N76` 폴백(기계·운송기기)이 가전 렌탈에 붙었다 |
| `M7011` → 의약·바이오 | **신약개발사가 「자연과학 연구개발업」으로 신고한다** |

## 세그먼트 분할 — `segment_rules.py`

법인 1건을 **사업 n 건**으로 나눈다. 삼성전자를 DS/DX/SDC/Harman 으로 가르는 일이다.

### 왜 별도 규칙인가

**세그먼트에는 KSIC 가 없다.** 사업보고서에 이름과 매출만 실린다.
법인은 KSIC 로 판정하지만 세그먼트는 **이름으로 판정할 수밖에 없다.**

### 판정 순서

| 순서 | 규칙 |
|---|---|
| ① | **지역 세그먼트는 버린다** (국내/북미/유럽…) — 사업 구분이 아니다 |
| ② | **회사 고유 약어** — 삼성전자 `DS`·`SDC`, LG전자 `HS`·`VS` 등 |
| ③ | **키워드 사전** — 「석유화학」「배터리」「할인점」… 긴 키워드 우선 |
| ④ | 없으면 **모법인 판정을 상속**하고 `상속` 으로 표시 |

키워드가 A 축까지 바꾸는 경우가 있다 — 현대자동차 「금융」 부문은 모법인이 제조여도
`금융` 이 된다. 반대로 「석유화학」은 B 만 바꾸고 A 는 모법인을 따른다.

### 예시

```
(주)엘지화학 [C2020] → 소재제조 / 화학·소재
   / 석유화학    소재제조  화학·소재     석유화학·기초   키워드
   / 첨단소재    소재제조  화학·소재     전자·전지소재   키워드
   / 생명과학    소재제조  의약·바이오               키워드

현대자동차(주) [C3012] → 완제품제조 / 기계·운송기기
   / 차량       완제품제조 기계·운송기기  완성차·부품    키워드
   / 금융       금융      금융                    키워드 (A 축까지 바뀐다)
   / 국내·북미                                    지역 — 제외
```

### 세그먼트 수집이 남았다

**DART Open API 에 세그먼트 전용 API 가 없다.** 재무정보 그룹 7개 API 는 회사 단위
계정만 준다. 세그먼트는 **사업보고서 본문·주석을 파싱**해야 하고, 그러려면
DART 인증키가 필요하다.

서식이 회사마다 달라 전량 자동 파싱은 불안정하다. 주요 기업부터 반자동으로
채우는 편이 현실적이다.

## 한계

- **KSIC 는 신고값이라 실질과 어긋날 수 있다.** 규칙으로 못 잡는 사례:
  - HD현대케미칼·쉘베이스오일 → `C1921`(원유 정제처리업) 신고, 실제는 석유화학·윤활기유
  - SK하이닉스시스템아이씨 → `M7390`(기타 전문·과학) 신고, 실제는 반도체 파운드리
  - 아이파킹 → `C2890`(기타 전기장비) 신고, 실제는 주차 관제 시스템
  - 지케이더블유라이팅 → `C2842`(조명장치) 신고, 실제는 차량용 조명 부품
- **B 부업종·밸류체인은 판정하지 않는다.** 겸업과 생태계는 사업 내용을 읽어야 한다
- **세그먼트 판정은 이름에 의존한다.** 이름이 추상적이면(「신사업」「기타」「소재」)
  판정할 수 없고 모법인을 상속한다. 같은 이름이 회사마다 다른 뜻일 수도 있다
- **세그먼트 수집은 아직 없다.** DART 인증키와 사업보고서 파서가 필요하다
- 담김형태 · 소유형태 · 법인형태는 다른 출처가 필요하다
