# 시나리오 카탈로그 — 전 케이스 입력 데이터 정의서

> 각 시나리오의 `초기 아이디어(initial_idea)`는 그대로 복사해 투입 가능한 실전 입력문이다.
> 프로젝트 ID 규칙: `test_<시나리오ID소문자>` (예: A-1 → `test_a1_unitconv`)
>
> 공통 판정·증거 규칙은 `04_evidence_and_failure_taxonomy.md`를 따른다. 이 카탈로그의 “검증”은 생성 결과의 사실성이나 운영 배포를 자동 보증하지 않으며, 현재 구현된 팩토리 동작과 산출물 품질을 검증한다.

## 제조·지식 그라운딩 공통 수용 조건 (D/E/F에 추가 적용)

각 제조/시뮬레이션/메가 시나리오에는 아래 세 항목을 별도로 기록한다.

1. 선택한 마스터 도메인·지식팩·원본 출처가 무엇인지, 해당 프로젝트 컨텍스트에 실제 주입되었는지
2. 산출물의 핵심 가정·권고가 연결한 기준정보/참고문헌과 충돌하지 않는지, 최소 한 개 이상의 근거 위치를 확인했는지
3. 다른 프로젝트·부서의 비관련 정보가 섞이지 않았는지

지식팩이 비어 있거나 원본 형식이 현 업로더에서 처리되지 않으면 “LLM 품질 저하”로 뭉뚱그리지 말고 `DATA_GROUNDING`으로 기록한다. 이 경우 분석 문서의 형식적 완주와 지식 근거의 PASS를 분리한다.
