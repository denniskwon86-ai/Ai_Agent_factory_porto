## 2. 「없음」 7 건 — 대부분 **누락이 아니라 미착수 범위**다

**T12·T13·T14·T15·T16·T46 여섯 건은 「표준 업데이트와 되돌림」 한 덩어리다.**
설계 §9 의 3-way 비교(마지막 수용 표준 B / 회사 구성 C / 새 표준 N)와 복구판 생성이
그 기능인데 **구현이 없다.** 실측:

- `core/enterprise_context/` 에 upgrade/restore 서비스 모듈이 없다.
- `accepted_standard_digest`·`initial_standard_digest` 는 **설치 시점 초기값 설정과
  「달라지면 차단」에만 쓰인다**(`process_installation.py:166`, `process_context.py:286`,
  `process_installation.py:518`). 이 값을 **전진시키는 코드가 없다.**
- `ProcessConfigurationService` 공개 메서드는 resolved/propose/validate/list_changes/
  get_change/approve/events/reject 뿐이다 — restore 가 없다.
- `SPLIT`·`MERGE` 는 오히려 **명시적으로 거절**된다(`test_b1_process_configuration.py::
  test_unsupported_or_invalid_commands_leave_no_partial_rows`).

★ B1 인계가 이미 적어 두었다 — 「복구/표준 업데이트는 아직 없다」(L48). 설계 §15 P5 도
`upgrade/restore service` 를 미착수로 둔다. **즉 시험이 없는 게 아니라 덮을 대상이 없다.**

**T21(책임자만 변경)은 단독 공백이다.** `ProcessNode.owner_scope_node_id` 필드는 있으나
서버가 boundary 로부터 채울 뿐이고 사용자가 바꾸는 명령(SET_OWNER 류)이 없다. 설계 §8
변경 정책에 속하는데 구현·시험이 모두 없다 — 위 여섯 건과 달리 **미착수로 선언된 기록도
찾지 못했다.**

## 3. 「부분」 15 건 — 공백의 성격이 셋으로 갈린다

### (가) 기능은 있는데 부정 경로가 **시험 0건** — 즉시 메울 수 있다

**T11** 의 두 오류 경로가 대표다. 코드에 있는데 시험이 없다.

| 오류 코드 | 구현 | 시험 |
|---|---:|---:|
| `PROCESS_PACK_UPGRADE_REQUIRED` | 1곳 | **0곳** |
| `PROCESS_MAPPING_CONFLICT` | 1곳 | **0곳** |

전수 조사하니 더 있다. **프로세스 계열 오류 코드 66개 중 25개가 시험에서 한 번도
검사되지 않는다.** 다만 그중 넷(`PROCESS_MIGRATION_CONFLICT`·`PROCESS_MIGRATION_INVALID`·
`PROCESS_INSTANCE_MIGRATION_REQUIRED`·`PROCESS_PACK_UPGRADE_REQUIRED`)은 위 §2 의 미착수
기능군에 걸쳐 있어 성격이 다르다.

### (나) 시험은 있는데 **fixture 가 비어 공허하게 통과**한다 — 가짜 통과

- **T07**(기존 앱 보존) — fixture 의 `kit_app_contracts` 가 항상 `[]` 다. 설치 전부터 있던
  앱·릴리스 연결이 설치 후 유지되는지 **검증 대상 데이터가 없다.**
- **T23**(구 편집기 v2 저장 시 바인딩 손실 없음) — fixture 가 `ADD_NODE` 합성 문서라
  `bindings == []` 다. 실제 팩 설치로 `DATA_REQUIREMENT`·`BLUEPRINT_SUGGESTION` 이 들어 있는
  승인판에 구 편집기 저장을 시도하는 함수가 없다.

★ AGENTS 가 Claude Code 역할로 못박은 「**가짜 통과**(오류 없이 조용히 기능이 죽는 경우)를
찾아 회귀로 잠근다」에 정확히 해당한다.

### (다) 기능 자체가 없거나 미연결

- **T01** — 팩 원본의 계수(L1 8/L2 29)는 검증되나 **8개 키트를 한 번에 설치**하는 시험이
  없다. 전 시험이 `["BK-01"]`·`["BK-02"]`·`["BK-03","BK-04"]` 만 쓴다.
- **T09** — 설계 §11.4 의 「적용 대상 L2 중 n/N」 **분모 계수 로직이 코드에 없다.**
  `test_usage_keeps_ids_and_denominator` 는 이름과 달리 N 값을 검사하지 않는다.
- **T10** — `_authorize` 가 boundary/scope 로만 판정하고 **노드별 `owner_scope_node_id` 를
  권한에 쓰지 않는다.** 「구매 편집자가 재고 업무를 못 바꾼다」가 성립하지 않는다.
- **T20** — 복제 성공 경로에서 「live connector·승인 토큰·데이터 권한은 복사되지 않는다」를
  확인하는 함수가 없다(현재는 복제 자체가 409 로 차단되는 것만 검증).
- **T25** — 팩 검증 단계의 순환은 덮이나 **편집 명령(`MOVE_NODE`)으로 조상-자손 순환**을
  만드는 경로가 미시험.
- **T29** — 1 L2 → 여러 앱의 비복제 참조, 권한별 필터 미시험.
- **T33** — 조회 실패 후 **재시도로 정상 판정에 도달**하는 경로 미시험.
- **T34** — 서버 측 경계 은닉은 넓게 덮이나 브라우저 뒤로가기·URL 복원은 자동 불가.
- **T38** — 거절은 덮이나 **복구판 생성의 긍정 경로**가 없다(T16 과 같은 뿌리).
- **T39** — 「인스턴스 active + 셋업 미완료」 조합에서 문맥 발급이 차단되는지 미시험.
- **T40** — 조각은 있으나 홈·생성기 **두 진입점을 한 시험에서 대조**하지 않는다.
- **T44** — 개별 요소는 덮이나 「새 표준 도입」 문맥으로 묶이지 않는다(§2 와 같은 뿌리).

## 5. 이 문서의 한계

- 판정은 **2026-09-14 시점 소스** 기준이다. 시험이 추가되면 갱신해야 한다.
- 「덮임」은 그 함수가 **명세의 합격 기준을 검사한다**는 뜻이지, 그 기능이 운영에서
  옳게 동작한다는 증거가 아니다. 실제 브라우저·현업·운영 데이터 검증은 전부 별개다.
- 시험 함수 871개를 전수로 읽은 것이 아니라 명세별 키워드 검색 후 후보를 읽었다.
  **덮는 함수가 있는데 못 찾았을 가능성이 남는다** — 「없음」·「부분」 판정에 이의가 있으면
  해당 함수를 근거로 이 표를 고치면 된다.
