## 2. 실행 원칙 (끊김 방지 설계)

1. **디스크 영속 트래커**: 모든 진행 상태는 `02_progress_tracker.md`에 기록.
   어떤 세션에서든 *"docs/test_plan/02_progress_tracker.md 읽고 테스트 이어서 진행해줘"* 한 마디로 재개 가능.
2. **1 Phase = 1 세션 단위**: 각 Phase는 독립 완결형. Phase 중간에 끊겨도 시나리오 단위로 완료/미완이 기록됨.
3. **시나리오 단위 커밋 규칙**: 시나리오 하나가 끝날 때마다 트래커에 결과(판정/점수/특이사항)를 **즉시** 기록 후 다음으로 진행.
4. **LLM 쿼터 관리**: 무료 티어(Gemini) 분당/일일 한도 고려, 파이프라인 실행은 **동시 1건**만. 429(쿼터 초과) 발생 시 해당 시나리오를 `DEFERRED`로 표시하고 다음 무료 슬롯에 재시도.
5. **HOTL 자동 승인 규칙**: 검증 목적상 HOTL 게이트는 기본 "무피드백 승인"(resume) 처리. 단, 리비전 시나리오(A-10 등)는 의도적으로 피드백을 입력.
6. **테스트 산출물 보존**: 테스트 프로젝트는 `test_` 접두사로 생성하며, 전체 검증 종료 후 사용자 확인 전까지 **삭제하지 않는다** (실물 확인용).

## 3. Phase 구성 (총 11단계)

| Phase | 내용 | 시나리오 | LLM | 예상 소요 |
|---|---|---|---|---|
| **P0** | 사전 점검: 환경/키/pytest 베이스라인 | ENV-1~3 | ❌ | 10분 |
| **P1** | 구조 테스트: 전 템플릿 프로젝트 CRUD, 메가 프로비저닝, 포맷/레지스트리/Export API | S-1~S-8 | ❌ | 20분 |
| **P2** | SW 팩토리 파일럿 1건 (초간단 앱) E2E — 기획→코드→QA→매뉴얼 전 구간 완주 확인 | A-1 | ✅ 소 | 30~60분 |
| **P3** | SW 팩토리 다양화 (CRUD/대시보드/인증/게임) | A-2~A-6 | ✅ 대 | 세션 2~3회 |
| **P4** | view_type 변형 (슬라이드/머메이드/문서) | A-7~A-9 | ✅ 중 | 세션 1회 |
| **P5** | HOTL 리비전/피드백 루프 | A-10~A-11 | ✅ 중 | 세션 1회 |
| **P6** | 마케팅 + 데이터 분석 트랙 | B-1~B-2, C-1~C-2 | ✅ 중 | 세션 1회 |
| **P7** | 제조 4종 트랙 | D-1~D-4 | ✅ 중 | 세션 1~2회 |
| **P8** | 경영 시뮬레이터 + What-if 재실행 | E-1~E-2 | ✅ 중 | 세션 1회 |
| **P9** | 메가 프로젝트 (8도메인 연동) | F-1~F-2 | ✅ 대 | 세션 1~2회 |
| **P10** | 시스템 기능: 배포/라이브러리/ZIP/스킬진화/자가치유/재시작 복원 | G-1~G-6 | 일부 | 세션 1회 |
| **P11** | 종합 효용성 평가 리포트 작성 | — | ❌ | 30분 |

> ⚠️ **P2가 관문(Gate)**: P2 파일럿이 완주 실패하면 P3 이후를 진행하지 않고 원인(코드 결함/쿼터/프롬프트)을 먼저 수정한다.

## 4. 효용성 평가 루브릭 (시나리오당 5점 만점 × 6항목)

| 항목 | 1점 | 3점 | 5점 |
|---|---|---|---|
| **완주율** | 중단/무한루프 | 재시도 후 완주 | 무개입 완주 |
| **요구 정합성** | 입력 아이디어와 동떨어짐 | 핵심 요구 반영 | REQ 전 항목 추적 가능 |
| **산출물 품질** | 스텁/빈약 | 골격+동작 | 실무 초안으로 사용 가능 |
| **렌더/실행성** | 렌더 실패 | 일부 동작 | 프리뷰 정상 + 상호작용 |
| **일관성** | 문서 간 모순 | 경미한 불일치 | RFP↔PRD↔코드↔매뉴얼 일치 |
| **비용 효율** | 쿼터 소진/타임아웃 다발 | 재시도 1~2회 | 폴백 없이 1회 완료 |

- **판정**: 24점↑ = ✅ 효용 있음 / 15~23 = ⚠️ 조건부(보완 필요) / 14↓ = ❌ 부적합
- 시나리오별 점수는 트래커에 기록, P11에서 트랙별 집계.

## 5. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| LLM 무료 쿼터 소진(429) | 시나리오 DEFERRED 처리 → Groq 폴백 자동 동작 확인 → 다음날 재개 |
| HOTL 게이트에서 무한 대기 | `GET /{pid}/hotl/check` 폴링 → `POST /{pid}/hotl/resume` 자동 승인 |
| 파이프라인 무한 루프 | `GLOBAL_MAX_SUPERVISOR_HOPS=8` 서킷브레이커 동작 확인 자체가 테스트 항목 |
| 세션 컨텍스트 고갈 | 트래커 영속화 + Phase 단위 재개 프로토콜 (2절) |
| 실행 중 서버 다운 | SQLite 체크포인트 복원(G-6)이 이를 검증 |

## 6. 재개 프로토콜 (새 세션용)

```
1. docs/test_plan/02_progress_tracker.md 읽기
2. 상태가 IN_PROGRESS 또는 첫 PENDING인 Phase 확인
3. 백엔드(run.py, 8080)/프론트(5173) 기동 상태 확인, 죽어있으면 재기동
4. 해당 Phase의 시나리오를 01_scenario_catalog.md에서 찾아 순서대로 실행
5. 시나리오 1건 완료 시마다 트래커 갱신
```
