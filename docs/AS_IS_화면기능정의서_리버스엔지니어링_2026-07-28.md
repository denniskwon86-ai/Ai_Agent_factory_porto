# AI Factory Studio As-Is 화면기능정의서

> 작성 방식: React 컴포넌트와 Zustand 상태·호출 API를 역추적했다. 이 문서는 화면 레이아웃 제안서가 아니라 현재 화면이 제공하는 기능 정의서다.
>
> 기준일: 2026-07-28 / 대상: `frontend/src/App.tsx`, `components/`, `store/useFactoryStore.ts`

## 1. 화면 구조 요약

```text
App
├─ 에이전트 마스터 전체화면
├─ 출력 양식 마스터 전체화면
├─ 결과물 실행 전체화면
├─ 프로젝트 미선택: Private AI Cockpit 런처
│  ├─ 새 프로젝트 생성
│  ├─ Mega 프로젝트 탭
│  ├─ 독립 프로젝트 Vault 탭
│  ├─ 결과물 라이브러리 탭
│  └─ 지식/MDM/업무표준/Crosswalk/텔레메트리/스킬진화/로그 오버레이
├─ Mega 프로젝트 선택: Mega Boardroom
└─ 독립 프로젝트 선택: 통제실
   ├─ 상단 바
   ├─ Workflow Strip
   ├─ Control Panel
   ├─ Timeline Panel
   ├─ Preview Panel
   └─ HOTL Input(통제 패널 하단)
```

### 공통 UI 원칙(현재 구현)

- 전체 기본 테마는 다크(`bg-[#0B0C10]`, 회색 패널, 파랑/인디고/보라 강조)다.
- 독립 프로젝트 통제실의 핵심은 좌→우 3분할 가변 패널이다: Control 22%, Timeline 40%, Preview 38%를 기본으로 한다.
- 앱 전역 상태는 Zustand 단일 store가 보유한다. REST 결과와 SSE 이벤트가 동일 store를 갱신한다.
- 실시간 연결은 SSE이며 연결 실패 시 5초 후 재접속한다.
- 프로젝트가 바뀐 뒤 이전 프로젝트 비동기 응답이 새 프로젝트 상태를 덮지 않도록 일부 fetch는 현재 프로젝트 ID를 재검증한다.

## 3. S-01: Private AI Cockpit 런처

### 3.1 목적

프로젝트 생성, 기존 프로젝트 선택, Mega 프로젝트 관리, 결과물 라이브러리 접근, 공통 데이터/관리 패널 진입을 제공하는 홈 화면이다.

### 3.2 헤더

| UI 요소 | 동작 | 연동 |
|---|---|---|
| 제품명/버전 | `V5.2 Private AI Cockpit` 표기 | 정적 |
| 에이전트 제어 | Agent Master 전체화면 진입 | `showAgentPanel` |
| AI 스킬 진화 | 제안 승인 대기열 오버레이 | `/skills/proposals` |
| 지식 허브 | 지식팩 관리 오버레이 | `/api/v1/knowledge/*` |
| 기준정보 마스터 | M1 오버레이 | `/api/v1/master/*` |
| 업무표준 | 단계별 기준/이력 오버레이 | `/api/v1/standards/*` |
| 연계/Crosswalk | 외부 시스템-기준정보 매핑 오버레이 | `/api/v1/crosswalk/*`, `/api/v1/mcp/*` |
| 운영 계기판 | LLM 텔레메트리 오버레이 | `/api/v1/telemetry/*` |
| Network 상태 | SSE 연결 상태 점/서버 로그 팝업 토글 | `/ws/timeline`, `/api/v1/factory/logs` |

### 3.3 새 프로젝트 생성 카드

| 입력/조작 | 값·규칙 | 결과 |
|---|---|---|
| Project ID | 공백 불가. 백엔드에서 영문/숫자/`_`/`-` 검증 | 프로젝트 식별자 |
| 워크플로 템플릿 | 서버 템플릿 목록에서 선택, 기본 `default` | 에이전트/스킬/그래프 선택 |
| 연결할 지식팩 | 다중 칩 선택 | 모든 에이전트 컨텍스트에 근거로 주입 |
| 기준정보 도메인 | 쉼표 구분 문자열 | M1 결정론적 주입 도메인 |
| 외부 실시간 참조 | 체크박스, 기본 OFF | M3 MCP grounding 허용 |
| 프로젝트 유형 | 독립 / Mega 라디오 버튼 | 독립 생성 또는 Mega 생성 |
| 생성 | 유형별 생성 API 호출 | 성공 시 프로젝트 선택 상태로 전환 |

### 3.4 런처 탭

| 탭 | 표시 내용 | 사용자 기능 |
|---|---|---|
| Mega 프로젝트 | 마스터 프로젝트, 서브 프로젝트 수, 통합 진행률 | 보드 진입, 삭제, 서브 프로젝트 진입 |
| 독립 프로젝트 Vault | 일반 프로젝트 카드 | 통제실 진입, 복제, 삭제, 진행률 확인 |
| 결과물 라이브러리 | 저장된 릴리스 카드 | SW 실행 또는 문서 열기, 삭제 |

### 3.5 예외/제약

- 프로젝트가 없으면 각 탭에 빈 상태를 표시한다.
- 삭제는 `confirm()`을 사용하며 프로젝트 볼트의 물리 삭제·복구 불가를 경고한다.
- 지식팩/기준정보/외부 참조는 프로젝트 생성 시점의 메타데이터이며, 실제 외부 쓰기 연계를 의미하지 않는다.

## 4. S-02: 독립 프로젝트 통제실

### 4.1 목적

프로젝트 단위 AI 생산 파이프라인을 시작·승인·중단·재개하고, 진행 타임라인과 산출물 Preview를 동시에 보는 주 작업 화면이다.

### 4.2 헤더와 상단 흐름

| 영역 | 기능 |
|---|---|
| 뒤로 | 현재 프로젝트 선택을 해제하고 런처로 복귀 |
| 제목 | 현재 프로젝트 이름/ID의 통제실 표시 |
| 실시간 통신 | SSE 연결 상태 및 서버 로그 팝업 |
| Workflow Strip | 계획/실행 노드의 상태를 가로 단계로 표시. 에이전트 레지스트리/현재 상태를 참조 |

### 4.3 3분할 패널

| 패널 | 기본 폭 | 핵심 역할 |
|---|---:|---|
| ControlPanel | 22% (최소 14%) | 아이디어, 계획 가동, WBS, 태스크, 실패 복구, 배포, 시뮬레이션 제어 |
| TimelinePanel | 40% | 노드 완료/활동, 슈퍼바이저 피드백, 이벤트 시간순 표시 |
| PreviewPanel | 38% | 생성 앱 미리보기, 문서·코드·QA·수용·추적성 확인 |

패널 폭은 `react-resizable-panels`로 드래그 조절한다.

## 5. S-03: ControlPanel

### 5.1 목적

프로젝트 실행의 명령 센터다. 계획 스프린트, WBS 태스크, HOTL, 실패/쿼터, 결과물 배포까지의 조작을 집약한다.

### 5.2 표시 상태

| 상태 | 화면 표시/행동 |
|---|---|
| `activeSprintId` 존재 | 실행 중 배지/강제 중단 가능, 다른 시작 버튼 비활성화 |
| `SUSPENDED_QUOTA` | 쿼터 소진 경고, 중단 위치부터 재개 버튼, 알림 닫기 |
| `lastSprintFailure` 존재 | 오류 요약, 오류 포함 재시도, 추가 지시 재시도, 보류 |
| `needs_revision` 또는 `hotlTaskId` | HOTLInput에 승인/피드백 UI 노출 |
| 모든 태스크 완료 | 수용검수 결과, 릴리스 저장, ZIP 내보내기, 재시뮬레이션 영역 노출 |

### 5.3 주요 조작

| 조작 | 조건 | API/효과 |
|---|---|---|
| 계획 가동 | 아이디어 입력, 실행 중 아님 | `POST /{project}/sprint/start` with `PLANNING_*` task |
| WBS 전체 새 창 | WBS 존재 | 별도 브라우저 창에 표 렌더링 |
| WBS만 재분할 | 계획 산출물 존재 | `POST /{id}/wbs/replan` |
| 태스크 신규 가동 | WBS 태스크가 대기/실패 | EXECUTION 스프린트 시작 |
| 태스크 이어서 재가동 | 중단/재개 가능 상태 | 같은 태스크 ID로 재개 경로 |
| 강제 일시정지 | 실행 중 | pause/stop API, UI HOTL 상태도 정리 |
| 쿼터 재개 | `SUSPENDED_QUOTA` | `POST /sprint/resume-quota` |
| 실패 재시도 | 실패 카드 존재 | 빌드 오류 포함/추가 지시 포함 재시작 |
| 최종 결과물 저장 | 최종 단계 조건 | `POST /{id}/release` |
| ZIP 내보내기 | 프로젝트 존재 | export URL로 다운로드 |
| 재시뮬레이션 | 완료 상태/입력값 | `POST /{id}/resimulate` |

### 5.4 WBS 태스크 카드

카드는 제목, 상태, 필요 에이전트, 진행 표시와 상태별 버튼을 보여 준다. 상태가 `TODO`이면 신규 가동, 중단 후 재개 가능하면 이어서 재가동, 실행 중이면 강제 일시정지를 제공한다.

### 5.5 입력 파일 주입

로컬 텍스트/Markdown 파일을 선택해 시뮬레이션 환경에 주입하는 UI가 있다. 이는 생성/시뮬레이션 컨텍스트 보조 입력이며, 전사 파일 관리·권한 시스템은 아니다.

## 6. S-04: HOTLInput 및 슈퍼바이저 대화

### 6.1 목적

사람 승인 게이트와 프로젝트 수준 슈퍼바이저 질의/지시를 하나의 하단 입력 영역에서 처리한다.

### 6.2 표시 모드

| 모드 | 조건 | 화면 요소 |
|---|---|---|
| 일반 대화 | HOTL 대기 아님 | 텍스트 입력 후 슈퍼바이저에게 질문/지시 |
| 산출물 승인 | `needs_revision`/`hotlTaskId` | 현재 대상 태스크, 승인 안내, 자유 피드백, 제출 |
| Clarification | `current_stage=CLARIFICATION` 또는 질문 존재 | 질문 카드, 추천 선택지, 복수 선택, 자유 텍스트 |
| 슈퍼바이저 개입 | `human_feedback_queue`에 `[SUPERVISOR]` 존재 | 위험/중단 사유를 붉은 경고로 노출 |

### 6.3 동작

- 승인만 할 때는 빈 피드백으로 HOTL resume을 호출한다.
- 수정 요구는 자유 텍스트와 함께 resume에 전달한다.
- Clarification은 선택한 옵션을 요약한 뒤 RFP 작성 입력으로 전달한다.
- 대화는 `POST /api/v1/factory/{project_id}/supervisor/chat`을 호출한다. API의 `task_id`는 선택값이며, 서버 구현은 빈 값일 때 프로젝트 전체 상태를 포함하도록 의도되어 있다.

### 6.4 현재 한계

UI에는 `Target Task` 표기가 남아 있고 실행 재개는 태스크 단위다. 그러나 장기 목표의 슈퍼바이저는 Task 전용 도구가 아니라 전역 문맥/권한/감사 도구여야 한다.

## 7. S-05: TimelinePanel

### 7.1 목적

SSE 이벤트와 서버 피드를 합쳐 AI 공장의 현재 활동과 의사결정 이력을 시간순으로 보여 준다.

### 7.2 데이터 원천

| 원천 | 내용 |
|---|---|
| `logs` | SSE `NODE_COMPLETED`, `AGENT_ACTIVITY`, `HOTL_PAUSED`, `SPRINT_COMPLETED`, `SPRINT_FAILED` 등 |
| `supervisorFeed` | `/feed` 및 슈퍼바이저 설명/개입 메시지 |
| `currentActivity` | 현재 활동 중인 에이전트/상태 |

### 7.3 표시 규칙

- 에이전트/이벤트 타입별 아이콘과 배경색을 사용한다.
- QA/리뷰 판정은 PASS/REWORK/REJECT 등의 배지로 표시한다.
- 현재 프로젝트 ID와 일치하지 않는 SSE 이벤트는 클라이언트에서 버린다.
- 로그는 메모리 상한을 두며 타임라인은 합친 목록을 재사용한다.

## 8. S-06: PreviewPanel

### 8.1 목적

생성 중/완료된 앱과 문서 산출물을 한 화면에서 확인하고, 추적성과 코드 요약까지 탐색한다.

### 8.2 탭

| 탭 | 데이터 원천 | 렌더링 |
|---|---|---|
| PREVIEW | `frontend_code_summary` 또는 릴리스 코드 | Babel 기반 iframe React Preview |
| RFP/PRD/UI/ARCH/TECH | 각 요약 필드 | Markdown/HTML iframe 또는 텍스트 뷰 |
| FRONTEND/BACKEND | 코드 요약 JSON의 `files` | 파일별 코드 블록 |
| REVIEW/QA/ACCEPT | 리뷰·QA·수용검수 요약 | Markdown 뷰 |
| MANUAL | `user_manual_summary` | 단순 Markdown 렌더러 |
| TRACE | traceability API | `TraceabilityGraph` |

프로젝트 템플릿이 동적 산출물 탭을 선언하면 기본 탭 대신 해당 탭 집합을 사용한다.

### 8.3 Preview 조작

| 조작 | 동작 |
|---|---|
| 새 창 | Preview HTML을 별도 OS 브라우저 창으로 연다. |
| 전체화면 | PreviewPanel을 fixed overlay로 전환, Esc로 해제 가능 |
| 새 창 포커스/메인 복귀 | popup 상태 관리 |
| 렌더 오류 | iframe `postMessage`를 수신하여 오류 표시 및 제한적 self-heal 호출 |

### 8.4 보안/호환성 주의

현재 iframe은 `sandbox="allow-scripts allow-same-origin"`을 사용한다. 생성 앱의 localStorage 호환성을 위한 선택이나, 완전한 격리 보안 경계가 아니다. 운영용 생성 앱 런타임과 분리해 다뤄야 한다.

## 10. S-08: AgentMasterPanel

### 목적

에이전트 레지스트리와 워크플로 템플릿을 편집한다. 에이전트의 역할, 스킬, 모델 tier, 순서, HOTL, debate, 출력 양식을 관리한다.

### 기능

| 기능 | 설명 |
|---|---|
| 템플릿 선택 | 기본/사용자 템플릿 레지스트리 로드 |
| 에이전트 편집 | AgentFlow 노드와 Detail Sidebar에서 속성 편집 |
| 저장 | 템플릿별 레지스트리 저장 |
| 기본값 초기화 | 기본 레지스트리 복원 |
| 복제/삭제 | 사용자 템플릿 복제·삭제, 기본 템플릿 삭제 제한 |
| AI 파이프라인 자동 구상 | 자연어 목적을 입력해 에이전트 파이프라인 초안을 생성 |

### 주의

기본 SW 파이프라인의 edge/router는 일부 하드코딩되어 있다. 임의 노드를 끄거나 순서를 변경한 레지스트리가 항상 유효한 그래프를 보장하지 않는다.

|---|---|

출력 양식의 `prompt_injection`은 Universal Node를 포함한 생성 프롬프트에 영향을 준다.

## 12. S-10: KnowledgeHubPanel

## 15. S-13: CrosswalkPanel 및 MCP 확인

| 화면 요소 | 기능 |
|---|---|
| 외부 시스템 목록 | 시스템 생성·선택·활성화 |

현재 화면은 연계 준비/매핑/읽기 해석 도구다. 실제 ERP/MES 쓰기 연동이나 운영 이벤트 동기화 UI가 아니다.

## 20. 현재 UX의 핵심 한계

1. 슈퍼바이저 대화는 프로젝트 화면 내 HOTLInput 중심이라, 목표한 자비스형 전역 AI 비서 UX와는 다르다.
2. 부서/사용자/권한에 따른 화면·데이터 격리는 구현되지 않았다.
3. 생성 앱 Preview는 산출물 확인 도구이며 운영용 멀티테넌트 앱 런타임이 아니다.
4. 데이터 패널은 M1/M2/M3의 기반 기능이며 데이터 카탈로그·품질·계보·계약의 완성 UI가 아니다.
5. Mega Boardroom은 생성 프로젝트 관리용이며 경영 디지털트윈 대시보드가 아니다.
6. 일부 화면 문구/주석은 인코딩 환경에 따라 깨져 보일 수 있다. 기능 설계 판단은 코드 구조/API 계약을 우선한다.
