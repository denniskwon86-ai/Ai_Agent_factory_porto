## 5. ★ 조심할 것 — 이 세션에서 실제로 데인 것

이 장이 이 문서에서 가장 값지다. **전부 실제로 일어난 일이다.**

### 5.1 좁은 범위로 시험을 돌리면 깨진 것을 못 본다

키트 관련 6 개 파일만 돌리면 전부 통과한다. `scripts/` 를 건드리는 시험 **전체**를
돌리자 셋이 나왔고, 그중 **둘은 분리(`a86a45295`) 때부터 깨져 있었다.** 그때
「합격조건 셋 통과」라고 보고한 것은 확인 범위를 넘어선 서술이었다.

    # 최소한 이 범위는 돌린다
    .venv/Scripts/python.exe -m pytest $(grep -rln 'kit_freeze\|starter_kit\|business_defs\|KIT-MFG' tests/ --include='*.py') -q -p no:warnings

⚠️ `--timeout` 같은 **없는 인자를 주면 pytest 가 exit 0 으로 죽는다.** 아무것도 안
  돌았는데 「통과」로 읽었다. 출력의 점(`....`)을 확인할 것.

### 5.2 ★ 작업 트리를 공유한다 — `git add <디렉터리>` 를 하지 말 것

`git add docs/` 를 했다가 **다른 세션이 작업 중이던 파일 다섯**(전사교육 PPT·PDF·
Codex 인계 문서)이 내 커밋에 딸려 갔다. 푸시 전에 잡아
`git reset <before> -- <paths>` 로 **작업 트리는 그대로 두고 인덱스만** 되돌렸다.

    git add <파일 하나하나>      # ✅
    git add docs/                # ✗ 남의 미커밋이 딸려 온다
    git status --porcelain       # 커밋 전 반드시

### 5.3 「지문 PASS」가 대장이 없어도 나왔다

`validate --version 1.1.0` 이 `frozen: true · fingerprint: PASS` 를 내는데 그 판본에
`.frozen` 도 `fingerprint.json` 도 없었다. **값을 바꿔도 검증 406 건이 통과했다.**
`is_frozen()`(manifest 상태로도 참) 과 `verify()`(대장 없으면 무검사 통과)가 만난
자리였다. 지금은 **`.frozen` 이 있는데 대장이 없으면 실패**한다.

### 5.4 우연한 일치가 결함을 가린다

`owner_of()` 는 사업 정의에 적힌 품목만 안다. 더미 품목은 기본값(마지막 사업)으로
떨어졌는데, **더미 완제품이 마침 전부 마지막 사업에 몰려 있어 우연히 맞았다.**
배정을 고르게 고치자 **판매 1,089 행이 마스터와 어긋났다.**

★ **하나를 고치면 그것이 가리고 있던 것이 드러난다.** 재고 음수 검사를 넣자 내가
  만든 것 말고도 **1.1.0 부터 있던 1,082 행**이 나왔다.


★ **세 번째 사례 (2026-09-22)**: 완제품 단가를 생성기가 품목 이름으로 분기해 정했고
  (`if FG-NISO4 ... elif FG-CATHODE`), 거기 없는 `FG-LIOH` 는 **더미 기본값 32,000**
  으로 떨어졌다. 그 값이 마침 그럴듯해 아무도 몰랐다. 더미 단가를 1,200 으로 낮추자
  **수산화리튬 매출이 57% → 4.5%** 로 무너지며 드러났다(9.5).

### 5.5 데이터를 고치면 지문이 바뀐다 — 판본을 새로 낸다

확정 판본은 **in-place 로 고치지 않는다.** 1.0.0 이 머지로 조용히 바뀐 사고가
있었고(`0ca2a58ad`), 그래서 **재생성이 아니라 파일과 지문이 판본을 보증한다.**

⚠️ 그 결과 1.0.0·1.1.0 은 **재생성되지 않는다.** 생성기 로직이 바뀌었기 때문이다.

### 5.6 안전장치를 우회하지 말 것

기초재고 창고를 고치며 넣은 폴백이 **「없는 창고면 멈춰라」를 조용히 무력화**했다.
`test_generator_must_stop_instead_of_falling_back` 이 잡았다. 못 찾으면 첫 후보를
그대로 돌려주고 **호출부가 검증해 멈추게** 해야 한다.

### 5.7 정본은 생성기다 — 산출물을 직접 고치지 말 것

`starter_kits/` 의 CSV 를 손으로 고치면 재생성에 덮어써진다. 고칠 것은
`scripts/business_defs/` 또는 생성기다.

### 5.8 ★ 등록부에 넣는 것이 화면을 바꾼다

선반 키트를 `register_all()` 에 태우자 **`GET /kits` 의 `kits` 목록이 늘었다.** 그
목록은 「조직 적용용 운영 템플릿」이고, 거기에 샘플 패키지가 섞이면
**「옛 9 종 Profile 이 두 번째 샘플 회사처럼 보인다」** — 코드 주석이 막으려던 바로
그 일이다.

`profile.kit_source` 로 갈라 `starter_kit_versions` 를 따로 냈다. **`kits` 는 종전
그대로다.** 데이터 층을 바꿀 때는 **그것을 읽는 화면까지** 따라가야 한다.

⚠️ 같은 이유로 `test_data_kit_runtime` 하나가 깨졌다 — 임시 디렉터리로 격리했다고
  믿었는데 **선반은 실제 자리를 보고 있었다.** `register_all()` 이 선반 자리도 인자로
  받게 했다.

### 5.9 ★ 시험 출력을 `tail` 로 자르지 말 것 — 기준선이 거짓이 된다

전체 시험을 `pytest … | tail -8` 로 돌려 그 결과를 **기준선**으로 삼았다. 그런데
`FAILED` 는 알파벳 순으로 나오므로 **앞쪽이 잘렸고**, 요약 헤더(`short test summary
info`)조차 없었다. 나는 그것을 「실패 8 건」으로 읽었다.

나중에 다시 돌리니 12 건이었고, 「새로 생긴 4 건」으로 보였다 — **전부 잘려 있던
것**이었다. 회귀를 쫓느라 시간을 썼다.

    pytest tests/ -q --tb=no > <파일> 2>&1     # ✅ 통째로 남긴다
    pytest tests/ -q | tail -8                 # ✗ 기준선이 거짓이 된다

### 5.10 환경에 기대는 시험은 언젠가 거꾸로 깨진다

`test_access_audit` 가 쓰기 실패를 만들려고 **없을 법한 드라이브**를 썼다.

    os.path.join("Z:", "nope", "audit.jsonl")   →   Z:nopeudit.jsonl

**백슬래시가 없다.** 드라이브 상대 경로이고, 이 PC 에 `Z:` 가 연결돼 있어 **쓰기가
성공해** 「실패가 카운트되지 않았다」로 시험이 깨졌다. 네트워크 드라이브가 붙었다
떨어졌다 하는 환경에서는 **결과가 오락가락한다.**

★ 고친 방법: **디렉터리에는 쓸 수 없다**는 성질을 쓴다(`tmp_path`). 예외 종류는
  OS 마다 달라도 `record()` 가 `except Exception` 으로 받으므로 어느 쪽이든 잡힌다.

### 5.11 ★ 통과하는 시험이 **아무것도 보지 않을** 수 있다

`test_host_runtime_wire` 의

    bad = [r.path for r in app.routes if ...startswith(shape)]
    assert not bad

가 **언제나 빈 목록**이라 통과하고 있었다. FastAPI 0.139 에서 `app.routes` 에는
`_IncludedRouter` 만 있고 `.path` 가 없기 때문이다(544 개 중 5 개만 보였다).

★ **실패 목록에는 잡히지도 않는다.** 실패한 10 건은 「없다」를 확인하는 시험이었고,
  이것은 「있으면 안 된다」를 확인하는 시험이라 **빈손일수록 초록**이었다.

    tests/conftest.py  →  app_endpoints() · app_paths()

한 곳에 모았고, 내부 구현이 사라지면 `app.openapi()` 로 떨어지게 했다 — **조용히
빈손이 되지 않게.**

### 5.12 ★ 읽는 사람이 다르면 **형식도 문서도 갈라야 한다**

두 번 틀렸다.

| | 무엇을 놓쳤나 |
|---|---|
| **형식** | 현업에 보낼 요청서를 `.md` 로 만들어 놓고 「그대로 보내시면 됩니다」라고 했다. 메일에 붙이면 표가 깨지고, 첨부해도 열지 못하고, **빈칸을 채울 수도 없다** |
| **범위** | 제련과 전지소재를 **한 문서**에 담았다. 키트가 각각 구성되고 **답할 담당도 다른데**, 제련 담당은 램프업을, 전지소재 담당은 부산물을 답할 수 없다 |

★ **「내용이 맞나」만 검토하고 「누가 어떻게 받나」를 검토하지 않았다.** 받는 사람이
  다르면 **문서도 형식도 갈라야 한다** — 그 둘은 내용만큼 중요하다.

    docs/decisions/DOMAIN_REVIEW_SMELTING_2026-09-22.md  + Word 본
    docs/decisions/DOMAIN_REVIEW_BATTERY_2026-09-22.md   + Word 본

`.md` 가 정본이고 Word 는 배포본이다 — **내용을 고치면 둘 다 고쳐야 한다.** 생성
스크립트는 스크래치패드에 있고, 저장소에는 산출물만 둔다.

### 5.13 ★★★ **묵은 판본이라고 지울 수 있는 것이 아니다**

**내가 지우자고 권했고, 그것이 정확히 거꾸로였다.**

1.0.0·1.1.0 을 「봉인 결함이 있던 판본이니 선반에서 치우자」고 제안했다. 지우기 전에
훑어 보니 **둘 다 시험의 고정물**이었다.

| 판본 | 지웠으면 죽었을 것 |
|---|---|
| **1.0.0** (43 MB) | `core/demo_vertical_slice.py` 가 그 `samples/full/*.csv` 를 읽는다 — **플랫폼 계산 카나리의 정본**이고 `tests/test_calc_canary.py` 전체가 그 위에 있다. 카나리는 그 데이터의 **구체적 결함**(`material_requirement` 200 건 어긋남·`INV-01` 음수 25 건)에 기대므로 새 판본으로 옮기면 거꾸로 깨진다 |

#### 그래서 고친 것 — 손으로 쓴 목록 대신 **훑어서 센다**
