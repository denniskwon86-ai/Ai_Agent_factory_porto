## 1. 결론과 정정

산술보다 **목표·현황·작업 배치 관리가 어긋났다.** 52.5%는 운영 트라이얼 준비율이 아니다. 최신 완료를 반영하지 않은 과거 미완료 사유까지 재인용했다. Codex도 최신 Claude 결과를 합치기 전에 다음 일을 제안했고, 팀보드에는 OPS-P1 담당을 Claude로 남겼다. 아래 배치가 그 기록보다 우선한다.

1. Claude의 DEP 최소 보완은 이미 마감됐다. `214042505`(10:54:06) 코드, `0d0789e97`(10:54:13) 보고가 커밋돼 있다. 보고 본문의 ‘커밋 없음’은 작성 시점 기록이며 현재 Git 상태가 아니다. 추가 작업 RUNNING 여부는 확인하지 못했다.
2. D03의 OWNER_CERTIFIED 관련 서명/인증 API·정책 API는 존재한다. ‘종점 구현 필요’를 계속 다음 작업으로 보내면 중복이다. 프런트 검색에서는 해당 API 소비 연결을 찾지 못했으며, 대표 사용자 화면→서명→인증→소비 수용은 별도로 남는다.
3. D04의 선행 5종 정렬과 보류 강제는 각각 9/11·9/12 완료 기록이 있다. 이를 다시 적재/구현할 일이 아니다. 정식 소유권·인증·보류 해제 근거 및 같은 문맥의 앱/계산 연결이 남는다.
4. 관리툴 R1은 설계·계약 검토 완료이지 제품 완료가 아니다. DEP 파일 색인과 시험용 원장은 정식 artifact/운영 control backend를 대신하지 않는다.

## 5. 바로 다음 실행: 병렬 두 경로만

### A. Codex — OPS-P1 정식 산출물 구현

- 기존 DEP 선별기를 재사용한다. DB/.env/사용자 파일/관리툴 혼입 차단을 보존한다.
- 첫 30분: 재사용 코드와 manifest 필드 매핑, 수정 파일·로컬 검사 경계 고정.
- 다음 60~90분: manifest 생성/검증의 실행 가능한 첫 묶음과 정상·변조·출처 누락 시험. 이는 중간 산출물이며 Linux/원격 CI 완료로 표시하지 않는다.
- OPS-P1 전체 잠정 0.5~1인일. Linux 실행환경/원격 승인 대기는 별도. 이후 Codex OPS-P2→OPS-P3로 진행한다.

### B. Claude — DB-1 실제 PG 첫 경로

- DEP 보완 재수행/구 7상태 원장 정교화/OPS-P1 병행 착수 대신 기존 adapter를 실제 PG에 연결한다.
- 첫 30분: 승인된 격리 PG 사용 가능 여부·driver·schema 적용 명령·필수 역할 확인. 없으면 환경 확보에 필요한 정확한 조치와 담당을 보고한다. 운영 DSN을 코드/문서/채팅에 넣지 않는다.
- PG가 없어도 첫 slice 설치/migration 명령과 runtime DDL 분리, ETL의 빈 consumed_at→NULL 규칙·대사 검사를 준비할 수 있다.
- 환경 확보 후 첫 수용 묶음 잠정 4~8시간: 7테이블 설치→합성 자료 이관→로그인/문맥/티켓→권한 거절→중복 소비 방지→재시작. 전체95테이블 이관 완료가 아니다.
- 다음으로 필수 저장소/파일/작업 실행 경로를 단계별 이관한다. 실제 readiness 수집기는 관측할 PG/노드 경계가 생긴 뒤 연결한다.

### 의존성과 통합 시점

T03과 T04는 병렬 가능하다. T04는 T05/T06의 위험을 먼저 드러내는 첫 경로다. T08/T09의 로컬 계약 구현은 업무 DB 전체 이관을 기다릴 필요가 없다. **실제 배포는 T05~T07, T08~T10과 환경 준비가 합쳐진 뒤** T11에서 검증한다. T12는 선정 업무·사용자·자료가 있어야 닫는다.

기존 관리툴 추정 6~11인일은 업무 DB 전체·실자료 승인·외부 환경 대기를 제외한 값이다. 이를 트라이얼 오픈일까지의 약속으로 재사용하지 않는다. 전체 오픈 ETA는 첫 실제 PG 경로와 필수 저장소 범위가 확인된 뒤 갱신한다. 실측 근거 없이 ‘며칠이면 배포’로 확정하지 않는다.

## 6. 작업·검증·보고 방식 변경

- 종료 조건이 없는 탐색을 중지한다. 진행 중인 UI는 보안/데이터 손실/현재 트라이얼 경로의 차단 결함만 우선한다. 삭제 예정 구 화면의 일반 UX 개선은 별도 대기열이다.
- 구현 묶음마다 직접 바뀐 경로의 정상·거절·회귀를 먼저 확인한다. 전체 검사/브라우저 재구축/모든 변이는 통합 지점 또는 위험 근거가 있을 때 수행한다. 권한·원자성·자료 유출 통제는 축소하지 않는다.
- 보고 단위: `닫은 납품/하위 기능 → 지금 하는 일 → 남은 기능 이름/개수 → 장애물/담당 → 다음 결과와 예상 시간`.
- 20~30분은 **중간 체크포인트**이지 매번 새 설계/승인을 기다리는 작업 종료점이 아니다. 새 권한/과금/정책 결정이 없으면 승인된 구현 범위 내에서 계속한다.
- 명령 통과 수는 증거로만 적는다. 전체 점수·기능 완료·실제 사용자 수용을 서로 바꾸어 쓰지 않는다. 공유 상태의 타임스탬프/HEAD와 인계 수신 여부를 분리한다.
