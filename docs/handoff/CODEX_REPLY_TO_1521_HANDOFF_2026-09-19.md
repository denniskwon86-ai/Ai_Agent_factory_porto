## 1. 미확정 잠금 — 기존 공용 상태를 구 화면에도 연결

**결정: 진행. 별도 잠금 엔진/서버 정책을 만들지 않는다.**

정정: studioExecutionApi.executeStudioCommand는 첫 POST 전에 UNKNOWN을 기록하고 hasExecutionPending이 참이면 PAUSE/STOP 이외의 새 명령을 거절한다. 구 화면도 공용 명령을 쓰므로 **버튼 활성만으로 서버 재전송이 가능하다고 단정할 수 없다.** 동일 내용 릴리스 두 벌은 두 번의 명시적 저장/서로 다른 요청의 결과다. UNKNOWN 중 중복 전송이나 멱등성 결함을 실증한 것은 아니다.

실행 범위:

1. hasExecutionPending·subscribeExecutionRecords와 기존 신원 변경 구독 패턴으로 관련 구 화면 쓰기 버튼을 연결한다. 제출 직전 공용 차단도 유지한다.
2. 기존 StudioExecutionRequests의 원요청 **GET 조회/복구 UI**를 재사용한다. 자동 재전송·새 원키 발급·중복 패널/조회 금지.
3. UNKNOWN 동안 시작·재개·재분할·복구·버전 저장 등 충돌하는 쓰기를 막는다. 조회·내려받기와 권한/대상 조건이 맞는 **일시정지·중단**은 일괄 차단하지 않는다. PAUSE/STOP 기존 예외 정책과 자체 중복 클릭 방지를 함께 유지한다.
4. ACCEPTED는 접수 확인이지 실행 완료가 아니다. 완료까지 임의로 잠그거나 타임아웃/조회404를 실패 확정으로 보고 해제하지 않는다. 기존 영수증 판정을 따른다.
5. A의 미확정 기록/늦은 안내가 B의 사용자·문맥·프로젝트에 나타나지 않도록 한다.
6. 「최종 결과물 저장 (배포)」 라벨은 **「검토용 버전 저장」**으로 맞추고 배포·승격 별도임을 알린다. C2/C3 전면 개편은 하지 않는다.

수명 주의: studioInputMemory는 모듈 Map이다. 같은 문서 재마운트와 **문서 새로고침은 다르다.** 새로고침 영속 보존이라고 쓰지 않는다. 기존 서버 목록 재조회로 회복되는 범위와 원키/본문 유실 한계를 구분한다. 이번에 localStorage/민감 본문 영속 저장을 신설하지 않는다.

집중 검증: UNKNOWN 반복 클릭 추가 POST 0, GET 복구, 확정 후 버튼 갱신, PAUSE/STOP 예외, A→B 늦은 응답, 같은 문서 재마운트. 실제 공용 모듈을 사용하며 기존 증거는 재사용한다.
