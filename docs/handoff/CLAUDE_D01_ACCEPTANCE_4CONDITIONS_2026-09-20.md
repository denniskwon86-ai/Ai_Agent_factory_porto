## ① 진입 — 통과

```
유효 링크  ?space=build&target=project&project=prj_ddb…
           → 서버가 준 이름 「합성 문맥 검증 프로젝트」로 열림
없는 대상  ?…&project=prj_does_not_exist_0000
           → 작업공간 «열리지 않음» · 「현재 회사·권한에서 프로젝트를 찾을 수 없습니다.」
           → 「현재 회사에서 다시 확인」 + 나갈 길(경영 홈·앱 제작)
네트워크   entry-metadata 404 «한 건» (+OPTIONS). 예전 기준선의 404 넷·SSE 구독·2~3회 반복 없음
```

문구가 「없습니다」가 아니라 **「현재 회사·권한에서 찾을 수 없습니다」** — 존재 여부를 흘리지 않는다.

## ② 페이지 이동 — 통과

```
뒤로 가기   없는 대상 화면 → Back → 유효 프로젝트 화면으로 복귀(URL·화면 함께). 거절 화면 잔상 0
입력 보호   앱 «안» 에서 「＋ 새 앱」 클릭 → 편집기 → 입력 「B6-LEAVE-GUARD-PROBE」 «값 확인» → Back
            → 주소가 움직이지 않음 · 편집기 유지 · 입력 보존
            → 「아직 저장하지 않은 입력이 있습니다.」
            → 선택지 5개: 요구초안 저장 / 저장 후 이동 / 입력 유지하고 이동 / 입력 폐기하고 이동 / 계속 작성
```

★ **관찰(결함 아님):** 이 보호는 **앱 안 이동**만 막는다. 주소창으로 직접 연 뒤의 뒤로 가기는
**문서 이동**이라 막히지 않고 입력이 사라진다. `studioLeaveGuard` 주석이 그 경계를 이미
적어 두었고(`beforeunload` 는 앱 안 이동의 대체 수단이 아니다), 이번에 `beforeunload` 를
새로 넣지 않았다. **수용 여부는 판단 사안**이다.

## ④ 권한 — **결함: 목록·진입은 막는데 릴리스 «단건 조회» 만 열려 있다**

같은 브라우저·같은 로그인(권혁일 · LS MnM 제련공장)에서 측정했다.

```
GET /api/v1/factory/proj_sent_synthetic/entry-metadata      → 404
GET /api/v1/factory/proj_sent_synthetic/state/latest        → 404
GET /api/v1/factory/library/list                            → 200, 2건
                                                              (rel_sent_synthetic_01 «없음»)
GET /api/v1/factory/library/item/rel_sent_synthetic_01      → **200**
                                                              project_id: proj_sent_synthetic
화면  ?target=release&release=rel_sent_synthetic_01
      → **정상적으로 열림** — 「합성 릴리스 (화면 확인용)」
         요구정의·기획서·화면설계·아키텍처·기술사양·프론트엔드·백엔드·코드검토·품질검증·
         수용검수·매뉴얼·추적성 탭 전부
```

`library/list` 는 자기 주석대로 **「보이는 프로젝트 집합」 밖의 릴리스를 건수까지 싣지
않는다.** 그런데 **같은 규칙이 `library/item` 에는 적용되지 않는다** — 릴리스 ID만 알면
그 프로젝트의 산출물 전문이 열린다.

**한쪽 문을 막고 거울 쪽을 열어 둔 형태다.**

### 과장하지 않기 위해 적어 두는 한계

- `proj_sent_synthetic` 이 **없는 프로젝트**인지 **안 보이는 프로젝트**인지는 은닉 계약상
  404 로는 구별되지 않는다. 즉 「다른 회사 것이 보인다」를 **실증한 것은 아니다.**
  실증하려면 **다른 회사 소유의 릴리스**가 필요하고, 그 fixture 를 만드는 것은 별도 승인 사안이다.
- 다만 어느 쪽이든 결과는 같다 — **목록이 적용하는 가시성 규칙이 단건 조회에 없다.**
  소유자 없는 릴리스가 모두에게 열리는 것도 같은 구멍이다.
- `rel_sent_synthetic_01` 은 화면 확인용으로 심어 둔 **합성 fixture** 다. 운영 자료가 아니다.

### 내가 고치지 않은 이유

서버 권한·은닉 계약 변경은 지시 없이 하지 않는다. 고친다면 `library/item` 이
`library/list` 와 **같은 가시 프로젝트 집합**을 쓰게 하는 한 줄 수준으로 보이나,
「소유자 없는 릴리스」 처리 방침이 함께 정해져야 한다. **지시를 구한다.**

## ⚠️ 이번에도 내 계측이 두 번 틀렸다 (보고 전 자체 적발)

1. **문서 이동으로 입력 보호를 시험하고 「보호가 안 뜬다」로 결론 낼 뻔했다.** 주소창으로 연 뒤
   누른 Back 은 앱 안 이동이 아니다. 가드 주석이 그 경계를 적어 두었는데 내가 읽고도
   시험 설계를 틀렸다. → **앱 안에서 눌러** 다시 하니 정상 동작.
2. 그 앞 시도에서는 **타이핑이 들어갔는지 확인하지 않고** 이동했다. → 이후에는 **값을 먼저
   읽고** 이동한다.

누적하면 이번 두 문서에서 계측 실수 5건이다. 전부 보고 전에 잡았고 제품 결함이 아니었다.
공통 원인은 **「무엇을 재는지」보다 「어떻게 재는지」를 먼저 정하지 않은 것**이다.
