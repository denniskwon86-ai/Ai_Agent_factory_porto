## 4. §10.1 「코드·문서 내려받기」 — 무엇이 틀려 있었나

두 화면이 각자 `a.href = .../export; a.click()` 이었다. 이 제품의 신원은 **`X-Session-Token`
헤더**이고(쿠키 아님) **앵커는 헤더를 못 싣는다.** 즉 **서버는 200 을 줄 수 있는데 버튼만
401** 이었고, 그 실패가 화면에 나오지도 않아 「눌렀는데 아무 일도 없다」였다.
개발 신뢰 헤더가 켜진 환경에서는 그마저 드러나지 않는다.

안 A(서버 무변경)로 고쳤다 — fetch 로 받고, 파일명은 서버 것, **401/403/404 를 구분해**
보이고, 실패하면 저장하지 않는다. 두 화면이 같은 함수를 쓴다.

## 5. ★ 먼저 봐 달라는 것

### ① 서버 한 줄이 필요한 잔여 — `Content-Disposition` 노출 (**승인 대상**)

교차 출처(5181→8086)에서는 그 헤더가 **응답에 노출되지 않아** 브라우저가 서버 파일명을
읽지 못하고 `<pid>.zip` 폴백을 쓴다. **종전과 같은 이름이라 회귀는 아니다.**
고치려면 CORS 에 `expose_headers=["Content-Disposition"]` 이 필요한데 **서버 계약 변경이라
손대지 않았다.** 같은 출처 배포에서는 문제가 없다.

### ② 내려받기 버튼의 **실제 클릭은 미검증**

이 fixture 에는 산출물이 없어 버튼이 **비활성**이다(「내려받을 결과가 없습니다」 — 정상).
그래서 «그 버튼이 쓰는 경로» 를 같은 페이지·같은 세션으로 호출해 확인했다. 산출물이 있는
프로젝트에서의 클릭은 **잔여**다(스프린트를 돌리지 않았다 — LLM 경로).

### ③ 계측 재현성 — 절차 문서에 **함정 ④⑤⑥** 으로 박았다

```
④ 기동이 organization_nodes 를 instance.json 으로 다시 쓴다 → 결속은 «세 곳» 에 적는다
⑤ SSE 티켓의 범위는 «본문» 이다(헤더는 제품이 일부러 무시) + 음성은 양성과 짝지어 적는다
⑥ 화면 관측은 «고유 문구» 로 판정한다(앞 600자·첫 dialog 로 판단하지 않는다)
```

### ④ `contexts/select` 권한 — 권고 접수, **보류 유지**

표/EXEMPT/`_ROLE_CAPS`/상태코드 **아무것도 고치지 않았다.** 이번 검증은 계정을 `manager` 로
«배정» 해 수행했고 그 범위를 명시했다.
