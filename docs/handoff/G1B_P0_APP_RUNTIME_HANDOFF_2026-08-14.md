**I-3 를 곧바로 배선하지 않는다** — 계약과 관측을 먼저 닫고, 격리 카나리로 종단 검증한
뒤에 전환한다.

### ⚠️ 다음 사람이 가장 먼저 할 일 — 승인 대기 중인 범위 추가 1건

**데이터셋에 매인 레코드 라우트 3개를 서버에 만들어야 한다.** I-3 의 선행이다.

```
GET    /api/v1/appdata/datasets/{dataset_id}/records/{record_id}
PUT    /api/v1/appdata/datasets/{dataset_id}/records/{record_id}
DELETE /api/v1/appdata/datasets/{dataset_id}/records/{record_id}
```

지금 서버에는 `PUT /records/{record_id}` · `DELETE /records/{record_id}` 처럼 **데이터셋을
말하지 않는** 경로만 있다. 브리지가 그것을 쓰면 앱은 자기가 이름 붙인 데이터셋이 아니라
**아무 레코드 id** 를 가리킬 수 있고, 현행 판정(`assert_release_*`)은 **사용자 기준**이라
그 사용자가 볼 수 있는 다른 앱의 레코드면 통과한다 — 앱 A 가 사용자를 대리해 앱 B 의
데이터를 고치는 **혼동된 대리인(confused deputy)** 이다.

★ 신규 PDP 는 앱 증명의 `release_id` 대조로 이것을 막는다. 그러나 **브리지는 전환 전에도
안전해야 하므로** 경로 자체를 데이터셋에 매는 것이 정답이다.

계약에 이미 적혀 있다: `core/host_runtime_wire.py` 의 `SERVER_ROUTES` · `ROUTES_OWED`.
`tests/test_host_runtime_wire.py::test_아직_없는_레코드_경로를_계약이_드러낸다` 가 잠근다.

> 이 항목은 G1-B P0 원래 목록에 없었다(계약을 짜다 발견). **범위 추가 승인 대기 중**이며
> 2026-08-13 보고에 올렸다. 승인 전이면 그 답부터 확인할 것.

### 1.1 판정 — `core/app_policy.py`

앱 데이터 접근 판정이 **한 곳**에 있다. 예외를 던지지 않고 **결정을 돌려준다**
(`allowed` · `reason` · `obligations`). 허용도 `obligations=("audit",)` 를 단다.

계약이 둘로 나뉘어 있다(교차검토 지시):

```python
ResourceScope      # 범용 — 테넌트·실행모드·조직범위·소유자·바인딩·상태. 온톨로지도 쓴다
AppResourceFacts   # 앱 전용 — release_id·app_class·매니페스트·선언 능력
```

판정 순서: 알 수 없는 행동 → 주체 없음 → **식별** → 차단 사유 → 자원 상태 →
**토큰 전수 대조** → 매니페스트 → 문맥 → 범위·부서 → 개인 앱.

⚠️ `Subject.blocked_reason` 은 **core 가 계산하지 않는다.** `api/deps.visibility_block_reason`
이 넣어 준다. 이 값을 빠뜨리면 **PDP 가 기존 판정보다 느슨해진다**(동등성 하니스가 실제로
그 칸을 잡아냈다).

### 1.2 증명 — `core/app_capability_token.py`

`sandbox_token`(VIRTUAL·read 고정)과 **다른 저장소**다. 전문을 저장하지 않고 sha256 해시로
보관한다. `session_id` 결속 · `scope_node_id` 필수 · `revoke_session()` ·
발급/사용/만료/취소 감사.

### 1.3 표면 — `core/host_runtime_sdk.py` (B01-A)

```
window.afs.data.{schema,list,get,create,update,remove}   데이터셋 「이름」으로만
window.afs.context.{app_id, release_id}                  표시용 읽기 전용
window.afs.{version, ready}
```

금지 항목을 **이름으로 적어 뒀다**: `afs.user`·`afs.token`·`afs.session`·`afs.fetch`·
`afs.sql`·`afs.db`·`afs.parent`·`afs.localStorage`·`afs.env`.

★ **범용 `fetch`/`sql` 을 열지 않은 이유** — 그 하나만 있으면 SDK 설계가 훨씬 쉽지만, 그 순간
**정책 결정점이 무의미해진다**(판정 대상이 「무엇을 하려는가」가 아니라 「어떤 문자열인가」가
된다). 그래서 행동 목록을 닫았다.

fail-closed 기본값 셋: ① 앱이 보낸 권한 입력 필드는 **검증이 아니라 삭제** ② 모르는 `op` 는
**쓰기로 취급** ③ 거부 사유의 기본 접힘이 **`NOT_FOUND`**.

## 2. 설계 판단 — 뒤집으려면 근거부터 보라

### 2.1 ★★★ `event.origin` 은 보안 경계가 아니다

앱 iframe 은 `sandbox="allow-scripts"` 다(= `allow-same-origin` 없음). 그래서 출처가
**불투명(opaque)** 이고 `event.origin` 은 `"null"` 로 온다.

⚠️ **아무 사이트나** 샌드박스 프레임을 만들어 같은 값을 낼 수 있다. 유일한 1차 경계는
`event.source === iframe.contentWindow` **동일성 비교**다. `sid` 는 2차, 봉투 표식은 3차.

⚠️ 같은 이유로 부모는 `targetOrigin` 을 지정할 수 없다(불투명 출처에는 이름이 없다).
즉 **응답은 `"*"` 로 나간다.** 그래서 §2.3 의 응답 투영이 선택이 아니다.

### 2.2 `sid` 는 자격증명이 아니라 **프레임 세대 라벨**이다

앱이 자기 프레임에서 읽을 수 있으므로 비밀이 될 수 없고, 권한 판정에 쓰이지 않는다.
하는 일은 하나 — **세대가 바뀌면 옛 프레임의 늦은 메시지를 버린다.**

⚠️ 남의 메시지·옛 세대는 **답하지 않고 버린다.** 오류로 답하면 그 답 자체가
「여기 부모가 있고 sid 가 틀렸다」는 정보가 된다.

### 2.3 ★★★ 서버 응답을 그대로 앱에 넘기지 않는다

`GET /datasets/by-name` 은 행 전체를 돌려준다 — `owner_dept_id`·`scope_node_id`·
`tenant_id`·`created_by` 포함. 그대로 넘기면 B01-A 가 `afs.user` 를 막아 놓고
**데이터로 같은 것을 흘리는** 셈이다.

허용목록으로 깎는다(금지목록이 아니다 — 서버가 필드를 하나 늘리는 순간 뚫린다):

```python
DATASET_PUBLIC_FIELDS = ("name", "label", "schema", "record_count")
RECORD_PUBLIC_FIELDS  = ("record_id", "payload", "created_at", "updated_at", "deleted")
```

⚠️ `dataset_id` 도 주지 않는다 — 앱은 데이터셋을 **이름으로만** 부른다는 것이 계약이고,
id 를 쥐여 주면 도로 보내는 코드가 생긴다(그리고 그 id 는 남의 것일 수 있다).

⚠️ `created_by`·`updated_by` 를 뺐다. 「누가 입력했는가」는 화면에 필요할 수 있지만 그것은
**동료의 계정 식별자**이고, LLM 이 쓴 앱 코드에 기본으로 줄 값이 아니다. 필요해지면
「표시 이름」을 서버가 판정해서 주는 별도 항목으로 연다 — **지금 열어 두고 나중에 닫는 것은
불가능하다.**

### 2.4 전달 실패는 「없다」가 아니다 — `UNAVAILABLE`

`app_error_code()` 의 기본 접힘은 `NOT_FOUND` 다. 시간 초과가 그리로 접히면 앱은
**서버에 있는 레코드를 화면에서 지운다.** 쓰기였다면 더 나쁘다 — 만들어졌는데 실패로 알고
다시 만든다.

그래서 전달 실패(시간 초과·서버 미도달·응답 과대)는 **판정 경로를 타지 않고**
`ERR_UNAVAILABLE` 로 간다. 뜻은 「막혔다」가 아니라 **「결과를 알 수 없다」** 이고,
앱이 할 일은 지우기가 아니라 **같은 멱등키로 재시도**다.

⚠️ 반대 방향도 막았다 — 판정 거부는 절대 `UNAVAILABLE` 로 접히지 않는다
(`DENY_ERROR_CODES`). 그러면 앱이 거부당한 쓰기를 무한히 다시 보낸다.

### 2.5 바꾸는 요청에 멱등키가 **필수**인 이유

이 계약은 `UNAVAILABLE` 을 받으면 재시도하라고 말한다. 즉 키가 없으면 **계약이 스스로
중복 쓰기를 만든다.**

⚠️ 다만 **「정확히 한 번」이 아니다.** 지금 막는 것은 한 세대 안의 중복(저장 두 번 누름,
`UNAVAILABLE` 후 재시도)뿐이고, 새로고침·프레임 재생성 이후의 재전송은 못 막는다.
서버 쪽 멱등은 `app_records` 변경이 필요하며 **아직 없다**(§5 부채).

### 2.6 없는 기능을 「있는 척」하지 않는다 — `version`

낙관적 동시성용 `version` 은 계약 모양에는 있으나 서버에 판 컬럼이 없고 `update_record` 는
**마지막 쓰기가 이긴다.**

받아서 무시하면 앱은 충돌 보호가 있다고 믿고 화면에 그렇게 표시하면서 남의 수정을 덮어쓴다
— 「조용한 거짓말」 그대로다. 그래서 **보내면 거부**한다(`NOT_YET_HONORED`).
서버가 검사하게 되면 그 튜플에서 이름을 빼는 것만으로 열린다(계약 모양은 그대로).

### 2.7 관측이 동작을 바꾸지 않는다

강제하는 것은 **기존 판정**이고 PDP 는 기록만 한다. PDP 가 터져도 요청은 살고, 대신
**센다**(조용한 유실 금지). 기록 저장소가 죽어도 요청은 살지만 **게이트는 닫힌 채로 있다** —
「기록이 안 되니 그냥 전환」이 되지 않는 방향이다.

## 3. 전환 게이트 — 「어긋남 0」으로는 전환하지 않는다

교차검토 지적: 종전 조건 `looser==0 and error==0 and total>0` 은 **읽기 한 건**만 일치해도
참이 된다.

정말 위험한 칸은 **눌러 보지 않으면 표본이 아예 생기지 않는다.** 그리고 **표본이 없는 것은
「안전」이 아니라 「모른다」** 다. 그래서 `policy_shadow.switch_gate()` 가 요구하는 것:

| 조건 | 상수·근거 |
|---|---|
| 여섯 작업 × **허용·거부 양쪽** 표본 | `REQUIRED_OPS` |
| 부정 시나리오 여섯 칸 | `REQUIRED_SCENARIOS` |
| 최소 표본 24건 | `MIN_TOTAL`(덮임 하한 18보다 위 — 「한 번씩 눌러 봄」과 「관측」은 다르다) |
| `looser` 0 · `error` 0 | |
| **설명되지 않은 강화** 0 | `EXPLAINED_STRICTER` |
| 기록 저장 실패 0 | |

부정 시나리오 여섯: 만료된 증명 · 다른 세션 재사용 · 다른 사용자의 증명 · 다른 앱의 데이터 ·
다른 조직 범위 · 문맥 불일치.

★★ **시나리오 라벨을 부르는 쪽이 붙이지 않는다.** 「이번 요청은 다른-앱 시나리오다」를
호출자가 선언하게 두면 그 라벨은 하니스가 **자기 자신과 합의한 값**이 된다. 대신
**PDP 가 낸 거부 사유**에서 읽는다 — 라벨을 만들려면 실제로 그 판정을 통과시켜야 한다.

⚠️ 설명되지 않은 **강화**도 막는다. 권한 확대만 사고가 아니다 — 예상 못 한 사유로 강화되면
전환하는 순간 **지금 되던 일이 안 되고**, 그 원인을 아무도 모른다.

### 지금 게이트 상태: **닫혀 있다**

토큰 관련 시나리오 넷은 브리지가 앱 증명을 발급해야 표본이 생긴다. 지금
`_shadow_check` 는 `via="session"` 으로만 판정하므로 `TOKEN_*` 사유가 나오지 않는다.
`data.get` 은 라우트 자체가 없다(§0).

**즉 게이트는 I-3 + 카나리 없이는 열리지 않는다.** 그것이 순서를 이렇게 잡은 이유다.

### 읽는 법

```python
from core.policy_shadow import policy_shadow
policy_shadow.switch_gate()            # 전체
policy_shadow.switch_gate("canary_1")  # 회차만 (환경변수 AFS_SHADOW_RUN 으로 태깅)
```

`blockers` 에 **막는 이유가 한국어 문장으로** 들어 있다. 「안 된다」만 있으면 사람은 게이트를
끄는 쪽을 택한다.

### 텔레메트리에 남지 않는 것

- **업무 데이터** · **토큰 전문**.
- 사유·작업은 **닫힌 목록**만 저장한다. 모르는 문자열은 `UNKNOWN`·빈 값이 된다 —
  예외 메시지가 사유 자리로 흘러드는 경로를 없앴다(예외는 자주 입력값을 담는다).
- `error()` 인자는 자유 문장이 아니라 **행동 + 예외 종류**다. 호출부에 「메시지는 넣지
  마세요」라고 부탁하는 대신 **넣을 자리를 없앴다.**
- 끊기지 않는 24자 이상 문자열은 가린다(`app_<urlsafe24>` · `token_urlsafe(32)` 가 그 모양).
  ★ 대조군 시험이 함께 있다 — 전부 가리면 「누가 어느 릴리스에서 막혔는가」에 답하지 못한다.

4. 응답을 **잘라서 주지 않는다.** 상한을 넘으면 오류다(자르면 조용한 거짓말이 된다).

## 7. 이번 작업에서 배운 것 (반복하지 말 것)

1. **죽은 가지를 「덮였다」고 우기지 않는다.** 봉투 필드 검사가 op 별 검사에 완전히 포함돼
   변이가 생존했다. 시험을 늘리는 대신 **가지를 지웠다.**
2. **내 하니스가 대조군을 스스로 무력화할 수 있다.** 게이트 시험의 채움값으로 `DENY_SCOPE` 를
   썼더니 「다른 조직」 시나리오가 공짜로 덮였고, 그 칸이 빠진 것을 잡는 시험이
   **거짓 초록**이었다. 채움값은 검사 대상과 겹치지 않는 것으로 고른다.
3. **「토큰은 안 들어올 것이다」로 두지 않는다.** 자리를 하나만 막으면 다음 사고는 다른
   자리에서 난다. 전수로 보고, **대조군**(정상 식별자는 안 가려진다)을 함께 둔다.
