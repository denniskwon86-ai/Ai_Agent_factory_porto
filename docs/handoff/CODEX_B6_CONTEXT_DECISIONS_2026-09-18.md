# B6-CONTEXT-SSE 다음 실행 결정

작성: Codex · 2026-09-18 KST. 공유 요청서 및 App 전환 경로, ProductShell, timeline 라우트/브로커/소비자, pause 생산자, supervisor 리스너 읽기 검토. 제품 수정·검사 재실행 없음.

## 검토 판정과 정정

- 전환기가 안 열린다는 보고는 측정 오류로 정정한다. 제품 결함 목록에 올리지 않는다. 이전 검토는 이 보고를 근거로 전환기 수정을 지시하지 않았다.
- FIX4의 구간 식별/현재 칸 번호 복구 방향과 기존 applyStudioEntry 재사용은 범위 내다. 별도 정책/진입 분기를 만들 필요 없다.
- 재확인 함수 이름 변경은 의미에 맞다. STATIC 검사와 추출 실행 검사의 증거 수준은 계속 구분한다.
- 현재 revalidateOpenEntry는 project/mega/draft/kit_app/release 다섯 조회 대상을 검사하며 new는 제외한다. '여섯 대상 모두 서버 재확인 완료'라고 쓰지 않는다. new는 조회 대상이 없으므로 새 문맥에서 입력 분리/권한 갱신을 검증하는 별도 경우다.
- plant scope→빈 scope 전환은 같은 tenant의 선택 조직 범위 변경이다. tenant가 실제 달라졌다는 증거 없이 회사 간 전환 성공으로 쓰지 않는다. 빈 scope는 권한 확대를 클라이언트가 부여하는 값이 아니라 서버가 판단하는 사용자 허용 범위다.
- 이전 SSE ABORTED와 새200은 재연결의 증거이고, 실제 이벤트 소비/격리 완료 증거는 아니다.

## 결정 1 — 열린 대상 화면에도 기존 문맥 전환을 제공

프로젝트 작업공간·초안 진입/편집 화면의 기존 상단에 현재 회사·선택 범위·REAL/VIRTUAL 표시와 전환 버튼을 둔다. ProductShell의 기존 문맥 칩을 작은 공유 컴포넌트로 재사용/추출해 모양·접근 가능한 이름·상태 원천을 유지한다. 전환 창은 기존 OperatingContextSwitcher 하나를 사용한다.
앱 전체 셸을 두 번 mount하거나 신규 전환 정책/새 내비게이션을 만들지 않는다. 모달 안에서는 버튼이 focus trap 밖에 갇히지 않도록 접근 가능한 헤더 위치를 선택한다. 첫20~30분에는 project와 draft 두 경로부터 닫는다.
전환 버튼을 누르기 전 미저장 입력/진행 중 상태를 기존 보호 정책으로 처리한다. 취소하면 문맥 자체가 바뀌지 않아야 한다. 전환 완료 후에는 이전 내용이 새 문맥에서 잠깐 보이지 않게 내리고 기존 진입 경로로 재확인한다. 다른 사용자/회사로 입력을 자동 복사하지 않는다.
URL/화면이 경계 배너로 어긋난 동안에는 URL이 현재 열린 대상이라는 가정을 하지 않는다. 이 경우 전환 전에 불일치를 해결하거나 실제 보존된 대상/입력을 안전하게 정리한다.

## 결정 2 — 거절 사례는 격리 fixture로 추가

기존 격리 조직/인증 생성 절차로만 계정과 범위를 추가해도 된다. 운영 계정·권한 정책·실사용자/키는 수정하지 않는다. role 우회, principal 모의 주입, localStorage로 불가능한 권한을 만들지 않는다.
서로 다른 두 증거를 분리한다:

- 선택 범위 전환 거절: A/B 범위 선택은 허용되지만 A 소유 프로젝트는 B 선택 문맥에서 보이지 않는 계정/소유권 조합. 열린 A 대상을 B로 바꿔 서버 재확인 후 비가시 거절을 확인한다.
- 사용자 권한 거절: 해당 대상 권한이 없는 좁은 계정의 실제 세션으로 진입. 단순401/유효하지 않은 노드의422를 대상 권한 거절로 세지 않는다.

기존 권한 모델상 첫 조합을 만들 수 없으면 권한 정책을 새로 만들지 말고 두 번째를 우선 수행하고 선택범위 사례의 한계를 보고한다. 현재 계약대로 비가시 대상은404, 명시 권한 거절은 해당 기존 상태코드를 유지한다. 테스트를 맞추려고403/404를 일괄 바꾸지 않는다.

## 결정 3 — SSE 이벤트 후보와 안전한 대안

확인한 실제 생산자는 core/async_orchestrator.py의 pause_sprint→SPRINT_PAUSED다. 그러나 활성 task와 엔진 상태가 필요하고 취소/정지 증거를 쓴다. 이번 이벤트 검증을 위해 sprint/start/resume/stop을 호출하지 않는다. NODE_COMPLETED는 감독 리스너가 LLM을 실행할 수 있으므로 표식으로 사용하지 않는다.
읽기만 하는 일반 제품 동작에서 무해한 timeline 생산자를 확인하지 못했다. 이를 확인된 제품 행동이라고 지어내지 않고 다음 대안을 승인한다:

- 격리 서버 프로세스 안의 테스트 하네스에서 B6_SCOPE_PROBE 같은 명시적 합성 표식 이벤트를 실제 factory_broadcaster.broadcast로 한정 발행한다. 유효한 합성 project_id와 고유 표식을 싣고 _broadcast_scope=global은 금지한다.
- 실제 /auth/sse-ticket→/ws/timeline→서버 권한/문맥 필터→EventSource→기존 store의 일반 로그 소비 경로를 그대로 사용한다. 화면/store에 직접 성공 값을 쓰거나 큐에 바로 넣어 권한 필터를 우회하지 않는다.
- 발행은 실제 SSE를 제공하는 프로세스/루프에서 수행해야 한다. 별도 Python 프로세스의 독립 broadcaster를 부르는 것은 전송 증거가 아니다. 재사용 가능한 하네스는 테스트 영역에, 임시 접근점은 격리 런처에서만 localhost·fixture ID 제한으로 제공한다. 제품 라우터에 디버그 발행 API를 추가하지 않는다.
- 현재 확인한 SupervisorDaemon은 지정 노드의 NODE_COMPLETED에만 반응한다. 기동된 하네스의 다른 내부 리스너/외부 알림이 이 표식에 부작용을 만들지 않는지 확인하고 LLM/외부 전송0을 지킨다. 안전 확인이 안 되면 발행을 중단하고 원인을 보고한다.
- B 문맥의 표식 수신·store/보이는 로그 소비를 양성 대조로 확인한다. A 전용 표식이 B 연결에 들어오지 않는 것은 네트워크에서 확인하고, 프런트가 뒤늦은 옛 연결 이벤트를 무시하는 것은 별도 지연 이벤트 실행 시험으로 증명한다. 서로 대체하지 않는다.
- 같은 프로젝트가 A/B 둘 다 보이면 그 이벤트는 B에서도 정당할 수 있다. 차단 시험에는 B에서 비가시인 A 소유 fixture를 사용한다. '아무 이벤트도 안 옴'만으로 성공이라고 하지 않는다.

결과 표기: '합성 생산자 + 실제 제품 SSE 전달/필터/소비'다. 실제 업무 행동→생산자 연계, LLM 실행, 시뮬레이션 전체 parity까지 통과했다고 쓰지 않는다. 이 제한이 B6 특정 조건을 닫는지 정본과 대조한다.
