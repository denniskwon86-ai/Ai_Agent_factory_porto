## 2. 선반의 키트가 **등록부에 올라갑니다**

예전에는 `profile_from_manifest()` 를 `demo_vertical_slice` 하나만 불러, 선반에
무엇을 올려도 **조직에 붙일 수 없었습니다**(`POST /instances` 는 등록부를 봅니다).

    kit_registry.discover_starter_kits()   선반의 **봉인된 판본**만 읽는다
    kit_registry.register_all()            두 곳(Profile · 선반)을 함께 등록한다

| | |
|---|---|
| 무엇이 올라가나 | **봉인된 판본만.** 작업 중인 것을 붙이면 그 뒤 내용이 바뀌어도 붙인 쪽은 모릅니다 |
| 이름 | `kit_name` → `company_name` → `kit_id` 순으로 떨어집니다 |
| `mode` | `data_class` 매핑. **모르는 값은 올리지 않습니다** |
| 구분 | `profile.kit_source == "STARTER_KIT"` |

★ **지문을 manifest 원문에서 뽑습니다 — 대장이 아닙니다.**
  `demo_vertical_slice.register_kit()` 이 같은 판본을 manifest 지문으로 이미
  등록하는데, 둘이 다르면 등록부가 「동결 판본의 지문이 달라졌다」로 **거부**합니다
  (P3-2) — 먼저 부른 쪽이 이기는 싸움이 됩니다.
