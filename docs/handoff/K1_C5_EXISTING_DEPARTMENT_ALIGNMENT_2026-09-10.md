## 2. 공장과 사업부를 같은 ID로 바꾸지 않는다

원천의 두 범위는 `site_plant`, 기존 생산 부서의 대응 범위는 `business_division`이다. 이름이 비슷하다는 이유로 원천 공장 ID를 사업부 ID로 치환하면 공장별 낟알이 사라진다.

```text
기존 LS MnM 법인
├─ 기존 동제련 사업부 / 동제련 생산 부서
│  └─ 제련공장 범위 (기존 공장 대응 확인 또는 제품 자동 채번 등록)
└─ 기존 배터리소재 사업부 / 배터리소재 생산 부서
   └─ 배터리소재 공장 범위 (기존 공장 대응 확인 또는 제품 자동 채번 등록)

발주 소유 부서 = 구매
물류 4종 소유 부서 = 물류
```

이는 공장마다 새 부서를 만들겠다는 뜻이 아니다. **자료 적용 범위와 자료 관리 부서는 별개**다. 기존 사업부 아래의 제1·제2공장을 키트 공장과 같다고 추정하지 않으며, 이전 공장/법인 노드도 삭제하지 않는다.

새 명세는 목표 공장 ID, 소유권 시행일, 승인 사건을 null로 유지한다. 등록 단계에서 제품 자동 채번과 기존 승인 API가 채워야 한다. 사용자가 ID를 입력하게 하지 않는다.

## 7. K1-c6a — 공장 재사용 조사 체크포인트 (2026-09-10)

### 권고 방안 — 시연용 고정가격 규칙의 소규모 후보부터

1. **가격 규칙을 먼저 선택한다.** A안은 계약마다 합의한 가격 결정일에 알려진 가격을 고정, B안은 발주일별 변동가격이다. 현재 PRC-01의 단일 benchmark_price 구조에는 A안이 더 잘 맞는다. B안은 발주별 fixing/원천 결속 및 단일 계약 가격과의 관계를 추가로 정의해야 한다.
2. **A안의 미승인 시연 가정:** 계약 valid_from을 가격 결정일로 놓고 `observed_at`, `published_at`, `vintage_date`가 모두 그 날짜 이하인 관측만 선택한다. 그 안에서 최근 관측·공표·vintage 순으로 고르고 동일 시점 중복은 거부한다. 미래 수정본을 과거에 넣지 않는다. valid_from은 앞선 합성자료 보정에서 바뀐 유효일이므로 실제 가격 결정일 증거는 아니며, 사용자 시연 정책 선택이 필요하다.
3. **첫 후보 범위 제안:** 코드·단위·통화가 일치하는 아래 2건·36행으로 규칙을 검증한다. 코드 일치만으로 품위·규격·정산/중량 기준까지 맞는 것은 아니다. 시연용 가격 기준을 명시해야 하며 실제 업무 가격이라고 주장하지 않는다.
