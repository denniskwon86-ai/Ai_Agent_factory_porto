기존 부서가 가리키는 회사·조직을 유지한다. 자료에 맞춰 사람과 부서의 조직 범위를 바꾸지 않는다.

기존 조직의 tenant는 `tenant_default`다. 현재 설치 설정은 `tenant-afs-demo-materials`이므로 **목표와 현재를 구분한다**. 이번 지시를 향후 전환 방향의 근거로 남기되, 설정 파일만 먼저 바꾸지 않는다.

새 부서 0개, 사용자/역할 변경 0개. 기존 부서 ID·버전·현재 scope는 보존한다.

## 2. 공장과 사업부를 같은 ID로 바꾸지 않는다

원천의 두 범위는 `site_plant`, 기존 생산 부서의 대응 범위는 `business_division`이다. 이름이 비슷하다는 이유로 원천 공장 ID를 사업부 ID로 치환하면 공장별 낟알이 사라진다.

```text
기존 LS MnM 법인
├─ 기존 동제련 사업부 / 동제련 생산 부서
│  └─ 제련공장 범위 (기존 공장 대응 확인 또는 제품 자동 채번 등록)
└─ 기존 배터리소재 사업부 / 배터리소재 생산 부서
   └─ 배터리소재 공장 범위 (기존 공장 대응 확인 또는 제품 자동 채번 등록)

발주 소유 부서 = 구매
물류 4종 소유 부서 = 물류
```

이는 공장마다 새 부서를 만들겠다는 뜻이 아니다. **자료 적용 범위와 자료 관리 부서는 별개**다. 기존 사업부 아래의 제1·제2공장을 키트 공장과 같다고 추정하지 않으며, 이전 공장/법인 노드도 삭제하지 않는다.

새 명세는 목표 공장 ID, 소유권 시행일, 승인 사건을 null로 유지한다. 등록 단계에서 제품 자동 채번과 기존 승인 API가 채워야 한다. 사용자가 ID를 입력하게 하지 않는다.
