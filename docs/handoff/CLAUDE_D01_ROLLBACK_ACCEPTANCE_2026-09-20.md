## 1. 왜 이 흐름을 골랐나

D01 의 남은 칸은 「실사용 검증」 하나이고, 그 조건 중 **롤백만 증거가 0** 이었다.
UI·서버·권한이 모두 이미 있고, 앞 라운드에서 만든 격리 합성 릴리스로 끝까지 밟을 수 있으며,
`reactivate` 로 되돌릴 수 있다 — 비과금으로 닫을 수 있는 유일한 조건이었다.

## 2. 밟은 경로 (전부 제품 화면 · 실제 포인터/키보드)

```
로그인(권혁일) → ☰ 전체 메뉴 → 🏢 워크스페이스(?space=workspace)
  → 릴리스 선택 → 「게이트 점검」
  → 3. 운영 준비 → 「운영에서 내리기」
  → 확인창 → 사유 입력 → 「사유를 기록하고 사용 중단」
앱 제작 → 릴리스 탭 → ☑ 사용 중단 포함 → 그 행 → 「릴리스 관리」 → 「▶ 사용 재개」
```

## 3. 확인된 것

| 수용 항목 | 결과 |
|---|---|
| **사유 없이 통과되지 않는가** | **막힌다.** 사유가 비면 확인 버튼이 `disabled` — 경고만 띄우고 눌리는 구조가 아니다 |
| 확인창이 무엇을 말하는가 | 4항목 고지 — 무엇이 바뀌는가 / 영향 범위(「쓰고 있는 쪽은 즉시 막힙니다 · 공유 0곳」) / 되돌릴 수 있는가 / 필요한 승인·근거 |
| 한계를 숨기지 않는가 | 완료 후 **「이미 배포된 코드 자체는 되돌리지 못합니다(실행 중 인스턴스·외부 배포본)」** 를 명시. 「삭제하지 않았다 — 남의 기록이 고아가 되기 때문」도 함께 |
| 서버 상태가 실제로 바뀌는가 | `GET /api/v1/programs/{id}` → `state: disabled`, `reason: "롤백: B6-ROLLBACK-PROBE…"` |
| **대상 격리** | 옆 릴리스(`…150809`)는 `candidate` 그대로 — 선택한 판만 내려갔다 |
| 감사 이력 | 3건이 **행위자·사유와 함께** 남는다(「지워지지 않습니다」). 게시 → 사용 중단 → 사용 재개, 전부 `권혁일` |
| 되돌릴 수 있는가 | **된다.** 워크스페이스에는 재개 입구가 없고(확인창이 「재사용은 별도 검토」라 말한 대로), **릴리스 관리(ProgramAdminPanel)** 에 「▶ 사용 재개」가 있다 |
| 게이트 판정 | 사용 자산·데이터 계약·보안·품질이 **「확인 불가(통과 아님)」** 로 나온다 — 모르는 것을 안전으로 치지 않는다 |

## 4. ⚠️ 그대로 두고 판단을 구하는 것 2건 (고치지 않았다)

1. **재개 후 상태가 `candidate` 가 아니라 `active`.** 내리기 전은 `candidate`(게시된 새 판 —
   승격 대상)였는데 「사용 재개」 뒤에는 `active` 다. 이력 표기(「사용 중단 → 사용 중」)와는
   일관되지만 **원래 값으로 돌아가지는 않는다.** 설계인지 결함인지는 내가 정할 일이 아니다.
2. **릴리스 선택 목록에서 두 판이 같은 이름으로 보인다.** 라벨이
   `display_name || project_name` 이라 같은 프로젝트의 두 판이 구별되지 않는다
   (값은 다르다). **어느 판을 내리는지 고를 때** 이름만으로는 알 수 없다.
   ★ 롤백처럼 되돌리기 어려운 화면에서는 위험 쪽이다. 게시 시각을 라벨에 붙이는 정도로
   충분해 보이나, 목록 라벨 규칙은 여러 화면이 공유하므로 지시를 받고 고치겠다.

## 5. ⚠️ 이번 실측에서 내가 세 번 잘못 읽었다

전부 **보고 전에 스스로 잡았고** 제품 결함이 아니었다. 기록으로 남긴다.

1. **자비스 추천 질문 칩을 롤백 버튼으로 셌다** — 「운영에서 내리기 전에 어떤 영향을…」이
   부분 문자열로 걸렸다. → 버튼은 **정확 일치**로 센다.
2. **「사용 중단 포함」을 머리글로 읽고 「고지와 동작이 어긋난다」고 결론지을 뻔했다** —
   그것은 **체크박스**(기본 꺼짐)였다. → 문구를 읽기 전에 **요소 종류**를 본다.
3. **상세 창을 목록으로 읽고 「내린 판이 사라졌다」고 판정할 뻔했다** — 목록은 2건이 맞았고
   상세 창만 이전 선택을 보여주고 있었다. → 목록과 상세를 **따로** 센다.

또 하나: **`form_input` 으로 select 값을 넣으면 React 가 못 본다.** 값은 바뀌는데 화면이
반응하지 않았다. **실제 포커스 + 키보드**로 바꾸니 즉시 반영됐다. 이후 조작은 전부
실제 포인터/키보드다.
