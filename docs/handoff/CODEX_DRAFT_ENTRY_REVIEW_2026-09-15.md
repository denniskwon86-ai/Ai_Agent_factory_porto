# DRAFT-ENTRY-01 검토 및 다음 실행 지시

작성: Codex · 2026-09-15. 사용자 전달 보고와 공유 소스/격리 결과를 읽기 검토했다.
제품·테스트 실행 담당은 Claude Code. Codex는 제품 수정과 테스트 재실행을 하지 않았다.

## 판정과 근거

- DRAFT-ENTRY-01의 제한된 metadata/reader/Gate 범위 구현은 확인했다. 그러나 초안 진입 전체 완료나 B6 수용 완료로 승인하지 않는다.
- App.tsx의 draft 분기는 StudioDraftEntryGate에 children을 전달하지 않는다. AVAILABLE에서도 조회 가능 안내만 나오며 실제 초안 본문/편집기는 열리지 않는다. 이는 보고된 잔여 범위이며, 새로 숨겨진 결함이라고 주장하지 않는다.
- 서버는 draft ID에서 저장된 boundary를 찾아 기존 authorize(READ)를 호출하고 요청 revision을 조회한다. 프런트는 ID·kind·revision 응답 일치와 문맥/요청 수명을 검사한다. 읽기 허용은 수정·승인·생성 허용이 아니다.
- 공통 flow 추출은 수명 부분에 한정되었고 대상별 오류는 보존되어 있다.
- 이전 MEGA 보완의 requireMega 전달과 true 검사, 감사시험의 독립 로그/표식 이후 사건 검사는 소스에서 확인했다. 이전 검토 전체를 재실행했다고 주장하지 않는다.

## 검사 증거를 정확히 표기

- output/usage-holds-aifmeq2d/tests.xml 및 isolation.json 확인: 서버 301 PASS / 2 SKIP / 0 FAIL, wrapper exit 0, sources_unchanged 및 protected_assets_unchanged true.
- 두 SKIP은 기존 bootstrap의 symlink/dangling-symlink 생성 권한·파일시스템 미지원이다. 새 권한 시험을 skip으로 우회한 것은 아니다. 해당 두 조건 검증 완료로 계산하지 않는다.
- 프런트 43+16+25+14+36=134 PASS 및 build PASS는 Claude 보고값이며 Codex 재실행값이 아니다.
- 별도 route_authority 스위트의 4 ERROR(ecm_org_seed 부재)는 남은 검증 공백이다. 위 9개 스위트 성공과 구분해서 계속 보고한다. 파일 미변경만으로 영향 없음이 증명됐다고 쓰지 않는다.
- 실제 브라우저 NOT_RUN. 변이 시험 결과는 Claude 보고값으로 보존한다.

## consultation 결정

당장은 명시적 지원 전 응답을 유지한다. turn_no를 revision으로 새로 정의하지 않는다.
A안의 두 행동을 분리한다: 지원 전 유지는 진행하되 URL 문법에서 revision을 제거하는 변경은 이번 묶음에 넣지 않는다.
아직 열 수 없는 종류의 문법부터 바꾸면 기능 완성 없이 계약 변경만 늘어난다. 상담 재진입의 대상/시점 의미가 정해질 때 별도로 설계한다.
지원하지 않는 링크를 최신 상담으로 조용히 대체하거나 성공 처리하지 않는다. 안내에 목록을 권한다면 실제로 그 목록에서 열 수 있는지도 확인하고, 확인 불가하면 중립적인 지원 전 안내를 사용한다.

## 다음 작업: DRAFT-OPEN-01 — 확인한 blueprint를 실제로 열기

사용자에게 보이는 목표: 초안 링크 → 요청한 판본 본문 표시 → 허용된 경우 기존 요구사항 화면에서 편집을 이어갈 수 있음.
광범위한 히스토리/UI 재설계보다 이 연결을 먼저 닫는다. 새 편집기를 만들지 않고 기존 BuildStartDialog 및 studioRequirementDraft의 제한적 확장부터 한다.

### 첫 묶음: 20~30분 예상, 완료 보장 시간이 아니라 중간 보고 시점

1. 공유 실행 상태에 작업 ID, ACK/RUNNING, 착수 시각과 이번 완료 조건을 기록한다.
2. 최대 5분 안에 기존 편집기 연결 계획을 짧게 기록한다. 참조: frontend/src/components/BuildStartDialog.tsx, frontend/src/lib/studioRequirementDraft.ts, frontend/src/factory/StudioDraftEntryGate.tsx, frontend/src/App.tsx.
3. Gate가 확인한 entry를 소비하는 연결과 exact revision 불러오기 경로를 구현한다. 기존 GET /drafts/{id}를 사용할 때 서버가 돌려준 ownership의 boundary 및 요청 revision을 사용한다. 선택 문맥으로 소유 boundary를 재구성하지 않는다.
4. readLatest는 현재 충돌 중인 receipt가 있어야 하고 최신판을 조회하는 함수다. 이를 직접 링크의 최초/지정판 불러오기로 재사용하면 안 된다. 별도의 명확한 load 동작을 두되 기존 검증·오류 처리는 재사용한다.
5. 원문 응답의 draft_id/revision/context_key와 지문 등 기존 판본 계약을 확인한 뒤 form과 receipt를 일관되게 결합한다. 내용의 종류/필수 매핑을 확인할 수 없으면 software_app 또는 빈 양식으로 추측해 덮지 말고 명시적으로 막는다.
6. 초기 seed/싱글턴 메모리와 로드 결과가 서로 덮어쓰지 않게 한다. 미저장 입력이 있으면 보존하고 전환 확인을 받는다. 진입만으로 저장·승인·프로젝트 생성은 절대 실행하지 않는다.
7. 조회 권한만 있는 사용자는 내용을 볼 수 있어도 수정 권한을 얻지 않는다. 기존 편집 권한/상태 통제를 유지하고, 과거판을 최신판으로 조용히 바꾸거나 기존 revision/digest 충돌 방지를 우회하지 않는다.

### 완료 확인: 추가 15~25분 예상

- 최소 실제 동작 검사: 지정판 내용 표시, ID/판본 불일치 거절, 회사/사용자 전환·닫기 후 늦은 응답 무시, 미저장 입력 보존, 과거판 저장 충돌, 조회 중 자동 쓰기 0회.
- 변경 지점의 좁은 검사부터 실행한다. 공통 flow를 다시 바꾸지 않았다면 전체 서버/모든 변이를 매 단계 반복하지 않는다. 연결 후 관련 프런트 검사와 build를 한 번 수행한다.
- 합성 격리 데이터로 실제 화면의 정상 링크 1건과 거절/전환 경로를 확인한다. 화면을 못 열었으면 NOT_RUN과 정확한 이유를 남긴다. fixture 성공을 실제 제품 연결 성공으로 대체하지 않는다.
- 서버 원문 조회도 자체 권한 검사를 통과해야 한다. metadata 승인을 이후 요청의 권한 토큰처럼 사용하지 않는다. 조회 도중 권한 변경 처리의 기존 보장과 차이가 드러나면 재현 근거를 보고하고 제한적으로 보완한다.
- route_authority 4 ERROR는 별도 검증 부채로 남긴다. 해결 시 필요한 seed만 안전하게 격리 제공하며 운영 conftest/DB 전체 적재로 우회하지 않는다. 이 문제로 첫 기능 연결 묶음 전체를 소진하지 않는다.

## 보고/종료 규칙

- 20~30분 시점에는 작동하는 사용자 동작, 변경 파일, 검사 결과, 남은 막힘, 다음 예상 시간을 보고한다. 검사 개수보다 무엇을 실제로 열 수 있게 됐는지를 먼저 쓴다.
- 전체 21/40=52.5%, 로컬 18/28=64.3%는 현재 유지한다. 세부 작업 상태와 정본 완료 칸은 별도다. 정본 조건을 충족한 칸의 ID와 증거가 있을 때만 가산한다.
- DRAFT-OPEN-01 이후 단일 진입·뒤로/앞으로·새로고침 수용으로 이동한다. 이번 지시는 그 전체 재설계까지 한꺼번에 수행하라는 지시가 아니다.
- App.tsx와 제품/테스트 코드의 단독 작성자는 Claude. 사용자 로그·DB·공유 ZIP·기존 미커밋 변경 보존. pull/reset/복원/커밋/푸시를 하지 않는다.
- 본 문서는 준비된 지시다. Claude가 수신 기록을 남기기 전에는 전달/실행 시작으로 보고하지 않는다.
