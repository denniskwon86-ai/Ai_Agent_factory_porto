## 2. 결정 1 — 열린 대상 화면에도 기존 전환을 제공

- `ProductShell` 안의 칩 마크업을 **공용 컴포넌트**(`OperatingContextChip`)로 뽑고 **셸도 그것을
  쓴다.** 작업공간·초안 편집기는 같은 컴포넌트·같은 상태 출처·같은 접근 이름
  (`aria-label="회사 문맥 전환"`). 전환 창은 **기존 하나**. 셸을 두 번 mount 하지 않았다.
- 초안 편집기는 **대화상자 «안»**(`contextChip` 자리)에 둔다 — 초점을 가두므로 바깥 칩은
  키보드로 닿지 않는다(실측: `closest('[role=dialog]')` 참·클릭 가능 참).
- 전환을 여는 **문은 하나**다:

```ts
const openContextSwitcher = useCallback(() => {
  if (strandedEntry) { setContextBlocked(true); return; }   // 주소·화면이 어긋난 동안엔 못 바꾼다
  confirmLeave(() => setShowContextSwitcher(true));          // 기존 보호 정책 그대로
}, [strandedEntry]);
```

  취소하면 전환 창이 **열리지 않는다** → 문맥이 바뀔 기회 자체가 없다.
  어긋난 주소가 떠 있으면 `revalidateOpenEntry` 도 **URL 을 믿지 않고 안전하게 정리만** 한다.
- 가는 길에 결함 하나: 좁은 화면에서 칩이 **22px 로 찌그러져 다른 버튼에 덮였다**(클릭 불가).
  상단 바 줄바꿈을 허용해 덮이는 대신 내려가게 했다.

## 3. 결정 2 — 거절 fixture (추가만, 정책 무변경)

기존 절차(`create_department`·`upsert_user`·`set_user_roles`)만 썼다. **운영 계정·권한
정책·실사용자·키 무변경.** role 우회·principal 모의 주입·localStorage 권한 조작 없음.
합성 계정은 `.invalid`.

```
부서 demo_battery → 기존 ECM 노드 plant-afs-battery-02 (노드 신규 생성 없음)
계정 t_scope_probe@afs.invalid   비관리자 · 두 부서 manager  → A/B 둘 다 «고를 수 있다»
     t_narrow_probe@afs.invalid  비관리자 · battery 만       → 제련공장에 role 없음
```

### 서버 판정 (실제 세션 + 실제 제품 API)

```
① 선택 범위 거절  t_scope_probe / A → 200 · B → 404 「현재 문맥에서 … 찾을 수 없습니다」
② 사용자 권한 거절 t_narrow_probe / A·B → 404
③ 대조군          hikwon / A → 200
```

①은 **계정을 바꾸지 않고 고른 범위만 바꿔** 200→404 로 뒤집혔다. ③이 없으면 「원래 다
404」를 배제할 수 없다.

### 화면 (사람이 로그인 · 비관리자 세션)

```
A 에서 프로젝트 열기 → 작업공간
칩 → B 선택        → entry-metadata 404 · 화면 「현재 회사·권한에서 프로젝트를 찾을 수 없습니다」
                     작업공간 사라짐 · 옛 제목 없음 · URL 의 project= 는 유지
A 로 되돌림        → 작업공간 복귀
```

⚠️ **한계**: ②의 거절도 **404(비가시)** 다. 「보이지만 권한이 없는」 403 은 조회가 아니라
쓰기 행동의 경우이며 이번 범위 밖이다. 상태코드를 맞추려고 고치지 않았다.

### 세 사실을 **구분해서** 적는다

| 사실 | 증거 | 결과 |
|---|---|---|
| 서버가 그 연결로 **보냈는가** | 브라우저 실측(제품 티켓→/ws/timeline→EventSource) | B 구독 **수신 0** · A 구독 **수신** |
| 제품 store 가 **소비하는가** | 실제 store 실행 시험 + 변이 | 소비 확인 |
| 그 화면에 **보이는가** | — | **미확인**(로그를 그리는 자리를 못 찾았다) |

### 뒤늦은 «옛 연결» 이벤트 무시 — 별도 실행 시험으로 닫았다

```
A 연결 → 문맥 바꿔 재연결 → «옛 연결» 이 늦게 뱉음 → 로그에 안 들어감
양성 대조: «지금 연결» 이 뱉으면 들어감
변이: isCurrentConnection 가드 제거 → 38 PASS → 37 PASS / 1 FAIL (원복 해시 일치)
```

**결과 표기: 「합성 생산자 + 실제 제품 SSE 전달/필터/소비」.** 실제 업무 행동 연계·LLM·
시뮬레이션 parity 는 주장하지 않는다.

## 5. ★ 먼저 봐 달라는 것 — 이번에 내 계측이 두 번 틀렸다

### ① ⚠️ SSE 음성 시험을 한 번 **틀리게** 쟀다

처음엔 B 구독에 A 소유 표식이 **들어왔다.** 「실시간 경계가 뚫렸다」로 보고할 뻔했는데,
원인은 제품이 아니라 계측기였다 — `POST /auth/sse-ticket` 은 **헤더의 범위를 일부러
무시**하고 **본문 `scope_node_id`** 만 본다(그 라우트 주석: 「요청자가 scope 를 지정하지
않는다」). 나는 헤더로만 보냈고 티켓이 «전체» 로 발급됐다. 본문으로 고쳐 다시 쟀다.
**보고 전에 잡았지만, 같은 실수를 세 번째 하고 있다**(「재는 도구부터 증명한다」).

### ② ⚠️ 화면 관측 판정도 한 번 느슨했다

앞 라운드에서 「전환기가 안 열린다」고 보고한 것은 `body.innerText.slice(0,600)` 만 본
탓이었다. 이번에도 `[role=dialog]` 하나로 판정하다 **HubDialog 의 머리말 문구**를 전환
창으로 오인했다. 이제 전환 창은 **본문 고유 문구**(「회사·조직 선택」)로만 판정한다.

### ③ 제품 소견 — `contexts/select` 가 `admin.organization` 을 요구한다 (**정책 미변경**)

```
표: POST /api/v1/enterprise-context/contexts/select → ('admin.organization',)
역할: viewer ✗ member ✗ manager ✓
member 계정 → 자기 범위 A·B 둘 다 403 「관리자 센터의 해당 탭 권한이 필요합니다」
```

그 엔드포인트는 **아무것도 저장하지 않고** 자기 안에 이미 `can_read_node` 검사가 있다.
viewer·member 는 그 검사에 **닿지도 못한다.** 표의 이웃(`tenants` 회사 이름 세우기 ·
`profiles/approve`)은 진짜 기준정보 수정이라 성격이 다르다. **의도인지 결정이 필요하다.**
(이 때문에 이번 화면 검증은 계정을 `manager` 로 «배정» 해서 했다 — 역할이 가진 권한은
건드리지 않았다.)

### ④ 내 fixture 결함 둘 — 고쳤다

- 배터리 ECM 노드에 `dept_id` 를 안 묶었다. 부서 쪽만 묶고 **노드 쪽**을 빠뜨렸다
  (`seed_ecm` 이 양쪽을 묶는 이유). → `readable_scope_nodes` 엔 있는데 `can_read_node` 는 거절.
- 그 결속이 **재기동으로 사라졌다.** `run.py` 의 `_apply_installation_settings()` 가
  `data/instance.json` 으로 `organization_nodes` 를 매 기동 다시 쓴다. → `instance.json` 에
  적어 고쳤고 재기동 후 유지를 확인했다. **절차 문서 갱신 대상.**

### ⑤ 잔여 — 거절 화면에는 문맥 칩이 없다

`button.afs-context` → null. 되돌리려면 「경영 홈」·「앱 제작」으로 나갔다 와야 한다.
결정 1 은 「작업공간·초안 편집기」를 지정했고 **게이트/거절 화면은 그 목록에 없었다** —
넓힐지는 지시 대상이다.
