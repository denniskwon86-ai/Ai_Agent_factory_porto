2. 홈/닫기 시 업무앱 화면·대상을 함께 놓은 수정은 타당하다. 초안/메가 포함 여섯 대상의 열기·닫기·홈·회사 전환 지점만 제한적으로 대조한다. 앱 모든 메뉴/화면 전수검사로 확대하지 않는다.
3. 권한표 선언 계약 시험은 적절하다. output/usage-holds-wjf6gvsn/tests.xml에서10 tests/0 failures/0 errors/0 skipped, isolation.json에서exit0·소스/보호자산 불변 true·차단 쓰기/SQLite경로0·conftest 미로드를 직접 확인했다. 기존4 ERROR 부채 종결. 선언 매핑과 런타임 단독 효력을 구분한 기록 유지. 추가 변이 확대 불필요.
4. library 경로 정정은 필요하다. 제품 코드의 상대경로를 확인했다. 과거 브라우저 환경의 전체 격리 주장은 철회/범위 정정하고, 최신 격리 러너 결과와 혼동하지 않는다. 최신 날짜 불변만으로 과거 쓰기가 전혀 없었다고 확정할 수 없다. '수행한 검증은 읽기였고 관찰한 변경은 없으나 과거 전체 무변경 증거는 제한적'으로 표현한다. 데이터 유출/변조를 확인한 것으로도 쓰지 않는다.
5. 실제 브라우저 history.go(-2)는 브라우저 기반 이동 시험이다. 사람의 다단계 메뉴 클릭/현업 수용과 구분하면 유효하다. 같은 시험을 수동 메뉴로 반복할 필요 없다.
6. 합성 릴리스의 실제 API/화면 진입·닫기·복원은 그 범위의 유효한 증거다. 업무앱 진입 시험은 시뮬레이션 실행 증거가 아니다. LLM/운영 데이터로 결과를 억지로 확대하지 않은 선택은 적절하다.

## 시작 전 작은 안전 점검 — 10~15분 상한

### A. 경계 배너의 연속 전이

App 배너의 '이 화면의 주소로 되돌리기'는 현재 칸의 주소를 교체하지만 historyIndex.current를 그 칸의 실제 state에 맞추지 않는다. 예전 화면의 번호가 남으면 이후 명시 이동에서 새 번호를 잘못 붙일 수 있다. '주소가 가리키는 화면으로 이동' 쪽은 이미 현재 state를 읽는다.
초점은 배너 철회가 아니라 두 선택 이후의 연속 이동이다. 미관리 항목 진입→현재 화면 주소 복구→다른 대상 이동→뒤로/앞으로 취소를 한 건 재현한다. 현재 칸 번호가 없으면 이전 번호를 그대로 사용하지 않는다. 관리 구간이 다른 항목 간 정수 차이만으로 방향을 추정하지 않는다. 번호를 모르면 기존 안전한 대체 동작을 사용한다.
판정/해결은 이 경계 한 건에 제한한다. 기존 전체 URL 시험과 모든 변이를 다시 반복하지 않는다. 보호 결함이 재현되면 최소 보완 후 다음 묶음으로 간다.

### B. 격리 기동 경로 확인

다음 회사/SSE 검증이 실제 사용하는 기동·인증·조직/정책·프로젝트·라이브러리·로그 저장 경로만 조사한다. 전체 저장소 상대경로 전수 감사는 하지 않는다.
실행 cwd, import된 모듈 경로, 실제 절대 데이터 경로를 기록하고 모두 지정 격리 루트에 포함되는지 경로 구성요소 기준으로 확인한다. 문자열 startswith만으로 형제 디렉토리를 포함시키지 않는다. 운영 내용/토큰은 출력하지 않는다.
하나라도 운영 쓰기 경로에 연결되면 해당 검증을 시작하지 말고 이 검증용 런처 설정만 제한적으로 고친다. 운영 제품 경로 체계 전면 변경은 별도 요청이다. 이후 변경 관찰은 해당 보호 파일 지문 등으로 남긴다. 과거 기준 지문이 없으면 소급 무변경을 단정하지 않는다.
환경 확인이 끝나면 같은 환경을 재사용한다. 임시 launch 항목의 원본/변경분/원복 대상을 기록하되 지금 임의로 종료·삭제·원복하지 않는다.
