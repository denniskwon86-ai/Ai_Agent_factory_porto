# 외부 공개자료 수집기 UI와 갱신 정책 보강 계획

- 작성: Codex / 2026-09-08 15:52 KST
- 사용자 요구: 외부 공개자료 수집기를 실제 사용자 화면까지 완성하고, 한 번 확보할 자료와 계속 갱신할 자료를 구분한다.
- 상태: 계획 반영. 이 문서 작성으로 코드·DB·원천 정책·스케줄·자동 적용 설정은 변경하지 않는다.
- 범위: 기존 대외 인텔리전스/수집기/업무 데이터 준비 화면을 연결한다. 새 수집 엔진이나 중복 정본 DB를 만들지 않는다.

## 1. 현재 구현과 남은 차이

- `AcquisitionPanel.tsx`가 `ExternalIntelligenceView.tsx` 하단에 연결돼 있다. 원천 카드·요청 폼·시험 수집·격리 적재 결과·정기 갱신 UI와 API 호출은 존재한다.
- `refresh_frequency`, `schedule_rule`, `next_run_at`, `last_success_at`, `auto_apply` 등은 이미 있다. 이를 버리고 새 스케줄러를 만들지 않는다.
- 현재 폼의 원천 코드 직접 입력과 목록의 내부 ID 표시는 사용자용 이름 선택/자동 매핑으로 보완해야 한다. 긴 화면 아래에 붙은 패널의 진입점도 정리한다.
- 자료별 갱신 성격·수정판 처리·최신성 표시를 기존 필드만으로 완성했다고 볼 수 없다. 주기가 같아도 새 기간 추가와 과거 값 정정은 다르다.
- 실제 원천 수집 및 인증→업무키트 준비도 연결, 인증된 브라우저 사용 검증은 미완이다. 기존 근거는 `DATA_ACQUISITION_ORCHESTRATOR_V0_1_2026-09-05.md` §7을 따른다.

## 2. 사용자가 구분할 두 축

### 기본 확보 방식

| 화면 표시 | 의미/예시 | 기본 처리 방향 |
|---|---|---|
| 1회 확보·보관 | 지정한 과거 기간의 자료 또는 특정 판의 보고서 원문 | 범위 확보 후 신규 기간 수집 중지. 원문·지문·출처 보관 |
| 정기 추가 | 새 날짜/월/분기의 관측값·공시가 계속 생기는 자료 | 원천 공표 주기와 사용 목적에 맞춰 미확보 구간 추가 |
| 변경 시 갱신 | 회사 개요·기준정보·개정 문서 등 내용이 바뀔 때 새 판이 필요한 자료 | 허용된 변경 알림이나 적정 간격 확인으로 변경분만 후보 생성 |

예시는 관리 방식 설명이며, 실제 공급자의 지원 기능·공표 일정·이용조건 확인 전 자동 실행을 켜지 않는다.

### 과거 자료 정정 확인 — 기본 확보 방식과 독립

- 별도 표시: 확인 필요 / 불필요함을 근거로 확인 / 아직 미확인.
- “1회 확보”는 “영구히 정확하거나 무제한 재사용 가능”이라는 뜻이 아니다. 과거 공시·통계도 정정될 수 있고 이용조건도 별도로 지킨다.
- 원천별 권장안을 제시하되 실제 정책은 데이터셋/수집 작업 단위로 확정한다. 같은 제공자도 지표별로 주기가 다르다.
- 과거 범위 확보와 신규 기간 추적을 한 요청 안에서 구분한다. 예: 과거 10개년 최초 확보 + 이후 새 공시 추가 + 정정 여부 재확인.
- 정정 확인 기간/주기는 원천 특성과 업무 목적에 맞게 설정한다. 최근 구간 재확인과 필요 시 과거 구간 점검을 조합하며 매번 전체 10년을 다시 받지 않는다.

## 3. 화면에서 보여 줄 정보

각 자료 카드에 이름과 함께 다음을 표시한다.

- 확보 방식, 과거 정정 확인 여부, 자동 수집 켜짐/꺼짐.
- 확보한 자료의 기간과 누락 구간, 최신 관측 기준일.
- 원천 공표일(알 수 없으면 미확인), 마지막 확인/성공 수집 시각, 다음 확인 예정.
- 원천에서 확보한 최신 판과 현재 업무에 적용한 판을 각각 표시.
- 확보 범위 충족 / 신규 자료 확인 예정 / 갱신 지연 / 정정 검토 중 / 수집 오류.
- 이용 가능 용도·재배포 조건 및 보존 제약. 1회 확보만으로 재사용 허가를 추정하지 않는다.

오래된 역사 자료라도 지정한 범위와 용도에 맞으면 단순히 오래됐다는 이유로 갱신 지연으로 표시하지 않는다. 원천 휴일·공표 간격을 고려하고, 확인 시각이 최신이라는 이유만으로 관측값도 최신이라고 표시하지 않는다.

## 4. 반영과 재현성 원칙

- 자동 수집과 자동 적용은 별도 설정이다. 기존 `refresh_runner.auto_apply_gate`의 원천·계약·품질·필드 구성 확인을 재사용한다.
- 자동 수집을 켜도 수집 후보가 생기는 것과 업무 데이터로 사용할 수 있는 것은 다르다. 현재 apply는 격리 적재이며 인증/준비도 미완을 유지한다.
- 동일 내용 재수집은 중복을 만들지 않고 확인 이력만 남긴다.
- 같은 관측 기간의 값이 달라지면 정정 후보로 표시하고 이전 값/새 값/원문 지문/수집 시각/정정 근거를 비교한다. 이전 판을 조용히 덮어쓰지 않는다.
- 공급자가 공표판 식별자를 주지 않으면 수집본의 원문 지문과 수집 시각으로 판 이력을 구분한다. 수집일을 공표일로 지어내지 않는다.
- 사용 중인 시나리오·보고서는 당시 선택한 판을 유지한다. 새 판 반영/재계산은 별도 행위로 하고 비교 결과를 보여 준다.
- 코드 확인 지점: 기존 관측 저장 함수는 같은 업무키·vintage에 UPDATE하며, 일부 Provider는 vintage_date에 관측일을 넣는다. “판 필드가 있다”만으로 정정 보존이 완성됐다고 하지 않고 신규 수집→인증 경로에서 이력 충돌 여부를 회귀로 확인한다. 이번 계획 작성에서는 수정하지 않는다.

## 5. 실행 순서와 완료 조건

1. 기존 대외 인텔리전스 안에 공개자료 수집 진입점을 명확히 하고 업무키트의 부족한 자료에서 바로 연결한다. 자연어 요청→원천/기간 추천→자료 미리보기→회사/업무키트 이름 선택→검토/연결 동선을 완성한다.
2. 현재 원천별 권장 주기와 작업 설정 위에 확보 방식/정정 확인/최신성 표시를 연결한다. 새로 만든 분류 라벨이 실제 스케줄 동작과 다르지 않아야 한다.
3. 실제 원천 소량 수집, 변경 없는 재수집, 신규 기간 추가, 같은 기간 값 정정, 누락/오류를 확인한다. 최초 수집부터 10년 전체를 반복 호출하지 않는다.
4. 외부 원천 사용 정책과 Snapshot 인증·업무키트 준비도를 연결한다. 공개 관측과 합성 상세의 성격을 보존하며 기준선의 혼합 제약을 우회하지 않는다.
5. 실제 브라우저에서 요청→추천→미리보기→검토→연결→다음 갱신 확인을 수행한다.

필수 회귀: 1회 확보 완료 후 불필요한 반복 수집 없음 / 중복 수집 시 행 증가 없음 / 신규 기간만 추가 / 과거 정정판 보존 / 갱신 실패 시 기존 적용본 유지와 오류 표시 / 기존 시나리오·보고서의 결과 지문 유지 / 자동 수집만 켠 경우 업무 적용되지 않음.

이 계획은 업무키트 K2 수량 대사와 병행할 UI·제품 연결 작업이다. 공개자료 수집기 5종의 추가 개발을 처음부터 다시 하는 일이 아니다. 구현 완료 판정과 추가 T3 실행, 자동갱신 활성화, 외부 원천 호출은 이 문서 작성에 포함되지 않는다.
