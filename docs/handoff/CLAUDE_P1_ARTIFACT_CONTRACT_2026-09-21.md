## 2. DEP-02 — 문서의 주장이 **사실이 아니었다**

`deploy/README.md` §4 는 「`update.sh` 가 `git archive` 로 추적된 파일만 내보낸다」고
적어 두었다. **`update.sh` 에 `git archive` 는 없다.** 운영 위치에서 `git fetch`·`git pull`
을 하고 빌드·재시작한다. 즉 **허용목록은 문서에만 있었다.** 문장을 고쳤다.

★ 그리고 고지문을 고친 것은 **차단기가 아니다.** 차단기는 §1 의 검사기이고,
**`update.sh` 는 아직 그것을 쓰지 않는다**(§6-③).

## 3. 검사가 넷인 이유 — 넷째가 **실제로 두 건을 잡았다**

```
선별  허용목록에 든 것만. 거부목록이 «이긴다».
내용  비밀로 보이는 것이 있으면 산출물을 만들지 않는다.
필수  있어야 할 자산이 없으면 «성공» 하지 않는다.          ← DEP-09
완결  ★ 앱이 import 하는데 목록에 없는 모듈이 있으면 실패.
```

**넷째가 없었다면 조용히 깨진 산출물이 나갔다.** 내 첫 초안에서:

| 빠졌던 것 | 규모 | 앞의 세 검사는 |
|---|---|---|
| `config.py` | 19곳에서 import | **전부 초록** |
| `nodes/` 패키지 | **22모듈** | **전부 초록** |

「필수 자산 목록」은 내가 «생각난 것» 만 담는다. 완결성 검사는 **코드에게 묻는다.**

⚠️ 완결성은 **앱을 import 하지 않는다** — import 는 DDL·seed 를 돌리고 자료를 바꾼다.
파일을 읽어 AST 로 해석한다. `__import__("nodes.vision_qa", …)`(`core/agent_graph.py` 가
실제로 쓴다)도 따라간다 — 이름이 다르다고 놓치면 패키지 하나가 통째로 빠진 채 초록이 된다.

## 4. 검사기가 **처음 돌자마자 잡은 것**

`core/connector_registry.py` 주석에 자격증명 모양의 DSN 예시가 통째로 적혀 있었다.

★ **예외 목록으로 덮지 않았다.** 예외가 한 줄 생기면 **그 파일 전체가 영원히 검사 밖**이
되고, 나중에 같은 파일에 들어온 진짜 키는 아무도 못 본다. 대신 그 «모양» 자체를 없앴다
(설명은 그대로). 실측해 보니 **검사기 자신도 예외가 필요 없었다** — 패턴의 소스는 그
패턴에 맞지 않는다. 그래서 **예외 목록이 아예 없다.**

## 5. 「업무자료 배제」와 「스타터 킷」이 부딪혔다

`starter_kits/` 에 **CSV 71 · XLSX 36** 이 있다. 형식 규칙으로 자르면 **스타터 킷이 조용히
반쪽**으로 나가고, 통째로 허용하면 그 규칙이 장식이 된다. 그래서 거부를 둘로 갈랐다.

```
DENY_ALWAYS     예외 «없음» — .env · DB · 로그 · data/ · raw/ · output/ · skills/_proposals/ …
DENY_FORMAT     업무자료 «형식» — csv · xlsx · zip · pdf …
ASSET_PREFIXES  형식 거부가 풀리는 «유일한» 자리 — starter_kits/ · process_packs/ · templates/
```

그리고 **예외로 나간 건수를 매 실행 결과에 숫자로 남긴다.** 예외가 조용하면 반드시 자란다.

```json
{"ok": true, "file_count": 702, "missing_required": [],
 "missing_imported_modules": [], "secret_findings": [],
 "business_format_exceptions": {"starter_kits/": 107}}
```

⚠️ 예외로 «나가는» CSV 는 내용 검사도 받게 했다 — **나가는데 안 보는 자리가 구멍**이다.
⚠️ **XLSX 36건은 내용 검사를 받지 못한다**(바이너리). 이 도구가 「봤다」고 말하지 않는다.

## 6. 극성 — 변이 6종이 **각각** 물린다 (원복 해시 전부 일치)

```
① 형식 거부의 자산 예외 제거        2 failed / 22 passed
② 항상-거부를 무시                  1 failed / 23 passed
③ __import__ 를 안 따라감           1 failed / 23 passed
④ 완결성 결과를 판정에서 뺌         1 failed / 23 passed
⑤ 내용 검사를 껌                    3 failed / 21 passed
⑥ 필수 자산 검사를 껌               5 failed / 19 passed
```

★ **내 시험이 내 도구의 실제 결함도 잡았다.** `def verify(root=ROOT)` 의 기본값은
파이썬이 **정의 시점에 한 번** 묶는다 — `ROOT` 를 바꿔도 따라오지 않는 「바꿀 수 있어
보이는데 안 바뀌는」 함정이었다. 호출 시점 해석으로 고쳤다.

## 9. ★ 결정이 필요합니다

1. **`scripts/**` 를 뺀 것 확인.** 실측상 `deploy/*.sh`·`afs.service` 어디도 `scripts/` 를
   부르지 않고(`ExecStart=… -m uvicorn main:app`) 제품도 import 하지 않는데, 그 안에는
   **운영 DB 에 자료를 심는 도구 8종과 이관 도구**가 있다. 운영 호스트가 들고 있을 이유가
   없다고 보고 뺐다. 운영에 필요한 도구가 있으면 **이름을 주시면** 그것만 다시 넣는다.
2. **`starter_kits/` 의 CSV 71·XLSX 36 을 내보내는 것 확인.** 제품 자산으로 보고
   형식 예외를 뒀는데, **그 내용물의 출처를 나는 확인할 수 없다.** 합성 자료가 맞는지
   판단이 필요하다. 아니라면 예외를 걷어낸다.
3. **`update.sh` 를 허용목록에 붙일지.** 붙이는 순간 배포 방식이 바뀐다(작업 디렉터리
   복사 → 선별 산출물). **P2 범위로 보는 게 맞다고 본다.**
4. 앞선 미결 4건(열 추가 규칙 · `julianday` 트리거 재작성 · 일반 `status` 승격 근거 ·
   PostgreSQL DSN)은 그대로 대기.
