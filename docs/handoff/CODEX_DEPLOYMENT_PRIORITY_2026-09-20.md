## 1. 목표와 즉시 바꾸는 순서

전체 제품40칸 또는 D01/D07 실사용 검증을 모두 채울 때까지 DB 준비를 미루지 않는다. 기존 WEB_DEMO_DEPLOYMENT_EXECUTION_PLAN_2026-08-21.md의 G7-DB 단계를 재사용한다. 별도 거대 설계서/평가 체계를 만들지 않는다.

CODEX_D01_REVIEW_NEXT_2026-09-20.md의 보안·데이터 보호 조건은 유지하되 일반 라벨 개선·구 화면 다듬기·광범위한 UI 수용 확대는 DB/배포 준비보다 후순위로 옮긴다. 현재 필수 수정이 완료됐으면 다시 하지 않는다.

### 배포 전 필수

- 릴리스 단건의 가시성·고아 자료 차단, 상태 판정 장애에서 실행 본문 비공개.
- candidate가 재개만으로 운영용 active가 되는 경로의 안전 판정/보완. 미해결이면 전체 기능을 안전하다고 배포 승인하지 않는다. 해당 동선 제한 배포는 사용자와 명시 합의가 필요하다.
- 사용자에게 실제 데이터 손실/중복 실행을 만드는 재현 결함, 인증·조직 격리·비밀값 노출.
- 배포 대상 DB/파일의 일관된 백업·이관 대사·복구 실증, 재기동 후 보존, 로그인·핵심 흐름·SSE의 서버 수용.

### 지금 뒤로 미룰 것

- 일반 문구/색상/정렬·전체 화면 라벨 통일, 구 화면 기능 추가, 이미 통과한 합성 흐름 반복 검증.
- 실제 사용자/자료가 없어 못 닫는 영역을 합성으로 반복해 채우려는 작업.
- 전체 pytest/변이 캠페인을 매 작은 변경마다 반복하는 것. 위험 관련 집중 검사 후 배포 후보 기준선에서 필요한 회귀를 묶는다.

## 2. Claude 다음 실행 묶음

1. **5분 상태 확인**: 최근 인계 이후 권한 보완 완료 여부 확인. 완료면 증거만 인용하고 반복하지 않는다. 미완료면 기존 첫20~30분 보안 묶음을 마감하고 상태 전이 잔여를 명시한다.
2. **다음30~45분 DB-0/DB-1 착수**: 기존 docs/architecture/SQLITE_INVENTORY.md와 scripts/sqlite_inventory.py를 먼저 재사용해 현재 저장소 대비 차이를 확인한다. 운영 앱 import/기동으로 초기화하지 않는다. 필요 DB 열람은 읽기 전용; 이관/실험은 일관된 사본에서만 한다.
3. 산출물은 한 장: 업무 정본 DB·담당 모듈·주요 쓰기/트랜잭션·연결 파일/릴리스 의존성·캐시/벡터 분리·현재 직접 sqlite 의존·첫 이관 묶음과 차단 조건. DB 개수만 세고 끝내지 않는다.
4. 이 지도로 **실제 사용자 흐름 하나를 지원하는 첫 저장소 묶음**을 선정한다. 빈 DB 설치→사본 이식→동일 입력 대사→읽기/쓰기/권한/감사→복구를 순서대로 구현한다. 쉬운 캐시/체크포인터만 옮겨 업무 DB 이관 완료라고 하지 않는다. 첫 묶음 구현 예상 시간은 의존성을 확인한 뒤 제시한다.
5. 서버 준비 체크리스트는 같은 보고 안에 붙인다: 목표 호스트/OS·DB 위치·도메인/TLS·영속 파일 경로·백업 외부 보관·비밀 주입·SSE 프록시·단일 worker 제한·헬스체크. 제품 설치/서버 조작은 대상 확정 전 실행하지 않는다.

Claude 단일 작업 세션이면 위 순서를 따른다. 다른 작업자가 실제 배정되지 않았는데 병렬 수행 중이라고 쓰지 않는다. DB-0/1은 모든 UI 수용 완료를 기다릴 이유가 없지만 DB-3 이후 사본 이관은 핵심 스키마/배포 기준선을 먼저 고정한다.

## 3. 이관·배포 완료의 경계

기존 G7-DB: DB-0분류 → DB-1접근계층 → DB-2스키마 → DB-3이관 → DB-4동등성 → DB-5전환/복구 → DB-6운영안전 → DB-7보존후폐기.

- 첫 전환에 앱 이중 쓰기를 도입하지 않는다. 승인된 쓰기 동결/최종 증분/전환 절차 사용.
- PK/FK·행수·내용 지문과 권한/감사/트랜잭션 결과 대사. 파일 저장소와 DB의 결속도 포함한다. 단순 행수 일치를 성공으로 삼지 않는다.
- 전환 후 새 쓰기가 발생한 상태에서 DSN만 SQLite로 되돌리면 유실될 수 있다. 되돌림 가능 시점·새 쓰기 보존/재대사·복구 조건을 리허설에 포함한다.
- PostgreSQL을 붙여도 SSE/작업 상태의 메모리 의존이 사라지는 것은 아니다. 근거 없이 다중 worker를 켜지 않는다.
- scripts/data_migration.py는 현행 내용상 JSON/자료를 SQLite·Chroma에 넣는 도구다. **SQLite→PostgreSQL 이관 도구가 아니므로 이름만 보고 실행하지 않는다.**
- 백업/복구 시험은 사본 환경. 운영 원본/사용자 로그/키를 Git·공개 서버로 무심코 싣지 않는다. 커밋·푸시 및 서버 전환은 별도 범위 확인.
