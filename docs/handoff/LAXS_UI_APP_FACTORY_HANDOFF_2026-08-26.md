## 1. 이번 인계의 목적

경영 홈을 확정한 뒤 상단 메뉴를 제품 기능 기준으로 정리하고, 다음 화면인 `앱 제작`을
실제 브라우저에서 점검했다. 이 문서는 다음 작업자가 화면을 다시 원상 복귀시키거나,
현재 남은 결속 문제를 단순 문구 문제로 오인하지 않도록 다음을 한곳에 고정한다.

1. 지금까지 확정한 제품 명칭·로고·공통 셸
2. 경영 홈과 회사별 업무 연결구성의 현재 상태
3. 앱 제작 목록과 새 업무 생성 창에 적용한 선행 보정
4. 브라우저에서 재현한 실제 결함과 아직 닫히지 않은 항목
5. 다음 작업 순서와 완료 조건

## 2. 제품 명칭·브랜드 정본

- 제품명: `LAXS`
- LS MnM 적용본: `LAXS-M`

- 명칭 의미: `AX embedded in LS`
- 지향점: `AX at the core of LS`
- AI 비서 표시명: `자비스`

현재 확정 자산:

frontend/public/brand/laxs-logo-primary-on-white-v3.png
frontend/public/brand/laxs-mark-64.png

사용 위치:

- 어두운 배경형: 제품 상단 셸·시스템 안내
- 밝은 배경형: 로그인·시스템 안내
- 별도 마크: 브라우저 파비콘

로고를 새 시안으로 교체하려면 파일 이름뿐 아니라
`tests/test_laxs_brand_about_ui.py`의 SHA-256 고정값을 함께 검토해야 한다. 시각 검토 없이
파일만 덮어쓰는 것을 막기 위한 계약이다.

## 3. 상단 메뉴 확정안

화면 상단의 주요 기능은 다음 일곱 개다.

```text
경영 홈 · 앱 제작 · 앱 운영 · 시뮬레이션 · 결정·보고 · 지식 · 에이전트
```

중요한 배선:

- `결정·보고`는 협업 받은함이 아니라 의사결정 목록에서 시작한다.
- `앱 제작`은 공통 `ProductShell`을 사용한다. 별도 Software Factory 머리 바를 다시 만들지 않는다.
- 화면당 주요 생성 행동은 상단의 `＋ 새 업무` 한 개다.
- 전체 메뉴에는 핵심 여정 다섯 단계가 순서대로 유지된다.

```text
1 업무 데이터 준비
2 계산 실행 승인
3 경로 계산
4 의사결정 안건
5 경영 브리핑
```

## 4. 경영 홈·회사 구성 현재 상태

완료된 범위:

- LAXS 공통 상단 셸과 첫 화면 시안 정렬
- 회사별 Digital Thread 업무 단계 편집
- 단계별 DATA·SW·TWIN 보조정보 카드 편집
- 보조정보가 없는 단계도 빈 구역을 유지
- 현재 적용 중인 연결구성과 편집 초안을 한 화면에서 확인
- 회사 이름·법인·가상회사·업무 연결구성 관리 화면
- 시스템 명칭·로고·운영 원칙 안내 페이지

### 4.1 현재 실행 문맥 결속 불일치

2026-08-26 실제 브라우저에서 다음을 확인했다.

```text
회사 정본에 등록된 표시명: LS MnM
회사 정본 tenant_id: tenant-afs-demo-materials
현재 인증 세션 tenant_id: tenant_default
현재 선택 범위: node_hq
```

따라서 `LS MnM`을 `tenant_default`에 화면에서 임의 대입하면 안 된다. 그것은 표시 수정이
아니라 다른 테넌트를 같은 회사라고 주장하는 것이다. 현재 화면은 내부 코드를 회사명처럼
노출하지 않고 다음과 같이 표시한다.

```text
회사 연결 필요 · 조직 연결 필요
```

실제 해결은 회사 정본·인증 세션·조직 노드의 식별자를 같은 설치 문맥으로 결속하는 것이다.
결속이 완료되면 `useOperatingContext()`가 저장된 회사·조직 이름을 자동 표시한다.

## 5. 앱 제작 목록 — 2026-08-26 선행 보정

브라우저 실측 전 상태:

- 화면 전용 어두운 헤더와 공통 셸이 혼재
- `Mega`, `Releases`, `Archive` 등 영문·기술 용어 혼재
- `tenant_default`, `node_hq`가 회사·조직 이름처럼 본문에 노출
- 문맥 밖 63건 안내가 화면 상단을 과도하게 차지
- 빈 상태와 주요 행동의 위계가 약함

적용한 변경:

- 경영 홈과 같은 `ProductShell` 적용
- 화면 제목을 `앱 제작`으로 통일
- 필터를 `미완료 · 내 프로젝트 · 통합 프로젝트 · 릴리스 · 보관함`으로 정리
- 제외 사유 상세를 접힌 영역으로 이동
- 본문의 중복 `새 업무 만들기` 버튼 제거
- 빈 상태가 상단 `＋ 새 업무`를 안내하도록 변경
- 회사·조직 내부 식별자 대신 결속 상태 또는 정본 이름 표시
- 검색 문구를 `이름 또는 ID로 찾기`로 정리

브라우저 실측 결과:

```text
보이는 미완료 프로젝트 0
보이는 내 프로젝트 0
보이는 통합 프로젝트 0
보이는 릴리스 5
문맥 밖 제외 63
```

이 숫자는 프로젝트가 0건이라는 뜻이 아니라 현재 실행 문맥과 결속되지 않아 목록에서
제외됐다는 뜻이다. 회사·조직 결속이 다음 P0인 이유다.

## 6. 새 업무 생성 창 — 적용 내용과 발견 결함

적용한 용어:

| 변경 전 | 변경 후 |
|---|---|
| Project ID | 업무 식별자 |
| 메가 프로젝트 | 통합 프로젝트 |
| 워크플로우 템플릿 | 업무 진행 절차 |
| 에이전트 순서 | 역할과 확인 순서 |
| 외부 실측값(MCP) 병기 | 외부 연계 실측값 함께 보기 |
| 기준정보 도메인 | 연결할 기준정보 분야 |
| 골든 레코드 주입 | 승인된 기준정보의 일관된 반영 |

### 6.1 실제 기능 결함 — 보이는 선택과 제출값 불일치

템플릿 목록은 비동기로 도착한다. 창이 먼저 열리면 내부 상태는 `default`였지만, HTML
`select`는 첫 번째 옵션 `소프트웨어 개발 팩토리`를 선택한 것처럼 보였다. 사용자가 그대로
만들면 화면에서 본 절차와 서버에 제출하는 값이 달라질 수 있었다.

조치:

- 목록이 도착했을 때 현재 값이 정본 목록에 없으면 첫 템플릿 ID로 상태를 동기화
- `지금 정해진 것` 요약도 내부 ID가 아니라 선택한 실제 절차 이름을 사용

### 6.2 하단 실행 버튼

1280×720에 가까운 화면에서 `이 조건으로 만들기`가 첫 화면 아래로 밀렸다. 생성 창의
하단 행동 영역을 고정하여 스크롤 중에도 `취소`와 생성 버튼이 보이도록 했다.

## 7. 업무키트 적용 현황

제품 구조는 다음 세 층으로 구분한다.

1. Starter Package: 샘플 기업·합성 데이터·앱·보고서 묶음
2. Business Kit: 구매·물류·재고·생산·원가 등 업무기능 묶음
3. App Blueprint/Release: 실제 실행 앱과 릴리스

현재 완료:

- 비철금속 Starter Package 35개 데이터 계약을 `FOUNDATION + BK-01~08`로 분류
- Data Prep에서 샘플 패키지와 조직 적용본을 구분
- 35행 원천 표보다 업무기능별 준비도 요약을 먼저 표시
- APP-01·03·04 기본 화면을 원본 데이터 표가 아닌 업무 화면으로 전환
- 내부 Snapshot/Binding ID를 일반 앱 화면에서 비노출

현재 앱 제작 생성 창의 잔여:

- `새 업무 만들기`에는 업무 진행 절차·지식팩·기준정보만 있고 **업무키트 선택·적용 단계가 없다.**
- 따라서 업무키트로부터 앱을 만드는 제품 경로가 앱 제작 화면에서 명시적으로 보이지 않는다.
- 다음 단계에서 `적용된 패키지/업무키트 기반으로 시작`과 `일반 앱 제작`의 관계를 설계해야 한다.
- 임의 키트 ID 입력창을 추가하지 않는다. 사용자가 볼 수 있는 조직 적용본과 승인된 앱 계약만
  선택지로 제공한다.

## 8. 릴리스 화면 실측과 잔여

현재 릴리스 5건은 보이지만 카드가 다음 값을 그대로 사용한다.

```text
kitapp_ki_…_APP-04
test_a1_…
2026-08-24T05:53:49+00:00
```

잔여 보정:

- 사람용 앱 이름·업무기능·상태를 첫 줄에 표시
- 내부 릴리스 ID는 보조정보 또는 관리자 진단으로 이동
- UTC 원문을 사용자 현지시각으로 표시
- `열기`와 `관리`의 차이를 카드에서 설명
- 운영 중·후보·중단 예고·중단 상태를 카드에서 먼저 확인

릴리스 관리 화면도 사용자 이메일·UTC 원문·release_id를 기본 본문에 노출한다. 감사 이력
원문을 삭제하지 말고, 사람 이름·현지시각·짧은 표시 ID를 우선하며 원문은 상세에서 유지한다.

## 9. 검증

이번 앱 제작 선행 보정:

```text
frontend npm run build              PASS
실제 브라우저 목록 화면             PASS
실제 브라우저 생성 창               PASS
생성 버튼 최초 화면 노출             PASS
선택 절차 요약과 select 표시 일치    PASS
내부 tenant/scope 코드 기본 노출      0건(결속 필요 상태로 대체)
```

커밋 직전 재검증(2026-08-26):

```text
frontend npm run build                                      PASS
브랜드·경영 홈·회사 정본·업무키트·키트 앱 집중 회귀          PASS (exit 0)
스타터 패키지·단일 사전검증 데이터 경계 집중 회귀             PASS (8 tests)
```

주의:

- 전체 Python T3 회귀가 아니라 이번 재현 묶음의 집중 회귀다.
- 전체 T3는 다른 작업자의 미커밋 백엔드 변경과 합쳐진 현재 작업트리를 기준으로 따로 수행해야 한다.
- 작업트리에는 Claude Code의 다른 백엔드 변경과 문서 개편이 함께 있으므로, 본 커밋은
  이 문서에 명시한 UI·브랜드·회사 구성·업무키트 화면의 재현 가능한 의존 묶음만 선별한다.

## 10. 다음 실행 순서

### P0-1 회사·조직 결속

완료 조건:

- 인증 세션 회사, 회사 이름 정본, ECM 법인, 조직 노드가 같은 tenant 축을 사용
- 상단과 모든 대화상자에 `LS MnM`과 실제 조직명이 표시
- `회사 연결 필요`, `조직 연결 필요`가 사라짐
- 다른 tenant를 이름만 같게 표시하는 우회 없음

### P0-2 앱 제작에 업무키트 진입 연결

완료 조건:

- 사용자가 접근 가능한 조직 적용본을 목록에서 선택
- 해당 적용본의 업무기능·앱 Blueprint·데이터 준비 상태를 함께 확인
- 승인된 계약이 없는 앱은 생성/운영으로 넘어가지 않음
- 업무키트 미선택 일반 앱 제작과의 차이를 화면이 설명

### P0-3 릴리스 카드 정리

완료 조건:

- 사람용 이름·업무기능·운영 상태·현지시각 우선
- 내부 ID와 감사 원문은 상세에서 유지
- 후보와 운영을 같은 `완성됨`으로 표시하지 않음

### P0-4 실제 프로젝트 통제 화면

회사 결속을 닫아 프로젝트가 보인 뒤 수행한다.

- 한 프로젝트 열기
- 현재 단계·다음 행동·사람 승인·생성 산출물 확인
- 긴 내용·오류·빈 상태·하단 행동 잘림 점검
- 새로고침 후 같은 화면으로 복귀하는 URL 상태 계약 점검

## 12. 금지사항

- `tenant_default`에 `LS MnM` 이름을 화면에서 하드코딩하지 않는다.
- 업무키트와 Starter Package와 앱 Blueprint를 한 목록으로 섞지 않는다.
- 내부 ID를 사람용 제목으로 사용하지 않는다.
- 후보 릴리스와 운영 릴리스를 같은 상태로 표시하지 않는다.
- 업무키트 선택을 사용자의 ID 직접 입력으로 대체하지 않는다.
- 다른 작업자의 미커밋 백엔드·문서·데이터 파일을 본 UI 커밋에 섞지 않는다.
- `origin/dev`는 보존 기준선이므로 강제 갱신하지 않는다. 현재 통합 브랜치에만 푸시한다.
