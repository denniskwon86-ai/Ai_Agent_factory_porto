- 프런트184PASS/contracts157/tsc/build는 Claude 보고값이며 Codex 재실행값이 아니다.

## 2. 화면 표식이 보이지 않는 원인 — 새 UI가 아니라 스키마/관측 지점

확인한 실제 경로:

frontend/src/store/useFactoryStore.ts의 logs
→ frontend/src/factory/factoryViewModel.ts toEvents(451행 부근)
→ vm.events
→ frontend/src/factory/ContextInspector.tsx '최근 실행 기록'(148행 부근).

toEvents의 표시 문자열은 event/message/text/status에서만 나온다. tests/b6_sse_probe.py는 marker/note만 보내므로 고유 표식이 표시 문자열에 포함되지 않는다. 구 TimelinePanel도 세 가지 업무 이벤트만 표시해 B6_SCOPE_PROBE를 찾는 대상이 아니다.
이는 '로그를 그리는 자리가 없다'의 증거가 아니다. 임의 표식 노출을 위해 제품 mapper/화면을 바꾸거나 새 로그 UI를 만들지 않는다.

다음 첫10~15분:

1. 하네스가 기존 검증된 marker로부터 고정 접두어의 message를 생성하도록 최소 수정한다. 예: '[SYNTHETIC B6] ' + marker. client의 임의 message/이벤트 타입을 통과시키지 않는다. 고정 B6_SCOPE_PROBE, project allowlist, 비global, 로컬 제한 유지.
2. 격리 서버가 최신 하네스를 사용하는지 확인한 뒤 실제 A 프로젝트 Studio의 기존 Inspector를 열고 '최근 실행 기록'에서 고유 message를 찾는다. 전달/실제 store/mapper/DOM 증거를 구분해 남긴다.
3. B 문맥 비가시 프로젝트 표식은 수신/표시되지 않아야 한다. A 양성 대조 없이 음성0건만으로 성공이라고 하지 않는다. NODE_COMPLETED로 바꾸거나 감독/LLM 경로를 실행하지 않는다.
4. 화면까지 이어지면 합성 생산자 기반 SSE 전달·필터·소비·표시 묶음을 마감한다. 업무 이벤트 생산자 parity는 별도 잔여다. 전체 변이/서버 회귀 반복 금지.

## 3. 거절 화면의 복귀 동선 — 10~15분 예상

대상 주소를 유지한 채 현재 문맥에서 못 여는 것은 정상이다. 같은 Gate/거절 헤더에도 기존 OperatingContextChip과 openContextSwitcher 경로를 재사용한다. 홈으로 강제 나갔다 재진입하지 않고 권한 있는 범위로 되돌아올 수 있어야 한다.
새 전환 창/권한 우회/자동 재시도 루프를 만들지 않는다. A 열림→B404→같은 거절 화면에서A 선택→서버 재확인200 및 옛 거절 제거를 확인한다. 키보드 접근과 제목/오류 노출 범위는 유지한다.

## 4. contexts/select 권한 — 결정 제안, 이번 구현에서는 보류

확인한 사실: core/route_authority.py는 해당POST에 ADMIN_ORGANIZATION을 요구한다. api/routes/enterprise_context_control.py select_context는 서버 상태를 저장하지 않고 resolve_scope_ref/can_read_node/부서 읽기 권한으로 선택을 검증한다.
제품 권고: 기준정보 수정 권한과 개인의 조회 문맥 선택은 분리하는 것이 맞다. viewer/member도 자신에게 허용된 범위를 고를 수 있게 하는 방향을 권고한다.
그러나 이는 현재 서버 권한 계약 변경이다. 사용자 별도 승인 전 표/EXEMPT/_ROLE_CAPS/상태코드를 고치지 않는다. 시험을 위해 일반 계정에 관리자 권한을 추가해 문제를 숨기지도 않는다.
승인 시 별도 좁은 설계/교차검토: 자기 범위 허용, 남의 범위·tenant/mode 불일치·없거나 해석불가 scope 거절, 조직 편집·승인 권한 불변, 실제 세션/격리 시험. 단순 표 항목 삭제만으로 구현하지 않는다. 현재 관리자 배정 fixture의 검증 범위는 명시적으로 유지한다.

## 5. 계측 오류와 fixture 재현성

- SSE 티켓 요청의 범위는 본문 scope_node_id에 넣는 실제 제품 계약을 하네스의 한 함수로 고정한다. 음성 시험 시작 전에 계정/선택범위/소유권과 양성 대조를 확인한다. 티켓/세션 값은 출력하지 않는다.
- 전환 창 관측은 고유 제목·접근성 이름과 가시성으로 고정한다. body 앞600자/첫 dialog로 판단하지 않는다. 동일 계측을 매번 수작업으로 재조립하지 않는다.
- 노드/부서 양방향 결속과 격리 instance.json 재기동 보존을 기존 환경 절차에 추가한다. fixture 재생성·재기동 후 같은 거절/허용 대조군을 재현 가능하게 남긴다. 운영 instance.json은 수정하지 않는다.
- 원복 대상은 기록 유지. 현재 요청은 철수/삭제 승인이 아니다.
