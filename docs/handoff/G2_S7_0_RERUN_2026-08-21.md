# §7-0 종단 **재실행** — 종이가 아니라 실제 코드로

작성: Claude Code (백엔드) · 2026-08-21
**상태: 실측 완료.** 운영 DB 에 쓰지 않았다(온톨로지는 임시 폴더, 색인은 격리된 승격 폴더).
전제: [§7-0 종이 시뮬레이션](G2_S7_0_END_TO_END_SIMULATION_2026-08-20.md) · [A rev.2](G2_A_PATH_CALCULATION_CONTRACT_2026-08-21.md)

> **한 줄로** — 경로는 **닫혔다.** 정본 데이터·실제 Resolver·실제 색인·실제 승인으로
> 5노드 4간선이 이어졌고, 근거 없는 칸이 0 이며 재실행 지문이 같다.
> 계산은 여전히 막혀 있고 — **막혀 있다는 사실이 실제로 그렇게 보인다.**

---

## 1. 무엇을 실제로 돌렸나

```
정본 다섯 종(승격 완료, 1,660건 색인)
  → 관계 4종 제안·제출·승인 (실제 원장 결속)
  → find_paths (실제 Resolver · 실제 범위 색인)
  → to_evidence (B1.1 봉투 계약)
```

종이 위에서는 「이럴 것이다」였던 것을 **코드가 그렇게 하는지** 봤다.

---

## 2. 결과

### 2.1 경로가 닫혔다

```
PO-000001-10 ─FULFILLED_BY_SHIPMENT→ SHP-000001
             ─AFFECTS→ STK-20260228-BP-GOLD-LOC-P1-RAW
             ─AFFECTS→ MPS-0000001
             ─AFFECTS→ SO-000001-10

노드 5 · 간선 4 · query_id oq_cf9bd53df25e… · 지문 ad2908fb314455fe
```

### 2.2 다섯 칸 모두 실제 인증판에 묶였다

| 칸 | 계약키 | 인증판 |
|---|---|---|
| 구매주문 라인 | `PRC-02` | `ds_2eceb2a4d4f647` |
| 선적 | `LOG-02` | `ds_c606967eabed42` |
| 재고 스냅샷 | `INV-01` | `ds_d13d557cf24648` |
| 생산계획 라인 | `MFG-01` | `ds_e2112ebb295f48` |
| 판매 라인 | `SLS-01` | `ds_b9de051c55bd4e` |

**근거 없는 칸 0.** 사람이 읽는 이름이 붙어 나온다.

### 2.3 시간과 재실행

```
재실행    query_id 동일 · path_fingerprint 동일
과거 as_of  NO_VISIBLE_PATH — **오늘의 답을 주지 않는다**
```

### 2.4 계산은 막혀 있고, 막힌 것처럼 보인다

```
complete = False
calculation_blocked = True
대외 사유 = "이 경로는 아직 계산할 수 없습니다."
```

⚠️ 대외 문구에 구간 수도, 참조 이름도 없다. 수치를 0 으로 채우지도 않는다.

## 3. ⚠️⚠️ 실행하면서 제품이 나를 **두 번 막았다**

둘 다 **옳은 거부**였고, 종이 위에서는 보이지 않던 것이다.

### 3.1 관계 유효 시작이 인증보다 이르면 제안이 막힌다

첫 실행에서 `effective_from = 2026-01-01` 로 관계를 제안했더니:

```
OntologyIntegrityError: endpoint dataset:purchase-order-line:PO-000001-10 is
required by RELATION_PROPOSAL but resolved as UNBOUND:
그 시점에는 아직 인증되지 않았습니다(as_of=2026-01-01T00:00:00Z).
```

★ **맞다.** 그 시점에는 그 자료가 인증되지 않았으므로, 그때부터 유효한 관계를 세울 수
없다. 「데이터는 2월 것인데 인증은 8월에 했다」는 사실이 그대로 드러난 것이다.

⚠️ 시연 대본을 쓸 때 **관계 유효 시작을 인증 시각 이후로** 잡아야 한다.

### 3.2 최소 경로가 **두 조직 노드**에 걸쳐 있다

```
PO-000001-10  plant-afs-smelting-01
SHP-000001    plant-afs-battery-02
```

단일 공장 문맥으로 물으면 PDP 가 다른 공장 것을 막는다 — **옳다.**

그런데 상위 조직(`org-afs-demo-group`)을 골라도 막혔다. 원인을 갈라 보니:

★ PDP 는 **조상 해석을 지원한다**(`app_policy._scope_covers` → `_scope_is_ancestor`).
✗ 그런데 **키트의 조직도(`FND-01`)가 ECM(`enterprise_context.db`)에 없다.**

즉 설계 결함이 아니라 **배선 공백**이다. 조직도를 ECM 에 올리면 상위 조직 문맥에서
경로 전체가 보인다.

⚠️⚠️ 이번 측정은 「전체」 문맥(`scope_node_id=""`)으로 돌렸다. **우회이지 조직 격리를
확인한 것이 아니다** — 그 확인은 조직도를 올린 뒤에 해야 한다.
