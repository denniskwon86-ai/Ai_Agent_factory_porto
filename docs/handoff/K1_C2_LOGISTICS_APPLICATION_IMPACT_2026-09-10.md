## 4. 앱·계산·기존 안건 영향

- 등록 앱 계약 7개 중 **4개**가 물류 5종 중 하나 이상을 직접 참조한다. 이는 코드 수정 필요 앱 수가 아니라 **데이터 변경 후 확인할 소비 앱 모수**다.
- 계산 승인 행 3개 중 도착지연 1개가 교체 대상 LOG-02·03 판을 직접 봉인한다. 자재부족/매출시기 2개는 이번 5종과 직접 겹치지 않는다. 후속 재고·생산·판매 판을 바꾸면 다시 평가해야 한다.
- 세 승인 행의 valid_until은 2026-09-23이다. ACTIVE 저장값만 확인했으며 원장 철회·권한을 재검증한 것은 아니다.
- `calc_execution_approval.binding_fingerprint()`는 snapshots를 포함하고, 제품 실행은 그 지문으로 승인을 조회한다. 새 판을 넣고 옛 승인 문자열만 복사하면 안 된다. **새 판의 계산 승인 검토가 필요하다.**
- 활성 기준선 1개는 판매 2행과 생산계획 2행의 배분 및 10월 인식일을 봉인한다. 기준선 이름만 유지하고 내용을 덮지 않는다.

보조 읽기 검사(검토 도구의 주 보고서와 별도):

- 해당 tenant의 decision_cases **15건 중 3건**의 package/evidence JSON 값에 기존 PRC-02·LOG-02·03 판 ID가 직접 있다.
  - `dec_a040b013ca00` DECIDED

- 해당 tenant의 ECM scenario_results는 0, publication_versions 조인 결과도 0이다. 다른 tenant·다른 계산 저장 경로에 결과가 없다는 뜻은 아니다.

## 5. 적용·복구 단위: 지금 바로 교체하면 안 됨

제품 `certify_demo_replacement()` → `replace_demo_snapshot()`는 **옛 판 철회+새 판 인증+색인 적재를 한 쌍 단위로 원자 처리**한다. 5종 전체가 한 번에 바뀌는 계약은 아니다.

옛 판은 REVOKED로 남고 원본 파일도 보존되지만, REVOKED는 종료 상태여서 다시 DEMO_CERTIFIED로 되돌리는 경로가 없다. “원본이 남는다”와 “옛 계산을 그대로 재실행할 수 있다”는 다르다.

적용 전 필요한 묶음:

1. 물류 5종 + 계약/공급사 보정 + 공장별 소유권을 하나의 **검토 명세**로 고정한다.
2. 현행 35개 판·RAW 지문, 기준선, 실행 승인, 직접 참조 안건 3개와 간접 참조를 적용 manifest에 담는다. 마지막 조회 뒤 변경이 있으면 적용하지 않는다.
3. 재고·생산·판매 정합성 및 한 업무 시나리오의 계산 결과까지 사본에서 먼저 확인한다.
4. 실제 전환 시 5종 중간 상태를 사용자/계산기가 보지 않는 방식을 확정한다. 기존 단건 교체 반복을 “일괄 원자 적용”으로 부르지 않는다.
5. 실패가 커밋 전이면 해당 트랜잭션을 취소한다. 이미 확정했다면 옛 RAW로 **새 복구 후보 판**을 만들고 인증·승인을 다시 거치는 방식 또는 쓰기 동결된 전체 일관 백업 복구 방식을 사전에 검증해야 한다.
6. 공유 운영 폴더의 DB 하나만 과거 사본으로 덮어 원장·기준선·안건을 서로 다른 시점으로 만들지 않는다. 이번에는 복구 기능이나 대규모 트랜잭션을 새로 구현하지 않았다.

## 6. 검증·불변성·한계

- 신규 7건 + 기존 물류 후보 10건 = **17 passed / 12.43초**.
- read-only 연결은 `mode=ro`, `query_only=ON`, `BEGIN`으로 열며 없는 DB 생성과 INSERT를 거부하는 시험이 통과했다.
- 계약 경계일, 제출 전 빈 날짜, 같은 총량이라도 tenant/날짜/단위가 다른 입고, 공장별 소유권 집계 회귀를 포함한다.
- 설치판 RAW 35개 체크섬·행수 일치. 분석 후 RAW 지문 변경 0.
- 최초 분석에서는 data_preparation.db 및 WAL, enterprise_context.db 및 WAL **명시한 4개 경로**의 SHA256/존재 상태가 동일했다. **최종 분석에서는 enterprise_context.db-wal이 없음 → 0바이트 파일로 바뀌었다.** 따라서 최종 보고의 selected_db_files_unchanged는 false다. 본 DB 2개와 data_preparation WAL은 동일하다.
- SQLite WAL 모드의 읽기 전용 연결도 WAL/SHM 보조 파일을 만들 수 있다. 공유 프로세스 활동도 있으므로 **원인을 다른 세션으로 귀속하지 않는다.** SQL 쓰기를 실행하지 않은 것과 파일 시스템 전체가 불변인 것은 구별한다. 빈 WAL을 임의 삭제하지 않았다. SHM·모든 운영 저장소의 불변식은 검사하지 않았으며, 실제 적용 전에는 쓰기 동결·일관 사본 단계가 필요하다.
- 후보/원천 파일·계약 지문을 검토 시 다시 대조했다. CSV나 DB를 재생성하지 않았다.
- DB별 읽기 트랜잭션이며 DB들 전체의 동시점 스냅샷은 아니다. 실행 직전 전체 적용 manifest의 재확인이 필요하다.
- T3·브라우저·설치·사용자 권한 실측·원장 승인 재검증은 미실행. 다른 세션의 T3 기록을 이번 검토 도구의 T3로 인용하지 않는다.

```powershell
venv/Scripts/python.exe -m pytest tests/test_kit_logistics_impact_review.py tests/test_kit_logistics_revision.py -v -x -p no:warnings
```
