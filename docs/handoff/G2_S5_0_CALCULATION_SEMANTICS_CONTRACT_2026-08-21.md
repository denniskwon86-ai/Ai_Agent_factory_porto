# §7 5-0 — 계산 **의미 계약** (설계 · 실행 없음)

작성: Claude Code (백엔드) · 2026-08-21
**상태: 의미 확정만. 계산은 하나도 실행되지 않는다.**

> **한 줄로** — 기존 계산 엔진과 온톨로지 계약은 「재고」라는 **같은 말로 다른 것**을
> 가리키고 있었다. 이름만 이으면 **부호의 뜻이 반대인 숫자**가 나온다.

---

## 0. ⚠️ 먼저 정정 — 계산 참조는 셋이 아니라 **넷**이다

§7-0 에서 셋만 적었다. 최소 경로 4관계에서 보이는 것만 셌기 때문이다. 계약을 다시
파싱하니 `g4_contract.required_calculation_refs` 에 넷이 있다.

| 참조 | 관계 | MVP |
|---|---|:---:|
| `CALC.LOGISTICS.ARRIVAL_DELAY.v1` | `shipment` → `inventory-snapshot` | ● |
| `CALC.INVENTORY.MATERIAL_SHORTAGE.v1` | `inventory-snapshot` → `production-plan-line` | ● |
| `CALC.PRODUCTION.REVENUE_TIMING.v1` | `production-plan-line` → `sales-line` | ● |
| `CALC.FINANCE.COST_MARGIN_CASH.v1` | `cost-record` → `ledger-line` | **✗ 범위 밖** |

★ 넷째는 §2.3 에서 「위 사슬과 떨어져 있다」는 이유로 MVP 에서 제외한 관계에 붙어 있다.
**빠뜨린 것이 아니라 범위 밖**이라는 사실을 코드와 시험에 남긴다 — 안 적으면 다음
사람이 「원래 안 보던 건가」와 「보다가 놓친 건가」를 구별하지 못한다.

---

## 1. ⚠️⚠️ 같은 「재고」가 서로 다른 것을 가리킨다

### 1.1 기존 엔진이 계산하는 것

`core/calc_graph.py`:

```
lost_ratio = min(max(지연일, 0) / 기간일, 1)
qty        = qty0 * (1 - lost_ratio)          생산량 ↓
inventory  = inv0 + (qty0 - qty)              기말재고 ↑   ← 안 쓴 원료가 쌓인다
```

**지연 ↑ → 생산 ↓ → 재고 ↑**

### 1.2 온톨로지 계약이 말하는 것

```
선적 지연 → 원료가 안 들어옴 → 생산가용 재고 ↓ → 생산 제약 → 매출 시점 밀림
```

**지연 ↑ → 재고 ↓ → 생산 ↓**

### 1.3 그래서 무엇이 문제인가

| | 기존 엔진 | 온톨로지 계약 |
|---|---|---|
| 무엇의 재고인가 | **안 쓰고 남은** 원료 | **쓸 수 있는** 원료 |
| 지연이 오르면 | **오른다** | **내린다** |
| 인과 방향 | 생산 → 재고 (결과) | 재고 → 생산 (원인) |

⚠️⚠️ 이름만 이으면 화면에 「지연 15일 → 재고 +230톤」이 뜬다. 숫자는 계산되고,
단위도 맞고, 지문도 결정론적이다. **그런데 뜻이 반대다.** 그 화면을 본 사람은
「재고가 늘었으니 여유가 있다」고 읽고, 실제로는 원료가 없어 라인이 선다.

★ 이것이 「참조가 있다」를 「계산이 된다」로 바꿔 적는 것보다 나쁜 이유다 — 뒤엣것은
비어 있어서 아무도 속지 않지만, 앞엣것은 **채워져 있어서** 속는다.

## 2. 지표를 나눈다 (확정)

`INV-01` 이 이미 네 칸을 구분해 갖고 있다 — 그동안 우리가 한 칸으로 뭉쳐서 썼을 뿐이다.

```
unrestricted_quantity  가용        quality_quantity   검사중
blocked_quantity       보류        safety_stock_quantity  안전재고
```

| 지표 | 뜻 | 단위 | 낟알 | 원천 |
|---|---|---|---|---|
| `on_hand_qty` | 창고에 있는 전량 | TON | 자재×창고×일자 | `INV-01` 네 칸의 합 |
| `available_qty` | **생산에 쓸 수 있는** 양 | TON | 〃 | `INV-01.unrestricted_quantity` − `safety_stock_quantity` |
| `in_transit_qty` | 운송 중(아직 없음) | TON | 선적×자재 | `LOG-02.shipment_quantity` (`eta` 미도래) |
| `shortage_qty` | 원료 부족량 | TON | 자재×사업장×기간 | `MFG-01.material_requirement` − `available_qty` |
| `producible_qty` | 부족을 반영한 생산 가능량 | TON | `plan_line_id` | `min(plan_quantity, 가용으로 만들 수 있는 양)` |
| `revenue_shift_days` | 매출 인식이 밀리는 일수 | 일 | `sales_line_id` | `actual_ship_date` − `due_date` |

### 2.1 부호 방향을 못 박는다

```
선적 지연 ↑  →  in_transit_qty ↑ · available_qty ↓
available_qty ↓  →  shortage_qty ↑  →  producible_qty ↓
producible_qty ↓  →  revenue_shift_days ↑
```

⚠️ **`on_hand_qty` 는 이 사슬에 쓰지 않는다.** 안전재고와 보류 재고가 섞여 있어서
「있는데 못 쓰는 것」이 가용으로 세어진다.

### 2.2 시점과 판

| 축 | 규칙 |
|---|---|
| `as_of` | 질의 시점. 색인이 **그 시점의 인증판**을 고른다(「그냥 최신」 금지) |
| 입력 Snapshot | 각 지표의 원천 계약키가 **같은 `as_of` 로 고른 판**이어야 한다 |
| 기간 | `INV-01.snapshot_date` 기준일. 기간 계산은 그 날짜로만 |
| 봉인 | 관계 승인 시 `snapshot_id` 를 봉인하고, 다른 판으로 답하면 무결성 장애 |

## 3. 기존 `calc_graph` 와 필드별 대조

| `calc_graph` 출력 | 뜻 | 온톨로지 지표와 같은가 |
|---|---|---|
| `production_qty` | 지연 비례로 깎인 생산량 | △ `producible_qty` 와 **원인이 다르다**(기간 비례 vs 원료 부족) |
| `ending_inventory` | `inv0 + (안 만든 양)` | ✗ **반대**다. §1.3 |
| `purchase_payment` | 환율 반영 구매대금 | ✗ 이 사슬에 없다(환율 동인) |
| `ending_cash` | 대금·이익 변화 반영 | △ 재무 영향이지만 **매출 시점**이 없다 |
| `operating_profit` | 단위마진 × 못 판 물량 | △ 〃 |

| `calc_graph` 동인 | 온톨로지 |
|---|---|
| `lead_time_days` | ● 선적 지연과 뜻이 통한다 |
| `fx_rate_pct` | ✗ 최소 경로에 없다(`DRIVES` 는 §2.3 제외) |
| `power_price_pct` | ✗ 〃 |

**결론**: 다섯 출력 중 **온톨로지 지표와 뜻이 같은 것이 하나도 없다.** 하나(`lead_time_days`)만
입력 쪽에서 통한다.

⚠️ 그래서 `(나) 계약의 참조를 기존 엔진에 맞춰 다시 정의` 는 하지 않는다. 맞출 대상이
없고, 억지로 맞추면 §1.3 의 사고가 그대로 남는다.

## 4. 실행 모델 — **간선별이 아니라 경로 단위**

⚠️ 간선마다 계산기를 하나씩 두면 네 번 계산하고 네 번 반올림하며, 중간값이 서로 다른
판에서 올 수 있다. 그러면 같은 질문에 두 번 답할 때 값이 흔들린다.

★ 대신 **경로 하나를 한 번에** 계산하는 계약을 우선한다.

```
입력   경로(4관계) · as_of · 봉인된 snapshot_id 들 · 승인 원장 ID · 가정(지연 일수)
출력   6지표 + 결정론적 지문 + 모델 판 + 쓴 판 목록
```

계산 참조 4종은 그 경로 계약의 **구간 이름**이 된다 — 각자 실행되는 것이 아니라
「이 구간의 의미는 이것」을 가리킨다.

⚠️ 이 계약이 승인되기 전에는 어떤 참조도 `APPROVED` 로 올리지 않는다.
