## 보완 1 — 메가로 요청했는지 보존하고 명시 true를 요구 [P2]

근거:

- App.tsx readStudioEntry는 mega를 구분하지만 initialProject/entryGateId로 옮긴 뒤 Gate에는
  projectId/childId만 전달한다. 자식 없는 메가 요청은 일반 project 요청과 구분되지 않는다.
- studioProjectEntry.ts는 is_mega_project의 boolean 형식만 확인한다(검토 당시81행).
  false인 정상 project 응답도 통과한다.
- StudioEntryCommit은 메가 여부 확인 없이 부모 또는 자식 project_id를 선택한다(116행).

지시:

1. target 종류 또는 requireMega 같은 명시 정보를 App→Gate→flow/reader까지 전달한다.
2. 일반 project 요청은 false도 정상. mega 요청은 자식 유무와 관계없이 명시 true일 때만 진행한다.
3. child를 요청했는데 is_mega_project=false인 응답도 거절한다.
4. target/child 변경 시 이전 flow/응답을 무효화한다. 확인 전 setCurrentProject 호출 금지.
5. 메가 URL+일반 프로젝트, 메가 URL+true, 일반 project+false, child+false 응답을 각각 검사한다.
   App의 요청 종류 전달도 실제 실행 또는 그에 준하는 좁은 배선 검사로 잠근다.

이는 서버의 boolean 사실을 확인하는 것이며 프런트가 소속 관계를 추측하는 것이 아니다.

## 보완 2 — 감사 검사 자체의 비교 오류 수정

tests/test_m2_entry_gates.py의 감사 검사는 before 최대100건과 이후 최대10건을 비교한다.
이 로직의 결함은 소스에서 확인했다. 그러나 두 limit를 같게 바꾸는 것만으로는 부족하다.
같은 limit라도 창이 가득 차면 새 사건이 생겨도 길이는 늘지 않는다.

지시:

- 이 시험에 한해 격리 감사 저장소 또는 요청 이후 추가된 사건을 식별하는 방식으로 수정한다.
- 404 응답, 이번 요청의 ACCESS_DENIED_SCOPE_MISMATCH 사건, 대상 식별자를 함께 검증한다.
- 과거 사건만으로 통과하지 않으며 감사 기록 호출을 제거하면 실패해야 한다.
- 이전 감사 사건이10건/100건 이상 있는 조건에서도 검사 의미가 유지되도록 확인한다.
- 운영 로그 삭제·초기화, 감사 제품 로직 변경, skip/xfail, 단언 약화는 금지한다.
- 기존 동일5파일 합동 명령을 마지막에1회 재실행한다. 1FAIL을 남긴 채 전체 통과로 보고하지 않는다.

이는 발견된 시험 결함의 제한적 보정 지시다. M2 기능 전면 작업으로 확장하지 않는다.

## 결정 A — 응답 계약

이번 동일 저장소 작업에서는 새 필드 엄격 검증을 유지한다.
is_mega_project 누락을 무조건 false로 바꾸지 않는다. mega에 대한 미확인을 정상처럼 다루지 않는다.
서버·프런트는 함께 전달하고, 별도 배포가 필요하면 새 계약 서버를 먼저 배포한 뒤 프런트를 배포한다.
혼합 버전 호환이 실제 요구될 때 일반 project에 한정한 버전별 호환을 별도 설계한다.
현재 이는 배포 실행 지시가 아니다.

## 결정 B — 503은 일괄404로 접지 않는다. 판정 순서를 검사한다

- 실제 읽기 장애를 없는 자원으로 위장하지 않는다. 볼 수 있는 자원의 판독 장애는503을 유지한다.
- 비가시/관계 밖 자원은 같은404이어야 한다. 이를 위해 숨겨야 할 대상의 상세 상태를 읽기 전에
  가능한 권한/문맥/관계 검사를 먼저 수행한다.
- 현재 child 경로는 child의 _authorized/state를 읽은 뒤 related를 검사한다.
  부모가 메가가 아니거나 부모 목록에 child가 없는 경우는 부모 사실만으로 거절할 수 있다.
  그 명백한 관계 실패는 자식 상태를 읽기 전에404로 처리한다.
- 비가시 자식+손상 상태, 부모 목록 밖 자식+손상 상태, 정상 권한/관계 자식+판독 장애를 확인한다.
  기존 권한 헬퍼의 순서 때문에 비가시 대상이503을 노출한다면 위치/재현을 먼저 보고하고,
  공통 헬퍼의 광범위 개편은 임의로 하지 않는다.
- membership의 읽기 실패 None 처리와 문서의503 설명이 충돌하지 않도록, 실제 보장 범위를 정확히 기록한다.
