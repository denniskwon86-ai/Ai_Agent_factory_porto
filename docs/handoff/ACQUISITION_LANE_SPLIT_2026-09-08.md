## 1-B. 새로 들어온 것 — 연구자료 «추천기»(`ac7e1b969`)

2026-09-08 사용자와 논의해 정한 것: **웹검색·RSS 자동 수집을 하지 않는다.** 대신
「이 회사·이 목적이면 어디를 보라」를 추천하고, **받아오는 행위는 사람이 한다.**

논거가 기술이 아니라 신뢰였다 — 기관 사이트는 개편되고 유료화되는데, 「나오던 게
안 나오면」 사용자는 그것을 **우리 시스템의 오류로 읽는다.** 자동 수집은 그 오해를
우리가 떠안는 구조다.

    core/external_intelligence/research_catalog.py     기관 27곳 — 닫힌 목록
    core/external_intelligence/research_recommender.py KSIC 접두사 매칭 · 결정론적
    api/routes/research_control.py                     GET /sources · POST /recommend

### ★★★ 화면이 지켜야 할 것 하나

> **LLM 이 기관을 «생성»하게 두면 안 된다.** 카탈로그에서 «고를» 수만 있다.

「이 회사에 맞는 연구기관을 추천해」라고 그냥 물으면 그럴듯한 기관명과 URL 을 지어내고,
사용자는 없는 사이트를 찾아 헤맨다 — 자동 수집을 그만두며 없앤 신뢰 문제가 추천 단계로
옮겨올 뿐이다. 화면이 LLM 으로 문구를 다듬는다면 **`verify_llm_output()` 으로 되돌려
대조해야 한다.** 서버가 그 함수를 제공한다.

### Codex 레인 — 화면에서 할 일

| | 무엇 | 비고 |
|---|---|---|
| U5 | 추천 목록 화면 | `POST /api/v1/external/research/recommend` |
| U6 | 원천 카탈로그 열람·필터 | `GET /api/v1/external/research/sources?use_case=&topic=` |
| U7 | 「이미 확보함 / 안 씀」 표시 → `exclude` 로 되돌리기 | 매번 같은 걸 권하면 목록을 안 보게 된다 |
| U8 | 「링크가 죽었다」 신고 동선 | ⚠️ 카탈로그가 **조용히** 낡지 않게 하는 유일한 장치 |

⚠️ **문구를 화면에서 새로 만들지 말 것.** 서버가 카드에 필요한 것을 전부 내려준다 —
  `name_ko` · `publisher` · `what_it_gives` · `series`(찾을 보고서) · `listing_url`
  (발간물 목록 페이지) · `access_label` · `language` · `update_cycle` · `caveats` ·
  `evidence_level` · `trust_grade` · `link_verified`.
  그리고 `why[]`(왜 이 회사에 맞는가)와 `warnings[]`(가기 전에 알 것)가 항목마다 붙는다.

★ **꼭 보여 줘야 하는 것 셋** — 빠지면 이 기능의 요점이 사라진다:

    ① notice / notes    「시스템이 접속하지 않는다 · 받아오는 것은 사용자」
                        ⚠️ URL 접두사가 `/research` 라 «가져오는» 기존 라우트와 같다.
                          접두사가 구분해 주지 않으므로 **본문이 말해야 한다.**
    ② excluded[]        고르지 «않은» 것과 사유(지시 3). 조용히 빼면 없는 것으로 읽힌다
    ③ link_verified     27곳 전부 `false` 다. 「확인 안 됨」을 숨기면 안 된다

★ `accounted` 와 `total_in_catalog` 를 함께 내려준다 — 화면이 「추천 + 제외 = 전체」를
  스스로 확인할 수 있다.
