# 경영 홈 — 승인 시안 대조 · **눈이 아니라 자로 맞췄다**

작성: Claude Code · 2026-08-25
**상태: 구조 일치. 상단 행동 칸은 사용자 결정으로 현 상태 유지.**

> **한 줄로** — 「딱 봐도 시안이랑 다르다」의 정체는 **클래스 이름 충돌**이었다.

## 1. 재는 방법

눈으로 비교하지 않았다. 시안(`uiux-prototypes/master-concept`)을 5188 에 띄우고,
앱(5179 · `--mode verify` → 8084 시연 서버)과 **같은 스크립트로 계산된 치수**를 뽑아
나란히 놓았다.

⚠️ 시안 페이지는 1440 뷰포트에서 **약 0.976 배로 축소**돼 렌더된다(측정 252/868/320 ↔
선언 258/690/328). 배율을 모르고 측정값만 비교하면 「6px 다르다」로 잘못 결론 낸다 —
**계측기부터 증명해야 한다.**

## 3. 고친 것

### 3.1 ★★★ 클래스 이름 충돌이 상단 바를 회색으로 칠했다

`product-shell.css` 안에 `.afs-product-shell` 규칙이 **두 벌**이었다.

```
29행   시안에서 옮겨 온 74px 구조 바   background: linear-gradient(100deg,#071747,…)
238행  레거시 «화면을 채우는 표면» 팔레트  background: var(--color-gray-950)  = #eef1f4
```

파일에서 나중에 오는 레거시 블록이 이겼다. **오류는 없고 색만 조용히 뒤집혔다.**

★ 두 가지는 다른 것이다 — 하나는 구조 바, 하나는 **전체 메뉴 패널**이 쓰는 팔레트
범위다. 레거시 21곳을 `.afs-palette` 로 갈랐다. 쓰는 곳은 `GlobalNav.tsx` 하나였다(실측).

⚠️ 한 이름에 둘을 담으면 반드시 한쪽이 다른 쪽을 덮는다. 그리고 그것은 조용하다.

### 3.2 시안의 `.product` 격자가 앱에는 없다

시안은 `<main class="product">` 가 `grid-template-rows:74px minmax(826px,calc(100vh-74px))`
로 셸과 작업면 높이를 함께 정한다. 앱은 셸(`ProductShell`)과 캔버스(`EnterprisePage`)가
**다른 컴포넌트**라 그 격자를 만들 자리가 없었다 — 실측 `.product` **0개**.
`.le-canvas .product{…}` 규칙은 걸릴 요소가 없어 아무 일도 하지 않고 있었다.

★ 그 값을 작업면이 직접 받게 했다. 높이만으로는 모자랐다 — 격자의 **암시 행**이 여전히
내용 높이(848)로 잡혀서, 행을 `minmax(0,1fr)` 로 못박고 칸의 `min-height:auto` 를 풀었다.
넘치는 내용은 시안과 같이 `.canvas{overflow:hidden}` 이 자른다.

### 3.3 ⚙ 이 두 개였다

행동 칸 713px 의 내역(실측):

```
SessionBar 360  = 사용자명 33 + 초기비밀번호 칩 91 + ⚙️ 환경설정·관리자 131 + ⏻ 로그아웃 81
GlobalNav  198  = 1차 아이콘 3 × 40 + ☰ 55
⚙           38
＋ 새 업무   95
```

셸의 ⚙(38)과 SessionBar 의 ⚙(131)이 **같은 콘솔**을 열고 있었다. 나란히 둘 있으면
사용자는 둘이 다른 것이라고 읽는다. 중복을 없애고 로그아웃은 아이콘만 남겼다.

1차 입구 셋(상담·협업·브리핑)은 **전체 메뉴 패널로 옮긴 뒤** 바에서 뺐다.
⚠️ 빼기 **전에** 갈 곳을 먼저 만들었다 — 「접는 것」과 「없애는 것」은 다르다.
실측: 패널에 「자주 쓰는 입구」 절이 생겼고 개수가 20 → 23 으로 맞았다.

## 4. 영향 4칸 — **못 내는 값을 약속하고 있었다**

시안의 네 라벨은 `예상 매출 · 영업이익률 · 납기 준수율 · 결정 신뢰도` 다. 그런데 이
시스템의 계산(`core/calc_graph.OUTPUTS`)이 내는 것은 **다섯**이고 그중 어느 것도 저
넷이 아니다:

```
production_qty 생산량 · ending_inventory 기말재고 · purchase_payment 구매지급
· ending_cash 기말현금 · operating_profit 영업이익
```

⚠️ 영원히 채울 수 없는 라벨을 걸어 두면 그 자리는 **영원히 고장**이다.
★ 실제로 낼 수 있는 이름 넷으로 바꿨다(`구매지급` 은 결정의 «결과» 보다 «투입» 에
가까워 뺐다).

### 4.1 그리고 **왜 비었는지**를 말하게 했다

`GET /api/v1/calculation/readiness` 가 관문별로 이미 답을 갖고 있었다. 문구를 지어내지
않고 서버의 `summary`·`next_action` 을 그대로 옮긴다. 실측 화면:

```
실행 승인이 없는 계산 3건
→ 계산 능력 실행을 승인하십시오(사람의 결정 + 원장 사건).   [열기]
```

「열기」는 그 관문을 실제로 다루는 화면으로 간다(관문→메뉴 표 한 곳에서 잇는다.
표에 없는 관문은 링크를 그리지 않는다 — 엉뚱한 화면으로 보내는 것이 침묵보다 나쁘다).

⚠️ 인스턴스가 **딱 하나**일 때만 그것으로 묻는다. 여럿이면 고르지 않는다 — 서버도
「아무 인스턴스나 골라 주지 않는다」로 두었고, 골라 버리면 그 답이 어느 인스턴스의
것인지 화면이 말할 수 없다.

### 4.2 ⚠️ 도중에 내가 낸 결함

계산 준비도 클라이언트를 `dataPrepApi` 에 **새로 만들었다.** 그런데
`lib/calculationApi.getReadiness` 가 같은 경로·같은 타입(`GateState`·`Gate`·`Readiness`)
으로 **이미 있었다.** 31줄을 철회하고 있는 것을 쓰게 고쳤다.

★ 같은 질문에 두 벌이 생기면 서버가 관문을 늘릴 때 한쪽만 고쳐진다.

## 5. 남은 것

1. **값 채우기** — 사용자가 셋 다 고르셨다.
   - 영향 4칸의 **숫자**: `POST /baseline/simulate` 가 답한다. 다만 봉인된 기준선과
     **계산 실행 승인**이 선행이라, 경영 홈이 로드 중에 조용히 돌릴 일이 아니다.
     지금은 그 사실을 화면이 말하고 갈 길을 연다(§4.1).
   - **노드 7개 대표 지표**: 공정 프로필 원천이 아직 없다(`/master/domains` 404).
     지금은 조직 트리를 업무 축으로 쓰고 그 사실을 화면에 적는다.
   - **오버레이 5칸 실제 자산**: 개별 자산을 노드에 귀속시키는 배선이 없다.
2. **전역 내비 / 행동 칸 폭** — 현 상태 유지 결정. 시안과 다른 이유는 §2 △ 참고.
3. `frontend/.env.local` 은 다른 세션 것이라 건드리지 않았다 — 이 세션은
   `.env.verify.local` + `--mode verify`(5179)로 띄운다. 시안은 `prototype`(5188).
