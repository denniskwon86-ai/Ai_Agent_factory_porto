## 1. 이번 결정

이번 작업은 다음 두 줄기를 하나의 임계경로로 묶는다.

1. **로컬 실제 브라우저 폐루프**: 데이터 준비부터 계산 승인, 영향 경로, 수치 계산, 의사결정 안건, 경영 브리핑까지 실제 제품 화면으로 완주한다.
2. **업무키트 제품화**: 현재 35개 데이터셋 묶음과 범용 표 조회기에 머문 Starter Kit를, 사용자가 업무 목적을 이해하고 바로 쓸 수 있는 앱·보고서 묶음으로 만든다.

이번 완료선에는 다음을 포함하지 않는다.

- Naver Cloud, 도메인, TLS 배포
- 실제 ROI·도입 효과의 정량 검증
- 현업 AFS Native 입력 루프
- PostgreSQL 전환과 최대 10명 파일럿

따라서 이번 완료는 `LOCAL DEMONSTRABLE MVP`이며, 웹 배포 완료·업무키트 전체판·파일럿 운영 완료를 뜻하지 않는다.

## 2. 현재 기준선

### 2.1 이미 있는 기반

- `scripts/seed_starter_data.py` + `run.py`: 단일 사전검증 정본 `data/` 확인·보충·제품 서버 기동
- Playwright 기반 실제 Chrome 드라이버와 화면 캡처 기반
- 데이터 준비, 계산 승인, 경로 계산, 의사결정, 브리핑 제품 화면
- 35개 Dataset Contract를 가진 비철금속 패키지와 배터리케미컬 패키지 등 샘플 기업 자산 2종
- Source Binding, DEMO 인증 Snapshot, 소유권 결속, Readiness 계산
- Dataset Resolver, 온톨로지 경로, 계산 모델 3종, B2→G5 계산 근거 봉인 기반
- 계산 불가를 0으로 접지 않고 `BLOCKED`로 표시하는 통제

### 2.2 지금 사용자가 실제로 만나는 상태

| 항목 | 현재 상태 | 판정 |
|---|---|---|
| 디스크의 샘플 기업 패키지 | 비철금속 1종 + 배터리케미컬 1종 | 2종이나 완성 수준이 다름 |
| 운영 레지스트리 | 9개 데이터셋 옛 정의 + 비철금속 35개 정본 | 배터리케미컬은 아직 제품 등록 전 |
| 키트 인스턴스 | 35개 Source Binding·Snapshot을 가진 인스턴스 1개 | 데이터 기반은 있음 |
| 앱 계약 | APP-03·APP-04만 승인된 운영 흔적 | 5개 Blueprint 중 2개 |
| 앱 릴리스 | APP-03·APP-04 디렉터리만 존재 | `entrypoints=[]`, 실행 앱 파일 없음 |
| 앱 화면 | Dataset을 모두 표로 보여 주는 범용 `AppViewer` | 업무 앱이 아니라 데이터 조회기 |

| 브라우저 증거 | 업무키트 화면 + 승인 전 핵심 여정 드라이버 | 승인 전 안전 폐루프는 실측, 승인 후 수치 폐루프는 HOLD |

## 3. 전체 모수

### 3.1 먼저 용어와 계층을 분리한다

종전 계획의 `정본 키트 1종`은 **이번 브라우저 폐루프에서 사용할 샘플 기업 패키지 1종**을 뜻했지만, 이를 업무키트 전체 모수처럼 적은 것은 잘못이다. 제품 구조는 다음 세 층이다.

```text
산업·샘플기업 Starter Package
  └ 업무기능별 Business Kit
      └ App Blueprint · Report · Question · Dataset Contract
```

| 층 | 뜻 | 현재 저장소 |
|---|---|---|
| Starter Package | 산업·샘플기업·데이터·시나리오를 묶은 체험/복사 패키지 | **2종** |
| Business Kit | 구매·물류·재고·생산처럼 사용자가 선택하는 업무 기능 | 하나의 패키지에 섞여 있고 독립 상품화 전 |
| App Blueprint | Business Kit를 실행하는 화면·행동 단위 | 비철금속 패키지에 5종 |

현재 확인된 Starter Package는 다음 두 종이다.

| 패키지 | 상태 | 데이터 | 판정 |
|---|---|---:|---|
| `KIT-MFG-NONFERROUS-PROCUREMENT` | `VALIDATED_FOR_DEMO` | 35종 | 첫 로컬 폐루프 기준 패키지 |
| `KIT-MFG-BATTERY-CHEMICAL-PROCUREMENT` | 합성 Quick/Full 데이터·규격 존재, 제품 상태/앱/보고서 미완 | 35종 | 두 번째 패키지, 제품화 필요 |

9개 데이터셋의 `afs_materials_procurement_v1`은 세 번째 업무키트가 아니라 비철금속 패키지의 옛 축약 정의다.

### 3.2 업무기능별 Business Kit 전체 모수

35개 데이터 계약을 업무 사용자가 고르는 단위로 분해하면 초기 제조·경영 제품군은 **업무키트 8종 + 공통 기반팩 1종**이다. 이 ID는 제품 카탈로그 정규화를 위한 계획 ID이며, 기존 데이터 계약 ID를 바꾸지 않는다.

| 계획 ID | 업무키트 | 주요 데이터 | 이번 폐루프 |
|---|---|---|---|
| FOUNDATION | 회사·조직·기준정보 기반팩 | FND·MDM | 공통 선행 |
| BK-01 | 구매·원료 도입관리 | PRC·MDM·EXT | **직접 사용** |
| BK-02 | 국제물류·도착관리 | LOG·PRC | **직접 사용** |
| BK-03 | 재고·수급관리 | INV·MDM | **직접 사용** |
| BK-04 | 생산계획·자재영향 | MFG·INV·MDM | **직접 사용** |
| BK-05 | 품질·Lot 추적 | QLT·INV·KNW | 후속 화면, 데이터는 유지 |
| BK-06 | 판매·수요·매출시점 | SLS·MFG | **경로 종점으로 사용** |
| BK-07 | 원가·현금·경영전망 | FIN·PRC·SLS·EXT | **직접 사용** |
| BK-08 | 공급위험·시나리오·의사결정 | EXT·SIM·DEC | **직접 사용** |

즉, 이번에 하나만 만드는 것이 아니다. **비철금속 Starter Package 1개를 기준회사로 사용해 7개 업무기능을 관통하는 첫 수직 폐루프를 닫고**, 품질 키트와 배터리케미컬 패키지 제품화가 그 다음 파동이다.

## 4. 표준 브라우저 폐루프

다음 과정은 API 호출, DB 편집, 개발자 도구 조작, ID 직접 입력 없이 제품 화면에서 수행한다.

| 순서 | 사용자 행동 | 화면이 증명할 것 |
|---:|---|---|
| 0 | 단일 사전검증 정본 상태 확인 후 제품 서버·프런트 기동 | `data/`의 같은 인스턴스·결속·인증판 사용 |
| 1 | 합성 데이터 관리자 로그인 | 실존 개인 계정 미사용 |
| 2 | 샘플 회사와 상위 조직 선택 | 조직 범위와 역할 문맥 표시 |
| 3 | 업무 데이터 준비에서 Starter Package와 업무키트 선택 | 패키지 2종의 상태, 선택한 7개 업무기능, DEMO/SYNTHETIC |
| 4 | APP-01에서 구매주문·선적·도착 지연 확인 | 업무 용어·필터·근거 Snapshot 표시 |
| 5 | 계산 실행 승인 화면에서 3개 계산 능력 승인 | 사람이 누른 원장 사건, 승인 전후 상태 변화 |
| 6 | APP-03/경로 계산에서 영향 경로 실행 | 구매→물류→재고→생산→판매 경로와 근거 |
| 7 | APP-04에서 기준선 대비 수치 확인 | 요청·결과 지문, 쓴 Snapshot, BLOCKED/COMPLETE 구분 |
| 8 | 의사결정 안건 생성 | 경로와 계산 결과가 같은 질문·같은 판에 결속 |
| 9 | 경영 브리핑·RPT-03/RPT-05 확인 | 사람이 읽는 이름, 합성 표시, 근거 지문 유지 |
| 10 | 경영자 역할로 재로그인해 같은 안건 조회 | 역할별 동작과 타 조직 비노출 |

정상 폐루프의 목표 시간은 8~12분이다. 최초 완료는 1회로 판정하고, 외부 배포 전 안정화 단계에서 3회 연속 성공으로 올린다.

## 5. 상세 작업 계획

### W0. 작업 기준선과 격리

예상: 0.5일

- 현재 통합 HEAD에서 전용 `codex/` 작업 브랜치와 격리 worktree를 만든다.
- 미추적 업무키트 파일의 작성 근거·의존 파일·시험을 감사해 원자 편입한다.
- 수동 기능 확인·통합 테스트·시연은 모두 `data/`의 같은 인스턴스·결속·인증판을 사용한다.
- 자동 단위·회귀 시험은 `tmp_path` 임시 사본만 사용하며, `data/` 직접 쓰기는 실패로 만든다.
- 현재 운영 DB와 다른 세션의 문서·아카이브 변경을 수정하거나 스테이징하지 않는다.
- 푸시는 별도 지시 전까지 하지 않는다.

완료 증거:

- 깨끗한 checkout에서 업무키트 계약 시험 수집 수가 작업 폴더와 동일
- 운영 DB 불변식 기준선 캡처
- 작업 파일 소유권 표

### W1. 로컬 데모 실행기 정비

예상: 0.5일

- 실존 계정 `hikwon@lsmnm.com`을 데모 경로에서 제거한다.
- `.invalid` 합성 계정 4명을 만든다: 설치·데이터관리, 실행, 승인, 경영자.
- 최초 Seed와 멱등 Top-up을 구분한다. 단일 정본 전체 삭제 Reset은 금지하고, 시연에서

## 7. 완료 게이트

### 현재 판정(2026-08-25)

| 게이트 | 상태 | 남은 핵심 |
|---|---|---|
| L0 재현 가능한 격리 | **부분 통과** | 앱 계약 3파일 원자 반영·fresh checkout 단독 재현·운영 불변식 최종 비교 |
| L1 업무키트 제품 표현 | **구현 통과 / 시각 재검증 대기** | APP-01·03·04 업무 화면의 2개 해상도 실측과 종단 합성 표시 |
| L2 실제 브라우저 폐루프 | **승인 전 통과 / 승인 후 HOLD** | 사람 승인 후 COMPLETE→안건→브리핑 |
| L3 증거·불변식 | **부분 통과** | `local_kit_loop_1` 단일 실행·최종 불변식 봉인 |

현재 성과를 `로컬 실제 브라우저 폐루프 완료`로 부르지 않는다. 정확한 판정은
**`승인 전 안전 폐루프 완료`**다. 다음 상태 전이는 사용자가 계산 능력 3종을 승인한 뒤에만 가능하다.

### Gate L0 — 재현 가능한 격리

- fresh checkout에서 Seed·서버 기동 가능
- 실존 계정·운영 데이터 사용 0건
- 멱등 Top-up과 범위 지정 시연 초기화 뒤 같은 정본 ID·계산 지문 재현

### Gate L1 — Starter Package와 업무키트가 제품처럼 보임

- Starter Package 2종과 각각의 완성 상태가 표시됨
- 비철금속 패키지에서 관통 업무키트 7종의 데이터·앱·보고서 관계를 확인 가능
- APP-01·03·04가 범용 표가 아니라 업무 화면
- APP-02 입력과 RPT-04 효과 측정은 후속임을 명시
- 모든 결과에 DEMO/SYNTHETIC 표시와 근거 존재

### Gate L2 — 실제 브라우저 폐루프

- 회사 선택부터 브리핑까지 개발자 도구 없이 완주
- 승인 전 차단과 승인 후 실행이 같은 세션에서 관찰됨
- 계산 결과와 의사결정 안건의 지문 결속 일치
- 콘솔 치명 오류·무한 로딩·빈 화면 0건

### Gate L3 — 증거와 불변식

- `local_kit_loop_1` 단일 실행 exit 0
- 1440×900 전체 동선, 1280×720 핵심 화면 가독성 확인
- 운영 DB·원장·정책 파일 불변
- 성공 스크린샷과 실패 재시도 기록이 섞이지 않음

Gate L0~L3가 모두 열려야 **`로컬 실제 브라우저 폐루프 1회 완료`**라고 보고한다.

## 8. 일정과 임계경로

| 묶음 | 예상 |
|---|---:|
| W0 기준선·격리 | 0.5일 |
| W1 데모 실행기 | 0.5일 |

현재 코드 재사용률이 높으면 5~6일, 앱 화면에서 데이터 계약 불일치가 추가로 나오면 8일 이상이다. 일정은 전체 35개 데이터셋을 새로 만드는 시간이 아니라 **이미 있는 데이터를 사용자가 이해하고 의사결정까지 이어 가게 만드는 배선·화면·증거 시간**이다.

## 9. 명시적 잔여사항

이번 완료 뒤에도 다음은 남는다.

| 잔여 | 후속 단계 |
|---|---|
| Naver Cloud·도메인·TLS | 외부 시연 배포 |
| 실제 실행 효과·ROI 대조 | 정량 효과 측정 |
| APP-02 현업 입력 | Native 입력 루프 |
| RPT-04 실행 효과 보고 | 정량 효과 측정 이후 |
| `우리 회사에 복사`와 실제 데이터 교체 | Native/Source Binding 운영 단계 |
| PostgreSQL·백업·복구·최대 10명 | M1 파일럿 |
| 브라우저 3회 연속·외부망 리허설 | NCP 배포 직전 |

Starter Package 2종과 업무키트 8종+공통 기반팩의 전체 모수를 이번 로컬 완료와 혼동하지 않는다. 이번에는 실제로 닫은 기능만 녹색으로 표시하고, 후속 기능은 `지원 대기` 또는 `보류`로 표시한다.
