# AI Factory Studio 3주 시연 가능 MVP 실행계획

> 기준일: 2026-08-15  
> 실행 기간: 2026-08-17 ~ 2026-09-04, 15영업일  
> 최종 목표: 대내외 이해관계자 앞에서 중단 없이 실행 가능한 제조 경영 수직 폐루프 1개 완주  
> 상태 정의: `DEMONSTRABLE MVP`이며 상용 운영 완료나 실제 경영 정확도 검증 완료를 뜻하지 않는다.

## 1. 결론

3주 안에 시연 가능한 수준은 달성할 수 있다. 다만 목표를 다음 한 문장으로 동결한다.

> 사용자가 샘플 회사를 선택하고, Javis의 안내로 원료 도입관리 앱을 생성·사용하며, 그 데이터와 기준정보·외부환경 지표가 기업 경영 온톨로지에 연결되고, 환율·도입 지연·전력비 변화를 결정론적으로 계산한 뒤, 의사결정 회의 요청·검토서·경영 브리핑까지 이어지는 한 개의 폐루프를 시연한다.

3주 동안 범용 제품 완성, 실제 EAI 구축, 모든 업무 모듈, 실제 예측 정확도 검증은 시도하지 않는다. 대신 향후 실제 데이터로 교체할 수 있는 계약과 안전 경계는 유지한다.

## 2. 시연 대상 경영 질문

대표 질문은 하나로 고정한다.

> “원료 도입이 14일 지연되고 환율이 10%, 전력단가가 12% 상승하면 다음 분기의 생산량·재고·현금·영업이익은 어떻게 변하며, 지금 어떤 결정을 내려야 하는가?”

시연 결과는 다음을 반드시 포함한다.

- 영향을 받는 원료, 구매주문, 선적, 공장, 생산계획, 제품, 재무지표의 관계 경로
- 기준선 대비 시나리오의 생산량·재고·현금·영업이익 변화
- 사용한 원천, 기준시점, 데이터 종류, 계산식 버전, 관계 근거
- 구매·생산·재무 관점의 권고 행동
- 의사결정권자에게 보낼 회의 요청과 3종 검토서
- 결정 전후의 예상 효과를 요약한 경영 브리핑과 보고서

## 3. 12분 표준 시연 시나리오

| 시간 | 화면·행동 | 증명할 제품 가치 |
|---:|---|---|
| 0:00~1:00 | `AFS 데모소재그룹`과 사업부·공장 선택 | 다법인·다조직 문맥과 권한 상속 |
| 1:00~2:00 | Javis에게 “원료 도입계획을 관리하려면 무엇이 필요한가?” 질문 | 상담역, 준비 데이터·업무 키트 선제안 |
| 2:00~4:00 | 승인된 원료 도입관리 키트로 앱 생성·실행 | 현업 사용자의 App-in-App 생성, Host 권한 상속 |
| 4:00~5:30 | 구매·선적·입고 현황 확인, 사용자 관리 메모 또는 대응안 등록 | 기존 원천 재사용과 AFS Native 입력 분리, 이중 입력 방지 |
| 5:30~7:00 | “이 도입 지연이 어디에 영향을 주는가?” 질의 | 기업 경영 온톨로지의 관계·근거 경로 |
| 7:00~9:00 | 환율 +10%, 지연 +14일, 전력비 +12% 입력 후 실행 | LLM이 아닌 승인된 계산 모델의 재현 가능한 수치 |
| 9:00~10:30 | 기준선·시나리오 비교 및 영향 부서 확인 | 구매→생산→재고→현금·손익의 전사 연결 |
| 10:30~11:30 | 의사결정 회의 요청, 요청자·결정자·영향부서 검토서 생성 | 분석을 결정과 실행으로 연결하는 폐루프 |
| 11:30~12:00 | 경영 브리핑·보고서 확인 | 경영자가 필요한 질문에 근거와 수치로 답변 |

핵심 시연 경로는 LLM 응답 성공 여부에 의존하지 않는다. Javis 설명과 앱 문구 개선에는 LLM을 사용할 수 있지만, 앱 생성 기본형·데이터·관계·계산·결정 패키지는 검증된 계약과 Fixture로 재현한다.

## 4. 3주 범위에 반드시 포함할 것

### 4.1 회사·사용자 문맥

- 샘플 회사, 사업부, 공장 선택
- 구매 담당자와 경영 의사결정자 최소 2개 역할
- 현재 회사·조직·사용자 문맥을 모든 화면에 일관되게 표시
- 샘플·합성 데이터임을 화면에서 명시

### 4.2 Javis 상담과 준비도

- 대표 질문 3종: 시작 안내, 데이터 준비도, 영향 분석
- 필요한 데이터셋과 누락 항목을 선제안
- `준비 완료 / 일부 가능 / 준비 필요 / 조회 실패`를 구분
- 불가능한 기능을 가능하다고 안내하지 않음

### 4.3 SW 생성기 최소 완주

- 승인된 `원료 도입계획·추적` 업무 키트 선택
- Dataset Contract와 App Runtime Contract를 코드보다 먼저 확정
- I-4 2.2와 3~8단계 완료
- 생성 앱은 자체 로그인·토큰·직접 API를 포함하지 않음
- 기존 원천 데이터는 읽기 전용, AFS Native 데이터만 생성·수정
- 사전 생성된 앱을 기본 경로로 사용하고, 라이브 생성은 선택 시연으로 둠

### 4.4 Minimum Demonstration Dataset

35개 전체 패키지를 쓰지 않고 다음 9개로 제한한다.

| ID | 최소 데이터 | 시연 용도 |
|---|---|---|
| FND-01 | 회사·사업부·공장·부서 | 문맥·권한 |
| MDM-01 | 원료·제품·단위 | 공통 의미 |
| MDM-02 | 공급사·고객 | 거래 상대 |
| PRC-01/02 | 가격조건·구매주문 | 구매원가·납기 |
| LOG-M1 | 선적·통관·입고 Milestone | 도입 지연 |
| INV-01 | 재고 Snapshot | 재고 부족 |
| MFG-01 | 생산계획·원료 소요 | 생산 영향 |
| FIN-03 | 월별 손익·현금 기준선 | 경영 결과 |
| EXT-01/03 | 환율·전력단가·운임 | 외부환경 Driver |

최소 데이터량은 원료 2종, 제품 2종, 공급사 3곳, 구매주문 12건, 선적 12건, 월별 기준선 6개월, 시나리오 3종으로 한다. 모든 값에 `source_type`, `data_kind`, `as_of`, `scope`, `quality_status`를 표시한다.

### 4.5 온톨로지 최소 런타임

전체 28개 객체·25개 관계를 한 번에 구현하지 않는다. 첫 시연 경로에 필요한 객체와 관계만 승인한다.

```text
원료 → 구매주문 → 선적·통관 → 입고·재고
    → 생산계획 → 제품 → 판매·회수 → 현금·손익
외부환경 지표 ────────────────┘
```

필수 기능:

- 승인 상태, 버전, 유효기간, 회사·조직 범위가 있는 관계 저장
- 기준시점 `as_of`로 동일 경로 재현
- 관계 근거와 원천 식별자 반환
- 권한 밖 관계의 존재·개수·사유 비노출
- 대표 질의 3종만 결정론적 Query Plan으로 지원
- 수치 계산은 하지 않고 G4 계산 모델로 참조 전달

### 4.6 경영 시뮬레이션 최소판

- 기준선과 시나리오를 분리
- Driver `pct`, `delta`, `set` 지원
- 환율, 도입 지연, 전력단가 3개 Driver
- 생산량, 기말재고, 구매지급, 기말현금, 영업이익 5개 결과지표
- 계산식·입력 Snapshot·버전·실행 ID 저장
- 같은 입력은 같은 결과를 반환
- 미승인 계산식·관계·데이터는 Fail-closed

### 4.7 의사결정과 보고

- 시뮬레이션 실행에서 의사결정 안건 생성
- 요청자용·의사결정자용·영향부서용 검토서 생성
- 회의 요청, 결정 상태, 실행 책임자·기한 표시
- 전사 브리핑에 질문, 근거, 기준선 대비 변화, 권고안 표시
- 대내외 보고서 예시 화면과 PDF/HTML 출력 중 하나 완주

## 5. 3주 동안 제외할 것

다음은 구현하지 않거나 시연의 필수 경로에서 제외한다.

- 실제 고객 ERP·MES·WMS·LPL과의 신규 EAI 구축
- 원천 시스템 쓰기와 L3 양방향 자동화
- 모든 업무 부서·산업·회사 유형의 범용 키트
- 전체 온톨로지 객체·관계와 자유형 Graph RAG
- 실시간 외부 데이터 수집과 유료 데이터 연계
- 예측 정확도·ROI·경영효과의 실제 성과 주장
- 운영 SSO 전환, 고가용성, 다중 워커, 재해복구 완결
- 전면적인 UI 테마 재설계
- 임의 요구의 완전 자동 앱 생성 품질 보장
- 모바일 최적화와 다국어

이 항목이 시연 경로를 막는 경우에는 실제 구현 대신 `지원 대기`로 표시하며 조용한 폴백을 만들지 않는다.

## 7. 팀 운영 방식

역할은 우선 담당일 뿐 고정 경계가 아니며, P0 결함과 교차검토는 서로 대체할 수 있다.

| 주체 | 3주 우선 책임 |
|---|---|
| Supervisor | 범위 동결, 시연 대상·표현 승인, 하루 안에 결정 |
| Claude Code | I-4, BDR 최소 런타임, G2/G4/G5 코드·회귀·E2E |
| Codex | 시연 IA·UIUX, 화면 구현 교차감사, 표준 시연 스크립트·블라인드 리허설 |
| Antigravity | 9개 Fixture, 공식 외부지표, 품질·계보·대사·계산 결과 독립 검증 |

운영 규칙:

- 매일 시작 시 `오늘의 시연 경로 차단 1건`을 먼저 정한다.
- 작업 항목에는 작성자, 목적, 영향 파일, 완료 증거를 남긴다.
- 같은 파일을 두 세션이 동시에 수정하지 않는다.
- P0 보안·데이터 오염 결함은 기능 일정보다 우선한다.
- 교차검토는 진행을 막는 사전 대기가 아니라 커밋 후 부채로 등록하되, 시연 기준선 병합 전 닫는다.
- 신규 아이디어는 `POST-DEMO BACKLOG`에만 적고 3주 구현에 넣지 않는다.

## 8. 시연 승인 게이트

### Gate A — 기능

- 회사 선택부터 보고서까지 새로고침 없이 완주
- SW 생성·실행, 온톨로지 질의, Twin 계산, 결정 요청 모두 실제 제품 화면에서 동작
- 빈 화면, 무한 로딩, 개발자 콘솔 조작 없음

### Gate B — 데이터

- 모든 시연 값에 `DEMO/SYNTHETIC` 표시
- 기존 원천 데이터와 AFS 입력 데이터가 구분됨
- 기준선과 시나리오를 혼합하지 않음
- 미승인·미바인딩·판독불가 데이터는 계산과 브리핑에 들어가지 않음

### Gate C — 계산·온톨로지

- 동일 입력 3회 실행 결과 동일
- 영향 경로와 수치 결과가 역할상 분리됨
- 관계·계산식·원천·기준시점·버전 확인 가능
- 권한 밖 객체나 관계의 존재·개수 누설 없음

### Gate D — UX

- 1280×720과 1440×900에서 가로 넘침·주요 기능 잘림 0
- 본문 12px 미만 0
- 조회 실패와 0건 구분
- Javis가 현재 사용자 권한 밖 기능을 가능하다고 말하지 않음
- 사용자가 다음 단계와 전체 진행상태를 동시에 파악 가능

### Gate E — 안정성

- 표준 시나리오 3회 연속 성공
- 원클릭 Demo Reset과 Readiness Check 제공
- 핵심 경로에서 외부 LLM·외부 네트워크 장애가 발생해도 계산·결정 결과 재현
- 전체 테스트·프런트 빌드·핵심 브라우저 카나리 통과

## 9. 절대 일정 방어선

|---|---|
