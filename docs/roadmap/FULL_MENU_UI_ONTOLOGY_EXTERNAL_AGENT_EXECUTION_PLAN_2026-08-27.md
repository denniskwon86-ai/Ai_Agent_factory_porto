# LAXS-M 전체 메뉴 UI·온톨로지 그래프·대외 수집 에이전트 실행계획

- 기준일: 2026-08-27
- 기준 브랜치: `integration/g2-vertical-loop-20260821`
- 현재 목표: 로컬 환경에서 실제 브라우저 폐루프와 전체 제품 화면 완성
- 배포·운영 이관(Naver Cloud/TLS, PostgreSQL, 10명 파일럿)은 후속 단계로 유지

## 1. 정정 사항

종전 계획은 대표 제품공간 중심이라 전체 메뉴 26개를 완전한 UI 개선 모수로 잡지 않았다.
또한 온톨로지는 표와 경로 목록까지만 계획했고, 실제 관계를 한눈에 보는 상관 그래프를 별도
완료 조건으로 두지 않았다. 대외 인텔리전스도 CSV·등록 API 수집까지만 있어 능동 수집 에이전트와
회사 기준 초기 조사 기능이 없다. 이 문서는 세 누락을 모두 정본 작업 범위에 포함한다.

## 3. UI 완료 조건

각 화면은 다음 10가지를 모두 통과해야 한다.

1. 메뉴 명칭과 화면 첫 제목이 일치한다.
2. 회사·조직·REAL/VIRTUAL 문맥이 상단에 유지된다.
3. 좌측은 작업 단계, 중앙은 실제 업무, 우측은 자비스 문맥으로 역할이 갈린다.
4. 버튼·표·폼이 1280×720에서 겹치거나 잘리지 않는다.
5. 긴 내용이 상단 셸을 밀거나 하단 실행 버튼을 숨기지 않는다.
6. 빈값은 0으로 보이지 않고 `등록 없음/권한 밖/미승인/장애`가 구분된다.
7. 권한 밖 개수와 객체 존재를 누설하지 않는다.
8. 변경·승인·철회는 영향, 근거, 복구 방법을 누르기 전에 표시한다.
9. 키보드 포커스·Escape·스크롤 잠금이 동작한다.
10. 실제 브라우저 캡처와 사용자 확인을 증거로 남긴다.

## 4. 업무 온톨로지 상관 그래프

### M0 범위

- 관계 API가 실제로 돌려준 객체만 노드로 표시한다.
- 승인 관계는 실선, 승인 전·종료 관계는 점선으로 구분한다.
- 네임스페이스를 색으로 구분하되 상태를 색 하나에만 의존하지 않는다.
- 노드 클릭은 영향 경로 시작점 선택, 간선 클릭은 승인·근거 상세 선택과 같은 상태를 사용한다.
- `as_of`, 회사·조직 권한, 관계 상태 필터가 그래프와 표에 똑같이 적용된다.
- 빈 그래프에서 숨겨진 관계 수를 추정하거나 가상 간선을 만들지 않는다.
- 표 형태 대체 표현을 유지한다.

### 후속 범위

- 영향 경로 한 개 강조와 사용 Snapshot 결속 표시
- 정량 간선의 계산 능력·승인 상태 표시
- 그래프 PNG/SVG 내보내기(권한 범위 안의 현재 화면만)
- 대규모 그래프 군집·검색·초점 이동

## 5. 대외 인텔리전스 수집 에이전트

기존 기능은 승인 원천에 귀속된 CSV와 등록 JSON API를 사람이 예행·적재하는 수준이다. 새 기능은
임의 인터넷 크롤러가 아니라 **회사와 업무 목적에 결속된 통제형 수집 에이전트**로 만든다.

### 5.1 회사 조사 프로필

회사 기준정보에 다음을 별도 판으로 둔다.

- 실제 법인 ID와 회사명·법인명·업종 코드
- 공식 도메인과 공식 공시/IR/뉴스 주소
- 사업·제품·지역·경쟁사·원재료 키워드
- 필요한 외부 지표와 사용 목적(기준계획/시뮬레이션/브리핑)
- 허용 도메인, 수집 주기, 담당 부서, 보존 기간
- 승인자·승인 시각·프로필 지문

회사 이름만 보고 봇이 동명이인 회사를 고르지 않는다. 공식 도메인 또는 사람의 식별 승인 없이는
`UNBOUND`로 남긴다.

### 5.2 봇 종류

1. **회사 기초조사 봇**: 공식 사이트·공시·승인된 공개 원천에서 회사/사업 후보 사실과 원천 후보를 만든다.
2. **지표 수집 봇**: 승인된 API·RSS·HTML 추출 규칙을 주기 실행해 관측값 후보를 만든다.
3. **대외 사건 감시 봇**: 뉴스·공시의 제목/본문 근거를 사건 후보로 만들되 수치 관측값으로 자동 승격하지 않는다.
4. **품질·변경 감시 봇**: 원천 구조 변경, vintage 누락, 단위 변화, 중복, 수집 실패를 감지한다.

### 5.3 상태와 승인

`DRAFT → REVIEW_REQUIRED → APPROVED → SCHEDULED → RUNNING → CANDIDATE_READY → ACCEPTED/REJECTED`

- 발견한 원천은 미승인 후보이며 자동 수집에 쓰지 않는다.
- 수집 결과는 RAW 후보이고 Actual·Gold·기준계획으로 자동 승격하지 않는다.
- 원문 URL, 수집 시각, 내용 지문, 추출 규칙 판, 근거 위치, vintage를 보존한다.
- 원천 철회·이용조건 변경 시 이후 실행을 막고 기존 결과는 이력으로 남긴다.
- 장애는 빈 결과나 0건으로 접지 않는다.

### 5.4 수집 어댑터

- JSON/공식 API: 명시 필드 매핑
- RSS/Atom: 사건 후보만 생성
- HTML: 승인된 도메인과 CSS/JSON-LD 추출 규칙만 사용
- 문서/PDF: 원문 보존과 추출 근거 페이지를 포함한 후보 생성
- 범용 검색: 회사 기초조사 단계의 원천 후보 발견에만 사용하며 사람이 승인해야 등록 원천이 된다.

robots.txt, 이용약관, 저작권, 호출 속도, 인증정보 저장 정책을 원천 계약에 포함한다. 우회 접근,
로그인 장벽 회피, 비승인 도메인 이동은 허용하지 않는다.

### 5.5 제품 화면

대외 인텔리전스에 다음 화면을 추가한다.

- `수집 원천`: 현재 등록부와 승인
- `수집 봇`: 회사·목적·주기·허용 도메인 설정
- `수집 작업`: 예약/실행/실패/재시도와 마지막 성공 시각
- `후보 검토`: 원문 근거와 추출값 대조, 수락/반려
- `관측값`: 승인된 결과와 vintage 비교
- `회사 기초조사`: 회사 기준정보에서 생성한 원천·사업·지표 후보

### 7.1 U1 구조 정렬 완료선 (2026-08-27)

다음 네 레거시 화면을 공통 `HubShell` 3열 구조로 전환했다.

- 업무·데이터 설계 상담: 상담 단계 레일, 선택 문맥, 준비도·원장 근거 자비스
- 업무 데이터 준비: 샘플 패키지부터 원천·데이터 판까지의 준비 단계 레일
- 계산 실행 승인: 준비 상태, 실행 승인, 시연 초기화의 통제 순서
- 경로 계산: 질문·기준시점, 영향 경로, 계산 결과·차단, 의사결정 안건 연결

### 7.9 U9 임원·AI 거버넌스 역할 및 1280px 실제 폭 감사 (2026-08-27)

1280×720 경영 홈에서 세로 스크롤바가 생기면 CSS viewport 1280이 아니라 실제 문서 폭 1265px를
써야 한다. 홈 작업면은 252/693/320px로 맞았지만 공통 상단 셸의 고정 최소폭 합이 행동 칸을
11px 밀어 문서 전체에 가로 스크롤을 만들었다. 1280 구간의 브랜드·회사 문맥·전역 메뉴 폭 예산을
160/210/405px로 다시 배분했다. 행동을 숨기지 않고 `documentElement.clientWidth == scrollWidth ==
1265`와 행동 칸 오른쪽 1251px를 실제로 확인했다.

임원 예시 계정으로 실제 `space=report`에 진입한 뒤 의사결정 센터와 대내외 발간 탭을 각각 눌렀다.
두 화면 모두 참여자 범위, 서버 발간 게이트, 자비스 근거 문맥을 유지했고 가로 넘침은 없었다.
`space=decision`·`space=publication`은 존재하지 않는 주소라 홈으로 접힌다. 이 주소를 열어 놓고
결정·발간을 검사했다고 세지 않고 실제 탭 조작만 증적으로 쓴다.

보안 검토자 예시 계정은 서버 권한 정본상 `is_ai_admin`이며 Agent Governance에서는 승인 행동이
보였지만, AI 스킬 진화는 오래된 `can_manage_standard`와 `assert_can_manage_standard`를 사용해
검토 전용으로 표시됐다. 이는 문구 차이가 아니라 AI 관리자를 막고 데이터 관리자를 통과시키는

### 7.10 U10 Viewer 최소권한 및 지식 하위화면 감사 (2026-08-27)

읽기 전용 Viewer 예시 계정으로 운영승격·워크스페이스·업무표준·AI 스킬·Agent Governance와
지식 허브의 업무 온톨로지·대외 인텔리전스를 확인했다. `space=ontology`와 `space=external`은
존재하지 않는 URL 상태라 경영 홈으로 접힌다. 이를 온톨로지·대외 화면 측정으로 세지 않고,
`space=knowledge`에서 실제 하위 탭을 눌러 다시 측정했다.

업무 온톨로지는 관계 목록·제안 문맥이 권한 없음으로 차단됐지만 `새 관계 제안` 버튼만 활성으로
남아 있었다. 제안 문맥을 읽지 못했거나 귀속 조직 범위가 준비되지 않았으면 버튼을 비활성화하고
사유를 title로 표시한다. 대외 인텔리전스도 목록은 접근 불가인데 회사 조사 프로필·대외 원천
등록 버튼과 수집 입력이 활성으로 남아 있었다. `/org/me`의 `can_manage_standard`를 화면 공통

### 7.11 U11 서비스 연결 장애·부분 복구 감사 (2026-08-27)

로그인된 관리자 세션에서 백엔드 프로세스만 중단해 두 종류의 장애를 실제 브라우저로 확인했다.
새로고침 시 인증 확인 요청이 실패하면 코드 주석과 달리 `out` 상태로 이동해 로그인 폼을 함께
보여 주고 있었다. 이를 `offline` 독립 상태로 분리했다. 세션 토큰은 지우지 않고 로그인 입력도
노출하지 않으며, 서비스 연결 안내와 `다시 연결하기`만 표시한다. 백엔드 복구 후 이 버튼만으로
기존 회사·사용자 문맥이 복원됨을 확인했다.

로그인된 화면을 유지한 채 대외 인텔리전스로 이동한 경우에는 조회 실패를 0건과 구분했지만
브라우저 기술 문구 `Failed to fetch`가 그대로 보이고 관리자 등록·승인·수집 버튼이 살아 있었다.
공통 데이터 상태가 네트워크 예외를 사용자 행동 안내로 정규화하도록 고쳤다. 대외정보의 핵심
7개 조회 중 하나라도 실패하면 수치가 `— / 조회 불가`가 되고 모든 변경 기능을 잠근다. 복구
