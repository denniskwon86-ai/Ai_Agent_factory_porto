# LAXS 시스템 식별자 자동 채번·비노출 전환 계획

기준일: 2026-08-27  
상태: Wave 0~3 완료선 · Wave 4-1~4-4 구현 · 구조화된 진단 사유·제한 진단 ID 펼침 잔여

## 1. 제품 원칙

사용자는 이름·목적·업무 내용을 정한다. API·DB·원장·파일 결속에 쓰는 내부 식별자는
시스템이 발급하고 일반 화면에 표시하지 않는다. 이름 변경과 객체 정체성은 분리한다.

| 구분 | 예 | 사용자 경험 | 저장 원칙 |
|---|---|---|---|
| 내부 객체 ID | 프로젝트·에이전트·지식팩 ID | 입력·노출하지 않음 | 시스템 자동 발급 |
| 업무 정본 코드 | 품목·계정·지표·부서 코드 | 이름·설명으로 검색·선택, 코드 입력·일반 노출 없음 | 정본 코드를 내부 참조 |
| 표시 이름 | 업무명·회사명·에이전트명 | 사람이 입력·수정 | 내부 ID와 별도 저장 |

로그인 계정, 외부 기관이 발급한 코드, 법정 식별자는 내부 ID가 아니다. 해당 값은 별도 검증과
마스킹 정책을 적용한다. 시스템이 임의 코드로 대체하지 않는다.

## 2. 신규 내부 ID 규칙 v1

형식은 `<3자 접두어>_<20자 소문자 16진수>`다. 80비트 난수를 사용하며 시간·회사명·사용자
입력을 포함하지 않는다. 예: `prj_0123456789abcdefabcd`.

| 객체 | 접두어 | 객체 | 접두어 |
|---|---:|---|---:|
| 에이전트 | `agt` | 워크플로우 | `wfl` |
| 프로젝트 | `prj` | 회사 | `ent` |
| 부서 | `dep` | 지식팩 | `kpk` |
| 데이터셋 | `dst` | 의사결정 | `dcs` |
| 릴리스 | `rel` | 시나리오 | `scn` |
| 시뮬레이션 실행 | `sim` | 기준선 결속 | `bln` |
| 대외 원천 | `src` | 조사 프로필 | `rsp` |
| 대외지표 | `xid` | 외부 연계 시스템 | `xsy` |
| 기준정보 유형 | `mtp` | 기준정보 레코드 | `mrc` |
| 출력 양식 | `fmt` |  |  |
| 업무 연결 단계 | `stg` |  |  |
| 외부 연계 시스템 | `xsy` |  |  |

- 중앙 구현: `core/system_ids.py`
- 발급 API: `POST /api/v1/factory/identifiers/allocate`
- 한 요청 1~20개, 닫힌 객체 목록, 미지원 객체는 422
- 저장 시 각 저장소의 고유 제약이 최종 충돌 방어를 담당한다.
- 기존 ID는 변경하지 않는다. 신규 객체부터 v1을 적용한다.

### Wave 4 — 업무 정본 코드 직접 입력 제거

`품목·계정·지표·부서·원천시스템·계획조직` 코드는 의미가 있는 업무 정본이다. 난수 ID를
발급하는 대신 다음 순서로 전환한다.

1. 승인된 기준정보 목록을 조회한다.
2. 사용자는 이름·설명으로 검색한다.
3. 일반 화면은 이름과 상태만 표시한다. 코드는 권한이 분리된 운영 진단에서만 명시적으로 펼친다.
4. 저장 payload에는 선택한 정본의 불변 ID와 당시 판 지문을 함께 결속한다.
5. 정본에 없는 새 코드는 별도의 제안·승인 절차로 등록한다.

대상: 마스터 코드, Planning 조직 코드, 대외지표 코드, 온톨로지 근거 참조.

### Wave 4-1 — 기준정보 신규 정본 (2026-08-28 적용)

- 일반 신규 등록은 코드 없는 `pending` 제안으로 전환했다.
- 제안자와 다른 데이터 관리자의 승인 때만 서버가 신규 정본 키를 발급한다.
- 승인 전 제안은 검색·주입·조직 결속의 대상이 아니다.
- 기존 정본 개정은 카탈로그에서 이름으로 선택하고 내부 키를 서버 경로에 결속한다.
- CSV 사용자 경로도 코드 직접 입력을 거부하고 일괄 제안으로 전환했다.
- 기존 의미 코드와 이력은 변경하지 않는다. 신규 내부 키는 UI에 노출하지 않고 정식 명칭·별칭·
  Crosswalk가 업무 의미를 담당한다.

### Wave 4-2 — 대외지표 신규 정본 (2026-08-28 적용)

- 플레이북에서 시드한 기존 지표와 의미 코드는 그대로 보존한다.
- 신규 지표는 명칭·단위·주기·목적을 코드 없이 제안하고 승인 전에는 확정 목록에 들어가지 않는다.
- 제안자와 다른 데이터 관리자가 제안 내용 지문을 대조해 승인할 때만 서버가 `xid_…` 내부 ID와
  결속 코드를 발급한다.
- 자기 승인, 오래된 지문, 동일 명칭 중복, 반려 사유 누락을 차단한다.
- 화면 목록·상세·기본 지표 선택·CSV 예시는 표시명만 사용한다. CSV/관측값 입력도 확정 지표의
  정확한 표시명을 허용하며 동명이의는 임의 선택하지 않는다.

### Wave 4-3 — 온톨로지 근거 선택과 일반 화면 비노출 (2026-08-28 적용)

- 관계 제안은 근거 참조 문자열을 사용자에게 입력받지 않고 승인 계약 제약의 근거 목록을 자동 결속한다.
- 객체·관계 선택값은 내부 참조를 유지하되 화면에는 업무 유형 문구와 계약의 한글 관계명을 표시한다.
- 계약·관계·경로·원장 지문은 원문을 노출하지 않고 승인·무결성·결속 상태로 표현한다.
- 경로 계산 화면의 시작 객체·경로 노드·인증판·모델 판·의사결정 결과도 내부 ID를 표시하지 않는다.
- 현재 객체 문구는 조회 결과의 안정 순번을 이용한 임시 표시다. 서버가 봉인한 사람용 객체 표시
  설명자가 아니므로, 이름 변경 이력과 객체 정체성을 분리한 정본 표시명 Wave는 잔여다.
- 서버의 자유 형식 브리핑·진단 문장에 기술 코드가 섞이지 않도록 닫힌 사유 어휘와 화면 번역이 필요하다.

### Wave 4-4 — 온톨로지 객체 인증판 표시 설명자 (2026-08-28 적용)

- 조회 순번으로 임시 표시하던 방식을 제거했다.
- 객체 본문은 복제하지 않고 Resolver가 선택한 인증판의 체크섬 검증된 원본 행에서 표시 설명자를
  결정론적으로 파생한다.
- 표시 설명자 지문은 객체 정체성·인증판·원본 체크섬·표시 문구를 함께 결속한다.
- 표시 문구는 경로 지문 재료가 아니다. 이름 변경과 경로 정체성을 분리한다.
- MVP 다섯 유형은 수량·기준일·납기일·운송 구간 등 업무 속성을 표시하며 내부 객체 ID와
  품목·고객·공급사 코드는 표시 재료로 쓰지 않는다.
- 원본 변조·대상 행 누락/중복·계약 불일치는 ID fallback이 아니라 무결성 장애로 차단한다.

### Wave 4-5 — 경로 계산 차단 사유의 폐쇄형 계약 (2026-08-28 적용)

- 일반 사용자용 사유를 관계 승인·계산 승인·인증 데이터·데이터 연결·기준선의 다섯 코드로 닫았다.
- 코드마다 사용자 문장과 다음 행동을 서버 계약으로 제공하되 관계 ID·계약키·계산 참조·사건 ID·건수는
  구조화 인자나 문장에 넣지 않는다.
- 코어의 `internal_reasons`는 운영 진단용으로 보존하고, 제품 API 경계에서 복사본을 만들어 제거한다.
- 경로 계산 화면은 내부 자유 문장을 렌더링하지 않고 `reasons[].next_action`만 표시한다.
- API 차단 응답에 `CALC.*`·데이터 계약키·관계/사건 ID가 없는지, 공개 변환이 원본 진단을 훼손하지
  않는지를 회귀로 고정했다.

### Wave 4-6 — 시스템 관리자 진단 펼침·복사용 본문 감사 (2026-08-28 적용)

- 내부 진단은 일반 계산 API와 분리된 두 제품 경로에서만 제공한다.
- 두 경로 모두 `ADMIN_SECURITY`를 요구하며 진단 목적과 행동별 명시적 확인값이 필수다.
- 서버가 경로·계산을 다시 실행하므로 클라이언트가 내부 ID나 진단 문장을 제출할 수 없다.
- 펼침과 복사용 본문 발급을 별도 감사 사건으로 기록한다. 감사 실패 시 503으로 차단하고 값을
  반환하지 않는다.
- 화면은 시스템 관리자에게만 진단 영역을 표시하고, 복사 버튼은 서버가 감사 후 발급한 본문만
  클립보드에 쓴다.

잔여: 미배선 namespace 표시 계약과 batch Resolver. 기준정보 제안은 승인
사이에 내용이 바뀌는 편집 API가 추가될 경우 지문 대조를 같은 수준으로 보강한다.

## 4. 완료 조건

1. 일반 사용자 화면의 생성 폼에 `ID`, `식별자`, `*_id`, 내부 코드 입력란이 없다.
2. 신규 객체 생성 API는 ID 생략을 지원하고 서버가 발급한 ID를 응답한다.
3. 화면에는 표시 이름이 보이며, 이름이 없어도 ID를 그대로 노출하지 않고 `이름 미등록`으로 표시한다.
4. 사용자 입력 문자열이 파일 경로·DB PK·원장 subject ID가 되지 않는다.
5. 업무 정본 코드는 자유 입력이 아니라 승인된 목록 선택 또는 제안·승인 경로를 사용한다.
6. 운영자 진단 화면에서 ID를 볼 때는 역할 권한·명시적 펼침·복사 이력을 적용한다.
7. 레거시 ID는 마이그레이션 없이 계속 해석되며 신규 ID와 충돌하지 않는다.

## 5. 현재 잔여 위험

- 기존 시뮬레이션 실행 중 기준선·기간·완전성 봉투가 없는 행은 자동 보정하지 않고 `사용 불가`로
  표시한다. 새 엔진 실행부터 `sim_…`·`bln_…`을 자동 발급하고 서버가 안건 생성 순간 재결속한다.
- 받은 앱이 현재 릴리스 목록에 없고 서버가 표시명을 주지 않는 레거시 건은 `이름 미등록 앱`으로
  보인다. 전달 사건 자체에 당시 표시명을 봉인하는 백엔드 보정이 필요하다.
- 마스터 코드·대외지표·온톨로지 근거 참조는 업무 의미가 있으므로 난수 ID로 즉시 바꾸면 안 된다.
  승인된 정본 선택기와 당시 판 지문 결속을 먼저 만들어야 한다. 계획 조직은 계산 엔진의 레거시
  조직키를 ECM `code/node_id`와 대조해 이름으로 선택하는 1차 별칭 결속을 적용했다. 기준정보
  유형과 원천 시스템의 기술 ID는 중앙 발급으로 전환했다.
- 중앙 발급 API는 발급만 하고 객체 저장과 단일 트랜잭션이 아니다. 각 생성 API가 서버 내부에서
  직접 발급하도록 점진적으로 옮겨야 한다.
- 표시 이름이 없는 레거시 객체는 일부 화면에서 ID가 대체 문구로 보일 수 있다. 일괄 표시명
  백필과 `이름 미등록` UI가 필요하다.
- 온톨로지 객체 설명자는 현재 MVP 데이터셋 다섯 유형에 한정된다. `mdm`·`external` 등 namespace가
  실제 배선될 때 각 정본의 이름 이력과 판 지문을 같은 계약으로 반환해야 한다.
- 대규모 인증판에서는 객체마다 원본 체크섬을 다시 계산하는 비용이 커질 수 있다. 무결성 검사를
  약화하는 캐시가 아니라, 한 요청에서 같은 인증판을 한 번만 검증하는 batch Resolver가 필요하다.
- 일반 경로 계산 차단 사유는 폐쇄형 코드와 다음 행동으로 전환했다. 별도 운영자 진단 화면은 아직
  시스템 관리자 권한·명시적 목적·열람/복사용 본문 발급 감사 아래에서만 내부 ID를 펼친다.
