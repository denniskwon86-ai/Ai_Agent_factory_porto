## 1. 사용자 지적에서 시작했다

세션 중반, 사용자가 직접 서버를 띄워 확인하고 세 가지를 지적했다.

1. **첫 화면이 SW 생성기다** — 설계의 경영 홈(Decision Canvas)이 아니었다
2. **백엔드가 연결되지 않는다** — `.env.local` 이 8081 을 가리키고 있었다(내가 남긴 것)
3. **상단에 임의 계정 전환기가 있다** — 「누가 시킨 건가」

그리고 방침을 주었다:

> 완성본 기준으로 겉모습을 설계와 동일하게 구현해놓고, 당연히 기능도 제대로 돌아가게 해놓고,
> 완성도 및 보안사항 등은 테스트를 하면서 잡아나간다. **실제 돌아가는 게 눈에 보이는 게 제일
> 중요하다.**

이후 작업은 전부 이 방침을 따랐다 — **설계와 대조 → 고침 → 살아 있는 화면에서 확인.**

## 2. 로그인·세션 인증 (신설)

계정 전환기를 없애고 로그인을 정본으로 만들었다.

- `core/auth.py` — pbkdf2_hmac(120k) · 세션 12시간 · 만료는 **읽을 때** 판정
- `api/routes/auth_control.py` — `/login`·`/logout`·`/me`·`/password`
- `api/deps.py` — 세션 토큰을 **기존 SSO 슬롯**에 붙였다(`X-Session-Token` → `X-Factory-User` 순)

**설계 판단 셋**

| 결정 | 왜 |
|---|---|
| 실패 사유를 「아이디 없음/비번 틀림」으로 **나누지 않는다** | 나누면 그 응답으로 **아이디 목록을 만들 수 있다** |
| 신규 가입 없음 | 조직도에 없는 사용자가 생기면 범위 판정이 전부 «모르는 사람» 으로 떨어진다 |
| 비밀번호 변경 시 **다른 세션 전부 끊음** | 바꾸는 이유의 절반은 「누가 내 계정을 쓰는 것 같다」이고, 그때 기존 세션이 살아 있으면 소용없다 |

⚠️ 전 계정 초기 비밀번호는 `pass:` 다(사용자 지시). 화면이 「초기 비밀번호」 칩으로 **바꾸라고
  말한다** — 알리지 않으면 그 상태로 운영에 들어간다.

## 3. §5 화면 사양 — 8개 절 전부

### 공통점 하나

고친 곳 대부분은 **「판단에 필요한 것을 보여주지 않는 자리」** 였다. 골격은 대체로 맞았다.

| 화면 | 있었던 일 |
|---|---|
| 전달 Wizard(§5.3) | 3단계가 「권한 Manifest」가 아니라 「전달 목적」이라 **무엇을 전달하는지 모른 채** 보냄 |
| 내 앱 주머니(§5.3) | 이름·날짜뿐 — 누가 준 앱인지, 회수됐는지 알 수 없음 |
| Reference Registry(§5.6) | 「검토 대기 51건」이라 말하면서 **그 51건이 무엇인지 볼 수 없음** |
| 승격 버튼(§5.4) | 초안 상태에서도 「전사 승격」만 강조 → 신청을 건너뛰고 눌렀다 거절당함 |
| 기준선 불일치(§5.5) | 배너만 띄우고 표는 그대로 읽힘 — **경고는 안 읽히고 숫자는 읽힘** |
| Skill 제안(§5.7) | 추가 규칙만 보임 — **현재 규칙과 충돌하는지 알 수 없음** |
| Agent 흐름(§5.7) | 순환·고립 노드는 저장은 되고 실행만 안 됨. 저장 전 확인할 자리 없음 |

### 신설한 서버 경로 (전부 「읽을 수 없던 것」을 읽게 함)

| 경로 | 왜 필요했나 |
|---|---|
| `GET /app-deliveries/preflight` | 전달 **전에** Manifest·차단 사유를 본다. 전에는 눌러야 알았다 |
| `GET /enterprise-context/edges` | 관계 **저장은 되는데 읽는 경로가 없었다** — 만들어도 볼 수 없었다 |
| `GET /reference/assets` | 이미 있었는데 **화면이 쓰지 않았다**(요약 4수치만 보여 줌) |

### ★ 승인 후 파일이 바뀌어도 「승인됨」이었다 (§5.6)

원본 자료 승인 시 **내용 해시를 남기지 않고** 있었다. 승인은 «그 내용» 에 대한 결정인데,
승인 뒤 파일이 통째로 바뀌어도 화면은 계속 «승인됨» 을 보여 줬다 — **검토받지 않은 문서가
검토된 얼굴로 색인되고, 색인은 되돌릴 수 없다.**

`approved_sha256` 을 남기고 서버가 `approval_drift` 로 판정한다.

⚠️ 승인 해시가 **없는** 옛 승인은 «변경됨» 이 아니라 **«확인 불가»** 다. 뭉치면 도입 시점에
  기존 승인 전부가 빨간 경고가 되고, 그러면 아무도 경고를 읽지 않는다. 실측 68건 중 승인
  17건이 전부 `unknown` 으로 나온다 — 의도한 구분이다.

### §5.8 관리자 콘솔 (신설 화면)

좌 6도메인 / 중앙 폼 / **우 Change Impact 고정**. 설계 세부를 그대로:

- 저장 버튼을 **헤더와 영향 패널 하단에 반복** — 누르는 자리 옆에 영향이 있어야 한다
- 전사 설정은 「저장」이 아니라 **「검토 요청」**
- **CI 색이 상태색과 충돌하면 저장 차단** (WCAG 휘도 + RGB 거리). 실측: `#a80020` 넣으니 버튼 2개 동시 잠김
- **API Key 는 마스킹된 값도 재표시하지 않는다** — `sk-••••1234` 도 뒷자리를 노출하고, 그것이 키를 특정하는 단서다
- 권한 화면에 **404 은폐·미바인딩 거부·OPERATING_PARENT** 정책 배너 **상시**

## 4. §6 상호작용 — 가장 값진 발견

### ★★ 늦게 온 응답이 다른 선택 위에 그려졌다 (§6.1)

설계는 「비동기 응답 적용 전 **요청 시점과 현재 문맥이 같은지 재검증**」을 요구하는데,
**지키는 곳이 한 곳도 없었다.**

```
화면 제목:   release_B      ← 사용자가 고른 것
게이트 판정:  승격 가능       ← 실제로는 release_A 의 판정
```

느린 화면이 아니라 **틀린 화면**이다. 그리고 이 화면들은 전부 되돌릴 수 없는 결정의 근거가
되는 자리다 — 전사 승격, Shadow 개선·악화 판정, 대외 발간, 기준정보 코드.

`useLatestOnly` 훅으로 담아 **8곳**에 적용했다. 화면마다 `alive` 플래그를 손으로 넣으면 반드시
빠지는 곳이 생긴다(`HubDialog` 에서 포커스 트랩을 셸로 올린 것과 같은 이유).

**실측 재현**: `fetch` 를 가로채 첫 이력 요청만 3초 지연 → 「회계」 → 곧바로 「물류」 선택 →
3초 뒤 도착한 회계 응답이 **그려지지 않고 물류가 유지**됨.

### §6.5 확인 Sheet — 「되돌릴 수 있는가」가 어디에도 없었다

`ConfirmInline` 이 `title`+`body` 자유서술뿐이라(호출부 29곳) 화면마다 담기는 항목이 달랐다.
다섯을 **이름 있는 자리**로 만들었다 — 자리가 있으면 비어 있는 것이 보인다.

사유는 **입력 자리**로 받는다. 전에는 「⚠️ 사유가 비어 있습니다」라고 경고만 했는데, 경고는
읽고 그냥 누를 수 있다.

⚠️ 고치면서 **사유를 두 곳에서 받고 있던 것**이 드러났다. 강제 전환은 사유를 Sheet 로 옮겼는데
  **Sheet 를 여는 버튼이 여전히 사유를 요구**해서, 사유 없으면 버튼이 잠기고 → Sheet 가 안
  열리고 → Sheet 안의 사유란에 닿을 수 없는 모순이 됐다(실측으로 잡았다).

### §6.2 재조회가 화면을 비웠다 — 그리고 **예외 자리에 잘못 적용했다**

`refreshing(prev)` 로 값을 두고 「갱신 중」만 덧붙인다.

⚠️⚠️ **KnowledgeHub 의 사용자 전환 핸들러에 잘못 적용했다가 되돌렸다.** 사용자 전환은 곧
  **권한 범위 전환**이라, 이전 사용자의 지식팩이 한 순간이라도 남으면 «느린 화면» 이 아니라
  **남의 자료를 보여 준 것**이다. 설계가 「문맥 변경은 즉시 비운다」를 따로 못박은 이유가 정확히
  이것이고, 나는 그 문장을 읽고도 반대로 고쳤다. 전수 검사로 다른 곳은 없음을 확인했다.

**`refreshing` 은 편의 함수가 아니라 경계를 가진 도구다.** 값을 남겨도 안전한 자리(같은 문맥
안의 재조회)와 위험한 자리(문맥·사용자·조직 전환)를 구분하지 못하면 권한 사고가 된다.

## 5. §7 Atlas · §9 접근성 · §11 검수

### §7 — 답변을 여섯 단으로

서버 프롬프트가 형식을 요구하고 프론트가 머리말을 찾아 구조로 그린다.
★ 여섯 중 **④「부족하거나 확인하지 못한 데이터」** 가 핵심이다. 적게 하지 않으면 비서는
모르는 것도 아는 것처럼 말한다 — 화면 전체에서 지켜 온 «조회 실패 ≠ 0건» 이 비서 답변에서만
무너지면 의미가 없다.

⚠️ 형식을 어긴 답은 **버리지 않고** 평문으로 보여 준다. LLM 출력에 화면 동작을 걸면 안 된다.

§7.3 경계(Atlas 가 DB 를 직접 고치거나 권한을 우회하지 않는다)를 **테스트 5건**으로 고정했다.
지켜지고 있을 때 고정해 두지 않으면 「비서가 대신 해 주면 편한데」 한 번에 뒷문이 열린다.

### §9 — 대비 56건 → 0건

실측 흐름 **56 → 32 → 12 → 6 → 0**. 줄어든 만큼 원인이 전부 달랐다.

★ 가장 중요한 발견: **`muted`(#667185)가 이미 4.92 로 겨우 기준을 넘어서**, 「muted 보다
옅으면서 4.5:1 을 넘는 색」은 **존재하지 않았다.** 「더 옅은 본문색」이라는 개념 자체가 WCAG AA
와 양립하지 않는다. 두 단계의 구분은 **색이 아니라 크기·배치**로 한다.

그리고 faint 를 고친 뒤 다시 재니 **muted 도 미달**이었다 — 흰 배경에서만 통과하고 모달이
쓰는 회색 배경(#eef1f4)에서는 4.34. **대비는 색 하나가 아니라 배경과의 쌍이다.**

**반응형**: 1024px 에서 문서 폭이 1205px 로 **가로 스크롤**이 났다. 경영 홈 그리드가
**인라인 style 이라 미디어 쿼리가 먹지 않았다.** 클래스로 옮겼다.
⚠️ 브레이크포인트를 `xl`(1280)로 잡았더니 **정확히 1280 에서 다시 넘쳤다** — 그 폭이 라벨을
  펼치기에 딱 모자라는 경계였다. 브레이크포인트는 디자인 눈금이 아니라 **내용이 실제로 들어가는
  폭**에서 정해야 한다. 375·900·1024·1280·1536·1600 여섯 폭 전부 통과.

  않으면 이렇게 남는다.

## 9. 이 세션의 교훈 (메모리에도 남김)

**측정기가 네 번 틀렸다.** 그때마다 「위반」이 부풀거나 잘못 잡혔다.

1. 검증 스크립트가 **404 를 「0건」으로** 읽음(경로 prefix 오인)
2. 대비 측정기가 **그라디언트 배경을 흰색으로** 가정
3. JS `.focus()` 를 키보드 포커스로 읽음(`:focus-visible` 은 키보드에서만 켜진다)
4. **파이프가 빌드 실패를 삼킴** — 「빌드 OK」가 거짓이었다

넷 다 같은 교훈이다: **못 잰 것을 결과로 세면 진짜 결과가 묻힌다.** 이 저장소가 화면에 대해
지켜 온 «조회 실패 ≠ 0건» 을 **검수 도구 자신에게도** 적용해야 한다.
