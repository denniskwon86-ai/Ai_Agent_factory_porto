## 왜 의뢰하는가

트랙 E **7단계(기존 3패널 제거)** 의 전제는 「Sprint 시작·일시정지·정지·재개·복구·재분할·
Release 가 새 Studio 에서 보존된다」(구현 명세 §8)이다. 다섯 명령을 새 화면에 올렸고
**두 개는 실제로 눌러서 확인**했으나, 나머지 세 개는 **전제 상태를 만들 수 없어 확인하지
못했다.** 전제를 만들려면 파이프라인을 끝까지 돌려야 하고 그만한 토큰 여유가 없다.

⚠️ **확인되지 않은 것을 확인된 것으로 세지 않는다.** 아래 3·4·5 가 초록이 되기 전까지
7단계 승격(3패널 제거)은 하지 않는다.

## 의뢰 절차

1. 버려도 되는 프로젝트를 새로 만든다 (`verify_runctl_<타임스탬프>`).
   ★ **기존 프로젝트에서 하지 말 것** — WBS 재분할은 되돌릴 수 없이 작업 목록을 지운다.
2. 기획을 **끝까지** 가동해 PRD·WBS 가 생길 때까지 둔다.
3. **WBS 재분할** 을 누른다 → 확인 문구가 뜨는지, 「다시 나눕니다」 후 서버가 새 `task_id`
   를 주는지, 기획 산출물(RFP·PRD·UI·아키텍처)이 **살아 있는지**.
4. **Release 저장** 을 누른다 → 릴리스 id 가 화면에 뜨는지.
   ⚠️ 실패 시 「저장하지 못했습니다」가 **뜨는지** 도 함께 본다(조용히 성공처럼 넘어가면 결함).
5. **재개** — 쿼터 소진을 재현하기 어렵다면, 동결 상태를 만든 뒤 새로고침해서
   `suspendedTaskId` 가 살아 돌아오는지까지만이라도 확인한다.
   ★ 재개는 **처음부터가 아니라 멈춘 지점부터**여야 한다. 처음부터 돌면 결함이다.
6. **복구** — 실패한 단계를 하나 만든 뒤 누른다. 「복구를 요청했습니다」 후 재시도가 도는지.
