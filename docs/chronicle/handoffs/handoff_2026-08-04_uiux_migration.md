## 3. 이관은 «색을 바꾸는 일»이 아니다

지식 허브에서 확인된 것이다. 그 화면을 옮기면서 **실제 결함 5건**이 함께 나왔다.

- 자체 `API_BASE_URL` 선언 → 공용 클라이언트로
- 조회 실패를 `console.error` 로 삼키고 빈 배열 → 화면이 «자료가 없습니다» 라고 거짓말
- `alert()`/`confirm()` → 무엇이 지워지는지 설명할 자리가 없다
- 자체 `fixed inset-0` 모달 → dialog semantics·inert·포커스 트랩·Escape 없음
- 9~11px 글자

**MDM·업무표준도 같은 구조다**(세 화면 모두 자체 모달·자체 fetch·오류 삼킴을 확인했다).
그러므로 이관 작업의 실제 내용은 다음 다섯 가지를 계약으로 바꾸는 것이다.

1. `lib/<screen>Api.ts` 를 만들어 `closedLoopFetch` 로 통일한다(실패를 던진다, 삼키지 않는다).
2. `Loaded<T>` 로 감싸 **조회 실패와 0건을 갈라 놓는다**.
3. `HubDialog` + `HubShell` 로 옮긴다(모달을 다시 구현하지 않는다).
4. `DataFoundationShell` 의 조각을 쓴다 — 검색·목록·출처·버전·등록·확인.
5. 글자 크기를 감사 기준으로 맞춘다.

## 5. 알아 둘 함정

- **`venv` 활성화 스크립트는 깨져 있다**(삭제된 Python 3.14 경로 참조). 인터프리터를 직접 부르면 동작한다.
  ```
  venv\Scripts\python.exe run.py
  venv\Scripts\python.exe -m pytest tests/ -q
  ```
- **가짜가 진짜보다 관대하면 테스트는 가짜를 증명한다.** CL-3 에서 실제로 겪었다 — 가짜 원장이
  아무 이벤트나 받아 줘서 단위 테스트 33건이 전부 통과했는데 화면에서 첫 요청이 500 으로 죽었다.
  그래서 지금 테스트의 가짜 원장은 **실제 `EVENT_TYPES` 를 검사한다.**
- **브라우저 실행이 단위 테스트가 못 보는 것을 잡는다.** pytest 는 라우터·의존성·직렬화·SSE
  배선을 지나가지 않는다. 그것을 지나가는 것이 `scripts/closed_loop_canary.py` 다(HTTP 로만 말한다).
- **포커스 이동이 조상 스크롤을 유발한다.** 전체 메뉴가 위로 잘린 원인이 그것이었다
  (sticky header 가 161.5px 스크롤됐다). popover 는 `body` 로 portal 하고 `preventScroll` 을 건다.
- 이 저장소의 preview 서버는 세션 범위다. 다른 사람이 감사할 때 내려가 있을 수 있으니,
  **감사 요청 전에 살아 있는지 확인하고 알린다.**

## 6. 이번에 만든 공용 계약 (다음 화면에서 그대로 쓴다)

| 파일 | 역할 |
|---|---|
| `frontend/src/design/tokens.css` | 의미 토큰 — `surface/* action/* state/* module/* rail/* jarvis-*` |
| `frontend/src/design/DataFoundationShell.tsx` | 데이터 화면군 공용 — 툴바·목록·출처·버전·등록·확인·Jarvis 문맥 |
| `frontend/src/design/DataState.tsx` | **조회 실패 ≠ 0건** 을 타입으로 강제 |
| `frontend/src/lib/backendHealth.ts` | 연결됨/확인 중/일시 중단/오프라인 |
| `frontend/src/lib/closedLoopFetch.ts` | 401/404/422/400 오류 규약 |
| `frontend/src/components/GlobalNav.tsx` | 1차 영역 + 영역별 전체 메뉴(portal popover) |

`action/*` 과 `state/*` 를 섞지 않는다. 1차 행동은 구조색(Navy), 위험은 Red,
성공은 Green 이다. 초록 버튼을 누르면 초록 성공 배너가 뜨는 화면에서는 사용자가
«성공했다» 와 «누를 수 있다» 를 색으로 구분할 수 없다.
