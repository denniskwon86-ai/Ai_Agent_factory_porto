## 1. 결론

현재 구현은 **읽기 전용 UI 수용 테스트를 시작할 수 있는 상태**다. 프론트 프로덕션 빌드와 전체
Python 회귀 테스트가 통과했고, 로그인 화면·기준정보 화면·신규 SW 제작 Studio를 실제 브라우저에서
검증했다.

그러나 **운영 배포 또는 전체 제품 수용검사 완료 상태는 아니다.** 다음 두 항목은 명확한 출시 차단점이다.

1. 로그인 화면은 생겼지만 백엔드가 아직 개발용 `X-Factory-User` 헤더를 신뢰한다. 세션 없이
   관리자 이메일만 헤더로 보내도 `/api/v1/auth/me`가 200을 반환했다.
2. 신규 Adaptive Production Studio는 기능이 구현됐어도 기본 화면이 아니라 구형 통제실 위에 여는
   카나리다. 요구 확인 대기·복구 실패 상태의 실데이터 검증과 동일 상태 대조가 끝나기 전에는 기본
   화면으로 승격하면 안 된다.

따라서 지금 가능한 수준은 다음과 같다.

| 구분 | 판정 | 설명 |
|---|---|---|
| 정적 빌드·타입 | 통과 | Vite 프로덕션 빌드 성공 |
| 백엔드 회귀 | 통과 | 2,716 passed, 1 skipped |
| 읽기 전용 UI | 시작 가능 | 관리자·일반 사용자 화면 캡처 가능 |
| 신규 SW Studio 시각 계약 | 조건부 통과 | 1280·1440에서 핵심 영역 동시 노출 확인 |
| 변경 기능 UAT | 준비 필요 | 복제된 시험 데이터와 되돌림 기준 필요 |
| 인증·보안 수용검사 | 차단 | 헤더 신뢰 폐기 전 운영 판정 불가 |
| LLM E2E·비용 평가 | 미실행 | 별도 예산 상한을 정한 카나리로 수행 |

## 2. 이번 점검에서 직접 수정한 사항

### 2.1 빌드를 막던 TypeScript 오류

- 사용하지 않는 App 상태·핸들러 제거
- 잘못된 `Banner` 속성(`danger`, `text`)을 실제 계약(`error`, children)으로 변경
- 사용하지 않는 `Refreshing` import 제거
- 사용되지 않는 제네릭 제거

### 2.2 실제 화면에서 확인된 결함

1. Adaptive Studio의 자식은 4개인데 CSS 행이 3개여서 **전체 14단계 지도 위로 작업면이 겹쳤다.**
   행을 `프로젝트 헤더 / 실행 통제 / 단계 지도 / 본체` 네 개로 명시했다.
2. 1280×720에서 실행 통제가 과도하게 줄바꿈되어 **Jarvis가 화면 밖으로 잘렸다.** 일곱 실행 명령을
   동일 폭 한 행으로 만들고, 비활성 사유는 버튼 안에서 두 줄까지 유지했다.
3. 경영 홈에서 Factory로 이동하면 이전 스크롤 위치가 남아 **새 업무 만들기와 필터가 화면 밖에서
   시작했다.** 화면·프로젝트 문맥 변경 시 맨 위로 이동하도록 했다.
4. “사람 대기”를 “사용자 대기”로 바꿨다.
5. 실제 동작은 산출물 보존 후 비노출인데 버튼이 “삭제”라고 표시됐다. **“목록에서 내리기”**로 바꿨다.
6. 서버가 실행 상태를 제공하지 않는 프로젝트까지 “진행 중”으로 묶었다. **“미완료”와 “진행률 집계
   전”**으로 사실대로 표현했다.
7. 로그인 직후 초기 비밀번호 `alert()`가 화면 전체를 막았다. 상단의 지속 경고 칩과 인접한 설정
   진입을 사용하고 네이티브 경고창을 제거했다.
8. 경영 홈의 비기술 정보 중 11px인 섹션 제목과 실행 문맥을 12px로 높였다.

## 4. 냉정한 잔여 결함과 위험

### P0 — 운영 전 반드시 해결

#### AUTH-P0: 로그인 우회 가능

- 현재 `config.py`의 `ORG_TRUST_HEADER=True`.
- 세션 토큰 없이 `X-Factory-User: hikwon@lsmnm.com`만 보내도 관리자 `/auth/me`가 200.
- 프론트 로그인은 제품 입구지만 서버 보안 경계는 아직 아니다.

권고 구현:

1. 로그인 성공 시 서버가 임의 세션 토큰을 **HttpOnly·SameSite 쿠키**로 설정한다.
2. `current_principal`은 SSO 주체 또는 서버 세션 쿠키만 신뢰한다.
3. EventSource는 동일 출처 쿠키를 자동 전송하므로 `?as_user=`를 제거한다.
4. `X-Factory-User`, `X-User-Id`, `as_user`는 테스트 전용 명시 플래그 아래에서만 허용하고 운영
   기본값은 거부한다.
5. 무자격 401, 권한 부족 403, 타 범위 자원 404 은폐를 인증 회귀 테스트로 고정한다.

이 변경은 기존 테스트와 SSE가 헤더에 의존하므로 별도 마이그레이션 작업으로 수행한다. 단순히 설정만
False로 바꾸면 실시간 연결과 다수 테스트가 동시에 깨진다.

#### STUDIO-P0: 기본 화면 승격 미완

- 프로젝트 “열기”는 아직 구형 다크 통제실로 이동한다.
- 신규 Studio는 `새 작업공간` 버튼으로 여는 병행 카나리다.
- 요구 확인 대기와 복구 실패의 실데이터 상태가 아직 검증되지 않았다.

승격 조건:

1. 같은 프로젝트 상태를 서버 원본·구형 통제실·신규 Studio 세 방향으로 대조
2. 요구 확인, 일반 HOTL, 실행, 실패, 1~3차 복구, Release 상태를 모두 확인
3. 사용자 초안과 선택 상태가 화면 왕복 뒤에도 보존되는지 확인
4. 승격 뒤 최소 한 릴리스 동안 `종전 통제실로` 되돌림 유지

### P1 — 제품 UAT 전에 해결 권고

- **인증 전용 자동 테스트 부재**: 로그인·로그아웃·만료·비밀번호 변경·세션 회수 테스트 파일이 없다.
- **서버 실행 상태 부재**: 프로젝트 목록이 실제 running/paused/failed를 받지 못해 “미완료”까지만
  구분한다. `run_status`, `last_activity_at`, `current_stage`, `decision_waiting` 계약이 필요하다.
- **URL 상태 부재**: 현재 공간·모달·선택 객체가 React 상태뿐이라 새로고침·공유·뒤로가기가 안 된다.
- **상단 1차 메뉴**: 1536px 미만에서 세 메뉴가 이모지만 남아 서로 구별하기 어렵다. 짧은 텍스트
  라벨 또는 아이콘 체계 재설계가 필요하다.
- **Backend 미구현 3건**: process profile 기반 Canvas, Connector→Contract→Crosswalk→MCP 연결 흐름,
  Jarvis/Atlas의 안전한 실행 경로. 현재 비서는 답변 중심이다.

### P2 — 성능·유지보수

- 번들 1.086 MB. 화면 모달을 route 단위 lazy load하고 `useFactoryStore`의 가짜 동적 import를 정리한다.
- ESLint는 378개(361 errors, 17 warnings)로 전체 게이트로 쓰기 어렵다. 기존 부채를 baseline으로
  동결하고 **변경 파일 신규 오류 0**부터 강제한 뒤 점진 감소시킨다.
- 캡처 자동화의 화면 목록과 기능 명세를 하나의 manifest로 합쳐, 새 페이지가 테스트에서 빠지지 않게 한다.

## 5. 권장 테스트 수행 순서

### Gate 0 — 정적 기준선

1. `npm.cmd run build`
2. 전체 pytest
3. 서버 health 200
4. 작업 트리에서 다른 세션 변경과 테스트 대상 커밋 분리

통과 기준: 빌드 실패 0, pytest 실패 0, 다른 세션 파일 덮어쓰기 0.

### Gate 1 — 인증·세션

1. 정상/오류 비밀번호가 동일한 실패 문구를 내는지 확인
2. 토큰 없음·만료·로그아웃 후 401
3. 비밀번호 변경 후 이전 세션 전부 무효화
4. 일반 사용자가 관리자 기능을 클릭하기 전에 차단 이유를 보는지 확인
5. 헤더·쿼리 위조가 실패하는지 확인 — **AUTH-P0 이행 후 수행**

### Gate 2 — 읽기 전용 화면 수용검사

관리자와 일반 사용자로 경영 홈, 기준정보, 지식, 업무표준, 조직·권한, 거버넌스, 에이전트 통제소,
스킬 개선안, 브리핑을 1280×720·1440×900에서 캡처한다.

통과 기준: 조회 실패를 0건으로 표시하지 않음, 12px 미만 업무 텍스트 0, 가로 넘침 0, 현재 위치와
권한 차단 사유가 화면 안에 존재.

### Gate 3 — SW Factory 상태 대조

시험 전용 프로젝트를 복제하고 다음 상태를 만든다.

1. 생성 직후 / WBS 없음
2. 요구 확인 사용자 대기
3. 기획·설계·WBS 완료
4. 실행 중 / 일시정지
5. 사용자 결정 대기
6. 빌드 실패 및 복구 1·2·3회
7. Release 가능 / 불가

각 상태에서 서버 원본, 구형 통제실, 신규 Studio의 단계·WBS·결정 수·사용 가능 버튼을 대조한다.

### Gate 4 — 통제된 변경 기능

- 시험 테넌트·시험 사용자·복제 프로젝트만 사용
- 앱 전달→수락→내 앱, 결정 패키지 초안, 기준정보 draft 등록 등 되돌릴 수 있는 기능부터 수행
- 외부 발간, 전사 승격·롤백, 권한 강제, 공유 회수, 스킬 승인·영구 반영은 별도 승인 전 금지

### Gate 5 — LLM 카나리

1. 모델별 최대 호출·비용·시간을 먼저 설정
2. 단일 소형 프로젝트 1회만 실행
3. 모델 라우팅, 토큰, fallback, 재시도, 단계별 품질 점수를 기록
4. 동일 입력의 재실행 전 캐시·재사용률과 산출물 회귀를 비교

완주만으로 통과시키지 않는다. 구문·렌더·권한·데이터 계약·결정 계보·비용 상한을 모두 충족해야 한다.
