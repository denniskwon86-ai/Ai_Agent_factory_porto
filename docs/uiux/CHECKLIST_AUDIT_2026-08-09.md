## 이 문서를 읽는 법

각 항목에 **근거**를 함께 적는다. 근거가 「코드에 있다」뿐인 항목과 「실제로 눌러 봤다」인
항목은 신뢰도가 다르다. 그래서 셋으로 나눈다.

| 표시 | 뜻 |
|---|---|
| **실측** | 브라우저·서버에서 실제로 확인했다 |
| **계약** | 서버 테스트가 그 규칙을 고정하고 있다(깨지면 빨개진다) |
| **코드** | 코드를 읽어 확인했다 — 실행으로는 확인하지 않았다 |
| ⚠️ | 충족하지 못했거나 조건부다 |

## ⚠️ 대조 방법에 대한 기록

이 세션에서 **측정기가 세 번 틀렸다.** 그때마다 「위반」이 실제보다 부풀거나 잘못 잡혔다.

1. 검증 스크립트가 **404를 「0건」으로** 읽었다(경로 prefix 오인) — 상태 코드를 먼저 본다.
2. 대비 측정기가 **그라디언트 배경을 흰색으로** 가정해 상단 바 흰 글자를 위반으로 셌다 —
   배경을 확실히 아는 경우만 판정하고 나머지는 «판정 불가»로 분리했다(24건).
3. `JS .focus()`로 재서 「포커스 링 32개 전부 없음」이 나왔다 — `:focus-visible`은 **키보드
   조작에서만** 켜진다. 실제 Tab 키로 확인하니 정상이었다.

4. **검증 명령이 빌드 실패를 삼켰다.** `npx vite build | tail -3 && echo "빌드 OK"` 는
   파이프의 **마지막 명령(`tail`)** 의 종료코드를 본다. `tail` 은 언제나 성공하므로 빌드가
   실패해도 «빌드 OK» 가 찍혔다 — 실제로 이 대조 중에 **깨진 빌드를 통과로 읽었다.**
   이후로는 종료코드를 변수에 받아 확인한다:

   ```bash
   npx vite build > /tmp/b.log 2>&1; code=$?; echo "종료코드: $code"
   ```

넷 다 같은 교훈이다: **못 잰 것을 결과로 세면 진짜 결과가 묻힌다.** 이 저장소가 화면에
대해 지켜 온 «조회 실패 ≠ 0건»을, 검수 도구 자신에게도 적용해야 한다. 특히 4번은
«확인했다» 는 말 자체를 거짓으로 만들었다.

## 프론트 변경을 확인하는 순서 (이 세션에서 확정)

`tsc --noEmit` 만으로는 **부족하다.** 이번 세션에서 타입 검사를 통과하고도 화면이 죽거나
빌드가 깨진 사고가 셋 있었다.

| 사고 | tsc | vite build | 화면 |
|---|---|---|---|
| `RailIcon` 에 없는 아이콘 이름 | 통과 | 통과 | **하얀 화면** |
| JSX **prop 자리**의 `{/* */}` 주석 | 통과 | **실패** | 렌더 안 됨 |
| JSX **표현식 자리**(`cond && (`)의 주석 | 통과 | **실패** | 렌더 안 됨 |

그래서 순서는 **① `tsc` → ② `vite build`(종료코드 확인) → ③ 브라우저에서 그 화면을 실제로
열어 보기** 다. 모달은 portal 이라 `get_page_text` 에 안 잡히므로 `read_page` 로 확인한다.
