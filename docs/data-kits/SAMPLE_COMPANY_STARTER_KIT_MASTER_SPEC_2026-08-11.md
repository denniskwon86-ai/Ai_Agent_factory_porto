## 1. 결정 요약

AI Factory Studio의 신규 사용자는 빈 화면에서 회사 데이터 구조를 직접 발명하지 않는다. 시스템은 산업·업무별 표준과 실제 운영 구조에 가까운 합성 데이터를 담은 **샘플 회사 Starter Kit**를 먼저 제공한다.

사용자는 다음 두 경로 중 하나를 선택한다.

1. **샘플 회사로 체험**: 완성된 가상기업, 데이터, 앱, 시나리오, 보고서를 즉시 실행한다.
2. **우리 회사에 복사**: 샘플 회사의 정의·계약·계산식·앱·시나리오를 복사한 뒤, 합성 데이터를 실제 회사 데이터로 순차 교체한다.

Starter Kit는 데모 자산이면서 동시에 다음을 수행하는 제품 자산이다.

- 산업·업무별 표준 데이터 요구사항의 선제안
- 생성 앱과 경영 Twin이 공유하는 의미·키·단위·기간 기준 제공
- 사용자의 데이터 준비 작업을 구체적인 업로드·연결·승인 업무로 전환
- 데이터가 부족한 상태에서도 가능한 범위와 차단 범위를 명확히 표현
- 실제 데이터 도입 전 기능·권한·계산·성능 검증
- 회사별 구축을 매번 처음부터 수행하지 않게 하는 반복 가능한 제품 패키지

## 2. 제품 목표와 비목표

### 2.1 목표

첫 번째 Starter Kit는 다음 수직 폐루프를 실제 데이터와 같은 구조로 재현한다.

```text
원료 가격·환율·운임
        ↓
구매계약·발주
        ↓
외부 협업 시스템의 선적·통관·운송 사건
        ↓
입고·재고·생산계획·수율
        ↓
출하·매출·원가·현금흐름
        ↓
경영 시뮬레이션
        ↓
의사결정 검토서·회의·실행과제
        ↓
실행 결과와 계획 차이 측정
```

첫 제품 키트의 식별자는 다음으로 고정한다.

```text
kit_id       = KIT-MFG-NONFERROUS-PROCUREMENT
version      = 1.0.0
industry     = 비철금속·배터리소재 제조
primary_loop = 원료 구매·도입계획 → 생산·재무 영향 → 의사결정·효과 측정
```

### 2.2 비목표

- 범용 ERP·MES 전체 데이터를 복제하지 않는다.
- 합성 데이터를 실제 회사 실적이나 예측 정확도 증거로 사용하지 않는다.
- 외부 거래처·관세사·운송사에게 AI Factory Studio 계정을 발급하지 않는다.
- 원천 시스템의 자격증명을 생성 앱이나 LLM 프롬프트에 제공하지 않는다.
- 업종별 예외를 제품 공통 스키마에 무제한 추가하지 않는다.
- 문서와 RAG 검색 결과를 재무·생산 수치의 원장으로 사용하지 않는다.
- 독립적으로 생성한 무작위 행을 현실적인 경영 데이터라고 부르지 않는다.

## 3. 현재 자산의 판정과 정리 원칙

### 3.1 재사용 가능한 자산

| 자산 | 재사용 범위 | 보완 필요사항 |
|---|---|---|
| `battery_material_m1.json` | 품목·BOM·설비·품질 후보 | 합성 표시, 단위·가격 검증, 계약·거래 데이터 추가 |
| `copper_smelting_m2.json` | 동제련 품목·공정 후보 | 유효기간·조직 범위·근거 등 메타데이터 추가 |
| `global_standard_m3.json` | ERP 규칙·KPI·표준 후보 | 승인 상태·적용 범위·버전·출처 연결 |
| `digital_twin_simulation_m4.json` | 공정·텔레메트리·시뮬레이션 후보 | 결정론적 계산 계약과 Golden Case 연결 |
| `external_intelligence/*` | 외부 사건·지표 Fixture | 공식 원천·관측값·시나리오를 분리 |
| `docs/reference/*` | 지식팩 후보 원본 | 승인 전 자동 색인·전수 프롬프트 주입 금지 |
| 데이터 카탈로그·용어·계보·계약 API | 등록·검색·추적 기반 | Starter Kit manifest와 자동 등록 배선 필요 |

### 3.2 기존 `ls_mnm_realistic_enterprise_seed.json` 판정

현재 파일은 품목 11개, BOM 2개, 설비 6개, 품질 기준 2개와 조직·경제 변수 일부를 가진다. 이는 **기준정보·UI·API 개발 Fixture**이지 실제 경영환경을 재현하는 데이터셋이 아니다.

제품 기본 키트와 다음처럼 분리한다.

| 구분 | 기존 파일 | 제품 Starter Kit |
|---|---|---|
| 목적 | 내부 개발·회귀 Fixture | 제품 체험·온보딩·수직 폐루프 검증 |
| 회사명 | 실제 회사와 유사한 명칭 | 명시적 가상기업 |
| 데이터 표시 | 불충분 | 모든 레코드에 `SYNTHETIC`·목적·버전 표시 |
| 기간 | 실적 시계열 없음 | 36개월 인과형 시계열 |
| 거래 | 거의 없음 | 구매·물류·재고·생산·판매·재무 연결 |
| 검증 | 건수 중심 | 대사·인과·Golden Case·권한·계보 검증 |

기존 파일은 향후 다음 메타데이터를 의무화하고 제품용 복사 대상에서는 제외한다.

```json
{
  "data_origin": "SYNTHETIC",
  "purpose": "ENGINEERING_FIXTURE",
  "not_for_management_decision": true,
  "company_identity": "REFERENCE_ONLY"
}
```

## 4. 샘플 회사 기준 모델

### 4.1 기본 회사

제품 기본 가상기업은 실제 회사와 혼동되지 않도록 다음 명칭을 사용한다.

```text
AFS 데모소재그룹 [VIRTUAL / SYNTHETIC]
├─ AFS 메탈 주식회사 [LEGAL_ENTITY]
│  ├─ 전사공통 [경영관리·재무·IT]
│  └─ 제련사업부
│     └─ 제1공장 [제련·정제]
└─ AFS 첨단소재 주식회사 [LEGAL_ENTITY]
   ├─ 전사공통 [경영관리·재무·IT]
   └─ 배터리소재사업부
      ├─ 제2공장 [황산니켈]
      └─ 증설 제3공장 [VIRTUAL EXPANSION]
```

### 4.2 회사 모델의 목적

- 그룹–법인–사업부–공장 권한 상속 검증
- 법인별 통화·회계·계약과 그룹 연결 손익 검증
- 공장 간 품목·재고·생산능력 차이 검증
- 전사공통 조직과 사업부 전용 데이터 분리 검증
- 가상 증설 공장을 통한 신사업·사업 확장 시뮬레이션
- 향후 경쟁사 Profile을 별도 `COMPETITOR` 모드로 추가할 수 있는 기준 제공

### 4.3 Quick Demo와 Full Demo

| 구분 | Quick Demo | Full Demo |
|---|---:|---:|
| 법인 | 1 | 2 |
| 사업부·공장 | 1개 사업부·1개 공장 | 2개 사업부·3개 공장(가상 포함) |

### 4.4 추가 가상회사 Profile

기준회사 하나만 제공하면 사용자가 가상회사 기능을 단순 복사 기능으로 오해한다. Starter Kit은
회사 선택·복사·신사업·해외진출·증설 비교를 바로 체험할 수 있도록 다음 Profile을 함께 제공한다.

| Profile | 유형 | 주 검증 목적 |
|---|---|---|
| AFS 데모소재그룹 | 기준 샘플회사 | 원료 구매 폐루프와 전체 데이터 계약 |
| AFS 배터리소재 제3공장 증설안 | 증설 | 생산능력·전력·원료·현금 영향 |
| AFS 순환금속 리사이클링 신사업안 | 신사업 | 회수율·스크랩 가격·탄소가치·투자수익 |
| AFS 글로벌 제련법인 진출안 | 해외법인 | 물류·환율·세율·투자·연결손익 |
| AFS 스마트 전력기기 신규법인안 | 인접산업 | 자동화·고용·품질·납기 영향 |
| AFS 북미 해저케이블 생산법인안 | 해외 생산법인 | 수주·구리 가격·현지조달·CAPEX 영향 |

추가 가상회사는 모두 `entity_mode=VIRTUAL`, `status=DRAFT`, `data_class=SYNTHETIC`이다.
복제 원본·목적·만료일이 반드시 있고 거래·원장·개인정보·외부 시스템 자격증명은 복사하지 않는다.
가상 문맥에서는 외부 운영 시스템 호출과 실제 의사결정 반영을 차단한다.

| FIN-02 | 매입·미지급·매출채권 | 지급·회수 일정과 운전자본 계산 |
| FIN-03 | 예산·회계실적·현금흐름 | 계획 대비·손익·현금 전망 |

### 6.6 외부환경·지식·시뮬레이션·결정

| ID | 데이터셋 | 목적 |
|---|---|---|
| EXT-01 | 환율·금리·물가 | 통화 환산·금융비용·거시 시나리오 |
| EXT-02 | 원자재·제품 기준가격 | 계약가격·매출가격의 외부 Driver |
| EXT-03 | 운임·에너지·기상·산업지표 | 물류·원가·가동·수요 위험 Driver |
| KNW-01 | 표준서·계약·규정·연구자료 | 계산·판단의 설명 근거와 업무 안내 |
| SIM-01 | Driver·계산식·제약 | 결정론적 계산 그래프 |
| SIM-02 | 기준·위험·대안 시나리오 | What-if 실행과 비교 |
| DEC-01 | 결정·실행과제·효과 | 결정 전후 폐루프와 학습 데이터 |

총 35개 데이터 등록 패키지로 구성한다.

- **운영 기준선 28개**: FND 3 + MDM 8 + PRC 2 + LOG 5 + INV 2 + MFG 3 + QLT 1 + SLS 1 + FIN 3
- **Twin·근거·결정 완성 7개**: EXT 3 + KNW 1 + SIM 2 + DEC 1

운영 기준선 28개는 구매–물류–재고–생산–판매–재무의 물량·금액을 닫는 필수 범위다. 나머지 7개까지 연결해야 외부환경 시나리오, 설명 근거, 의사결정·효과 측정을 포함한 제품 폐루프가 완성된다.

## 8. 데이터 생성 원칙

### 8.1 독립 난수 생성 금지

데이터는 업무 사건과 회계·물량 대사가 맞도록 순서대로 생성한다.

```text
외부지표·계약
  → 구매계획·발주
  → 선적·통관·입고
  → 재고 이동
  → 생산 투입·산출·수율
  → 출하·매출
  → 원가·매입·미지급·현금
  → 손익·KPI
```

### 8.2 필수 보존 등식

```text
기말재고 = 기초재고 + 입고 + 생산 - 투입 - 출하 ± 조정

구매원가 = 수량 × 계약가격 + 프리미엄 + 운임 + 보험 + 관세 ± 환율·헤지효과

생산량 = 투입량 × 실제수율

생산능력 = 정격능력 × 가동가능시간 × OEE

매출총이익 = 매출 - 재료비 - 가공비 - 물류비 - 품질손실

기말현금 = 기초현금 + 회수 - 구매지급 - 운영비 - 투자지출
```

### 8.3 재현성

- Generator 버전과 random seed를 기록한다.
- 같은 입력·버전·seed는 같은 결과를 생성한다.
- 시나리오 충격은 기준 데이터 복사본이 아니라 변경 이벤트와 계산 결과로 저장한다.
- 원본 기준선은 변경하지 않는다.
- 생성 오류와 대사 불일치는 조용히 보정하지 않고 실패시킨다.

기본 복사 대상:

- 데이터 계약과 의미 모델
- 산업 표준 코드·동의어·품질 규칙

- 예시 사용자·권한

- 다른 회사의 실제 데이터
- 원천 시스템 자격증명
- 실제 사용자 개인정보
- 승인되지 않은 지식 문서

### 12.3 실제 데이터로 교체

```text
SYNTHETIC
  → 사용자 파일 또는 읽기 연결 등록
  → RAW Snapshot
  → 코드·단위·조직 Crosswalk
  → QUARANTINE 분리
  → STANDARDIZED
  → 원천 건수·수량·금액 대사
  → 데이터 오너 승인
  → CERTIFIED ACTUAL 기준선
```

사용자는 전체 데이터를 한 번에 준비하지 않고 데이터셋 단위로 교체한다. 시스템은 교체할 때마다 다음을 다시 계산한다.

- 데이터 준비도
- 현재 사용 가능한 앱·보고서·시뮬레이션
- 합성값 의존 비율
- 차단된 계산과 다음 준비 작업

## 14. 외부 데이터와 지식의 경계

### 14.1 외부 참여자

거래처·관세사·포워더·운송사는 고객사가 이미 사용하는 공급사 포털·물류·통관 시스템에 데이터를 입력한다. AI Factory Studio는 외부 참여자용 업무 시스템을 재구축하지 않는다.

Starter Kit에는 특정 LPL 스키마가 아니라 다음 범용 Query Contract만 포함한다.

- `partner_submission`
- `shipment_milestone`
- `customs_clearance`
- `transport_milestone`

고객사별 어댑터가 기존 시스템을 이 계약에 매핑한다.

### 14.2 외부지표

- 공식·검증 원천의 Reference 관측값을 우선한다.
- 실구매 단가·청구 전기료·회사 운임을 공개 지표로 대체하지 않는다.
- 외부지표는 Driver 또는 비교 기준으로 사용하며 적용식과 시차를 승인한다.
- 발표일·관측일·수정판·라이선스를 보존한다.

### 14.3 지식 문서

- 원본이 존재한다는 이유만으로 프롬프트에 넣지 않는다.
- 승인·조직 범위·분류·유효기간을 통과한 문서만 지식팩에 포함한다.
- 문서는 설명·근거 검색에 사용하고 계산 수치의 원장은 데이터셋이 담당한다.

## 15. 품질·권한·감사 원칙

### 15.1 품질

- 필수 키 중복 0건
- 계약–발주–선적–입고 참조 무결성
- 물류 사건 시간 순서 유효성
- 품목·단위·통화·조직 Crosswalk 성공
- 재고 물량 대사
- 구매·매입·지급 금액 대사
- 생산 투입·산출·수율 대사
- 손익과 현금 흐름의 연결 검증

### 15.2 권한

- 모든 데이터는 명시적 `scope_node_id`를 가진다.
- 미바인딩 데이터는 누구에게도 노출하지 않는다.
- 앱 전달·수락은 데이터 권한을 확대하지 않는다.
- 가상기업 데이터는 REAL 회사 범위로 승격하지 않는다.
- 타 법인·사업부 데이터 존재 여부를 404 정책으로 은폐한다.

### 15.3 감사·계보

사용자 질문
  → 사용 데이터셋·Snapshot

  → 계산식·시나리오
  → 결과·보고서

  → 실행과제

## 16. 완료 정의

Starter Kit v1은 다음이 모두 충족될 때 완료다.

1. Quick·Full 두 프로필을 재현 가능하게 생성한다.
2. 35개 데이터셋이 manifest와 계약에 등록된다.
3. 운영 기준선 28개 데이터셋이 한 수직 폐루프로 연결된다.
4. 모든 합성 데이터에 `SYNTHETIC` 표시와 계보가 있다.
5. 구매–물류–재고–생산–재무 대사가 허용 오차 안에 있다.
6. Golden Case 10개 결과가 허용 오차 내에서 재현된다.
7. 사용자 역할에 따라 동일 질문의 데이터 범위가 달라진다.
8. 앱 5개와 보고서 5개가 같은 ID·단위·버전을 사용한다.
9. 데이터 하나를 제거하면 관련 계산이 꾸며지지 않고 `BLOCKED_BY_DATA`가 된다.
10. `우리 회사에 복사` 후 합성 데이터를 실제 데이터로 데이터셋 단위 교체할 수 있다.
11. 최소 한 개 운영 Snapshot이 향후 RAW→CERTIFIED 경로로 교체될 자리를 가진다.
12. 샘플 결과를 실제 경영 정확도 증거로 표현하지 않는다.

## 17. 제품 확장 원칙

Starter Kit는 고객별 코드 포크가 아니라 버전형 제품 자산이다.

```text
Core Kit
  + Industry Extension
  + Company Overlay
  + Source Adapter Profile
  + Approved Knowledge Pack
```

- 산업 공통 정의는 Core·Industry에 둔다.
- 회사 특성은 Company Overlay로 분리한다.
- 원천 시스템 차이는 Adapter Profile로 분리한다.
- 실제값은 회사별 데이터 영역에만 저장한다.
- 키트 업데이트는 데이터 계약·계산식·앱 영향 diff를 제공한다.
- 기존 회사 개정값을 자동 덮어쓰지 않는다.

## 18. 최종 제품 메시지

> AI Factory Studio는 사용자에게 빈 데이터베이스를 주지 않습니다. 산업과 업무에 필요한 데이터, 표준, 앱, 시나리오와 보고서를 샘플 회사에 미리 완성해 제공합니다. 사용자는 먼저 그대로 실행해 효과를 확인하고, 준비된 양식에 맞춰 자기 회사 데이터로 순차 교체합니다. 데이터가 부족해도 가능한 범위와 다음 행동을 제시하며, 합성값과 실제값을 절대 혼동하지 않습니다.
