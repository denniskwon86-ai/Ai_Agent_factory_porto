# LAXS-M 문서 분석과 소개 영상 기획

작성: Codex · 2026-09-10 · 버전 1.0 · 내부 검토용

## 1. 제품을 어떻게 이해했는가

**LAXS-M의 목적은 기업이 자신의 업무와 데이터를 이해하고, 현업이 필요한 실행 도구를 만들며, 경영진이 선택지의 영향을 검토하고 그 결과로 학습하는 능력을 회사 안에 축적하는 것이다.** 앱 생성·에이전트·RAG·온톨로지·디지털트윈은 이 목적을 실현하는 수단이다. 중심은 제조기업의 경영이며, 기능의 수보다 업무에서 판단과 실행 효과까지 이어지는 연결이 중요하다.

제품의 뿌리는 AI Factory Studio의 소프트웨어 생산 공장이다. Product Bible은 이를 현업 주도의 전사 운영 플랫폼으로 확장했고, 8월 3일 전략은 제품 범주를 **Manufacturing Management Twin & Operational App Factory**로 구체화했다. 현행 공식 소개·제안 자료는 이를 LS MnM의 AX 경영 플랫폼인 **LAXS-M**으로 설명한다. 따라서 영상에서는 LAXS-M을 제품명으로 사용하고, AI Factory Studio는 개발·제품 철학의 계보로 이해한다.

LAXS는 ‘랙스’로 읽는다. L과 S 사이의 AX는 LS의 업무와 경영 안에 AX를 내재화한다는 의미다. 이름의 해설은 로고를 설명하는 장식이 아니라 제품 사상의 압축이다. 현업의 업무 방식, 전사 공통 데이터, 경영 판단과 실행 책임이 같은 운영체계로 이어진다는 메시지다.

### 핵심 사상 여덟 가지

| 사상 | 문서에서 읽은 의미 | 영상으로 번역할 메시지 |
|---|---|---|
| 현업의 주도권 | 현업은 긴 프롬프트·코드·데이터 모델을 작성하는 개발자가 아니라 업무 목적과 판단기준을 설명하는 사람이다. | ‘현업의 생각을 업무 앱으로’ |
| 아래에서 자라는 전사 플랫폼 | 작은 부서 앱의 데이터·업무 규칙·승인 이력이 전사 지식과 의미 모델로 축적된다. | 작은 업무 카드들이 하나의 기업 지도로 연결됨 |
| 부서 자율성과 전사 일관성 | 부서는 필요한 앱·시뮬레이터를 구성하되 회사·조직·데이터 계약·기준선을 공유한다. | 다섯 부서가 하나의 공통 기반 위에 놓임 |
| 의미의 연결 | 품목·거래처·공정·재고·계정·KPI를 동일한 뜻과 관계로 연결한다. | 구매→재고→생산→판매→재무의 영향 경로 |
| 생성보다 신뢰 | 생성물은 요구·데이터 원천·권한·테스트·릴리스·운영 정보와 함께 제공되어야 한다. | 생성 과정 사이에 검증과 사람 확인이 존재 |
| AI·계산·사람의 역할 분리 | AI는 해석·설명·제안을 지원하고, 승인된 데이터와 산식이 계산하며, 사람이 중요 결정을 책임진다. | ‘데이터·산식으로 계산, 사람이 결정’ |
| 실행 후 효과까지 연결 | 판단·승인·실행·실적·예상 대비 차이·검증된 학습이 다시 다음 업무에 연결된다. | 단방향 화살표가 마지막에 순환으로 닫힘 |
| 기존 시스템과 공존 | ERP·MES·LPL 등은 원천 업무와 사실의 책임을 유지한다. 승인된 범위의 읽기 연계부터 시작한다. | 기존 시스템이 지워지지 않고 아래층에서 연결됨 |

### 세 제품면과 공통 기반

1. **현업 앱 공장:** 요구 정제, 업무키트, 에이전트 구성, 앱 생성·검증·릴리스·운영.
2. **기업 경영 의미지도:** 기준정보, 데이터 위치·품질·오너, 문서와 지식, 승인된 업무 관계와 영향 경로.
3. **경영 디지털트윈:** 부서별 가정과 결과를 전사 손익·현금·납기 영향으로 조합하고 대안을 검토.

세 제품면 아래에는 회사·조직 문맥, 권한, 데이터 계약, 시점·버전·지문, 확정 산식, 감사·비용·발간 통제가 놓인다. MDM, 카탈로그, 온톨로지, RAG, 계산 엔진은 서로 다른 책임을 가진다. 영상의 짧은 문구는 이 구분을 지우지 않아야 한다.

업무키트는 앱 템플릿 한 장보다 넓다. 입력 필드·코드·단위·규칙·데이터 계약·관리 화면·에이전트·계산 모델을 재사용하는 실행 자산이다. ‘맨땅에서 앱 만들기’보다 ‘회사의 업무 기준에서 시작하기’라는 진입 경험을 강조하는 편이 제품 의도에 맞다.

**읽힌 사업 논리:** MnM의 대표 업무에서 현업 채택과 실제 효과를 증명하고, 공통 코어·업무키트·운영 방법을 재사용해 전사와 그룹으로 확장한다. 독립 제품조직의 제안은 단발 개발을 넘어 제품 로드맵·품질·운영·확산에 지속적인 책임을 부여하려는 취지다. 비용과 ROI는 확정 성과가 아니라 적용 범위와 실측을 전제로 한 의사결정 자료다.

20초에는 조직·가격·ROI·전체 기능 목록을 넣지 않는다. 시청자가 ‘무엇을 위한 플랫폼인가’를 기억하도록 한다. 90초 본편에서는 가치 흐름을 이해시키고, 도입 논의는 별도의 제안 자료로 이어지게 한다.

## 3. 문서를 대조하며 확인한 표현상의 주의점

### 정본의 역할과 기준일을 구분

Product Bible과 전략은 철학의 상위 기준이다. 7~8월 문서의 ‘미구현’ 목록을 9월 현재 판정으로 그대로 가져올 수는 없다. 반대로 최신 공식 브로셔의 현재형 기능 설명만으로 실운영 완성을 판정할 수도 없다. 이번 분석은 철학·공식 메시지·최근 검증 기록을 대조한 문서 분석이며, 시스템 전체 코드를 새로 감사하거나 실데이터 E2E를 실행한 결과는 아니다.

### 시연 숫자와 성과를 구분

브로셔에는 원료 도입 지연 14일·원료 가격 +10% 등의 시나리오와 영향 수치가 있고, 기능설명서에는 12일 지연·환율 +3.5%·전력단가 +8%의 DEMO/SYNTHETIC 사례가 있다. 서로 다른 예시와 기준선이므로 하나의 시연인 것처럼 결합하지 않는다. 숫자를 본편에 쓰는 경우 한 실행의 데이터·가정·산식·결과를 묶어 보여주고, 합성 자료임을 읽을 수 있게 표시해야 한다. 이번 20초 샘플은 영향 수치를 사용하지 않는다.

### 최근 검증 기록의 경계

9월 9일 세션 인계·기준선 정리와 9월 10일 결정 자료에는 실제 원천 승인·실측 수집·탄력도 근거·인증 자료의 앱 연결 등 남은 항목이 기록되어 있다. 최근 전체 통합 시험과 브라우저 확인도 미완 항목으로 명시되어 있다. 따라서 ‘실제 기업 운영을 자율적으로 최적화한다’, ‘정확한 경영 예측을 완성했다’, ‘입증된 절감률’ 같은 주장은 사용하지 않는다.

### 문구를 다듬을 지점

- 브로셔의 ‘작은 현업 앱이 쌓일수록 전사 경영 모델은 더 정확해집니다’는 데이터 품질·모델 검증·대사·학습 승격 조건이 생략되어 있다. 영상에서는 **‘검증된 업무 지식이 다음 판단의 기반으로 쌓입니다’**로 표현한다.
- ‘AI는 실행한다’는 표현에는 조직 권한·정책·사람 확인이라는 조건이 있다. 영상에서도 승인 단계를 생략하지 않는다.
- ‘학습’은 고객 데이터를 외부 LLM 학습에 자동 투입한다는 뜻이 아니다. 업무 결과·근거·규칙·템플릿·검증 이력이 회사 자산으로 환류하는 뜻이다.
- ‘경영 디지털트윈’은 공장 3D 시각화보다 운영과 재무의 대안을 재현 가능하게 비교하는 모델에 가깝다. 로봇·우주·공장 홀로그램보다 업무 연결도를 주된 시각 언어로 쓴다.

## 4. 권장 영상 방향

**콘셉트: 현업의 작은 생각이 회사의 더 나은 판단이 되기까지.**

주 대상은 LS MnM 경영진·현업 책임 사용자, 보조 대상은 PI/IT·데이터 조직으로 가정한다. 전달할 감정은 ‘막연한 미래 기술’보다 ‘우리 회사의 일이 연결되고 판단에 근거가 생긴다’는 이해와 신뢰다.

주 메시지: **현업의 실행과 경영의 판단을 연결하는 AX 경영 플랫폼, LAXS-M.**

기억할 세 문장:

1. 현업이 업무 언어로 필요한 앱과 업무 모델을 만든다.
2. 부서의 데이터와 지식이 같은 전사 기준으로 연결된다.
3. 경영의 판단·실행·효과가 다음 업무의 자산으로 쌓인다.

연출은 공식 브로셔의 네이비·레드·시안과 넓은 여백을 계승한다. 점과 선은 실제 업무·데이터·의미·영향 관계를 표현하는 데만 사용한다. 한 장면에는 주 메시지 하나와 이를 설명하는 그림 하나를 둔다. 모든 장면이 명료한 한국어를 중심으로 읽혀야 한다.

## 5. 90초 본편 구성안

본편은 대표 사례 **‘원료 도입이 늦어지면 생산·출하·현금은 어떻게 달라지고, 누가 무엇을 결정해야 하는가?’**를 끝까지 따라간다. 이 사례는 8월 3일 전략의 첫 수직 폐루프와 공식 소개 자료의 제조 경영 흐름에 맞는다.

| 시간 | 화면·연출 | 내레이션 초안 | 시청자가 이해할 것 |
|---|---|---|---|
| 0–10초 | 같은 ‘원료 도입 지연’ 사건이 구매 메일·생산 계획·재무 보고에 따로 나타남. 서로 다른 기준시점 강조 | ‘원료 도입이 늦어지면, 생산과 납기, 회사의 현금은 어떻게 달라질까요? 답을 찾는 동안 자료는 다시 모이고, 판단은 늦어집니다.’ | 경영의 문제는 업무 사이의 단절 |
| 10–22초 | 구매 담당자의 업무 목적 입력→업무키트 선택→앱 설계·검토. 실제 화면은 핵심 입력 영역만 확대 | ‘LAXS-M은 현업의 업무 언어에서 시작합니다. 필요한 앱과 업무 모델을 만들고, 회사의 데이터와 권한 기준 안에서 운영합니다.’ | 현업이 문제 해결의 주체 |

**구현 형식:** 16:9, 1920×1080, 30fps, 600프레임, 20초, H.264/AAC MP4. 한국어 자막을 화면에 삽입하고 SRT도 별도로 제공한다. 자연스러운 등장·연결 점의 이동·짧은 크로스페이드를 사용한다. AI 생성 실사 영상이나 제품 조작 녹화가 아닌 코드 기반 모션그래픽이다.

**음향:** 로컬 Windows Microsoft Heami 한국어 합성 음성, 직접 합성한 잔잔한 화음과 연결음. 내레이션을 명료하게 들려주는 검토용 음향이다. 본편 최종판은 전문 성우의 호흡과 억양으로 교체하면 전달력이 높아진다. 이번 샘플에 외부 음악·유료 영상·스톡 푸티지는 사용하지 않았다.

**브랜드:** 공식 브로셔의 색상 체계와 기존 로고를 사용한다. 로고 원본 파일은 변경하지 않고 종횡비를 유지해 영상에 배치한다. 샘플의 앱 카드와 연결도는 제품 비전을 설명하는 개념도이며 실제 구현 화면인 것처럼 표시하지 않는다. 영상 하단의 ‘제품 비전 · 콘셉트 영상’ 표기를 유지한다.

## 7. 본편 제작 시 촬영과 편집 기준

현행 기능설명서의 생성·온톨로지·시뮬레이션·결정·보고 화면은 촬영 후보를 찾는 데 유용하다. 그러나 저장된 캡처에 있는 기능과 숫자는 현재 실행의 증명이 아니다. 실제 화면 촬영은 고정된 데모 데이터와 동일한 실행으로 별도 확보한다.

촬영 후보: 업무 목적 입력 → 업무키트·생성 계획 → 회사 데이터 연결 → 영향 관계 → 기준안·대안 → 의사결정 안건 → 실행 책임·효과. 화면 전체를 오래 보여주기보다 해당 장면의 주제에 맞는 영역을 확대하고, 화면 캡처·설명 도식·비전 장면의 성격을 구분한다.

첫 관람 점검은 세 가지면 충분하다. ‘이 제품을 왜 쓰는지’ 한 문장으로 설명할 수 있는가, ‘누가 판단하고 숫자는 어디서 나오는지’ 이해했는가, ‘앱을 만든 뒤 회사에 무엇이 남는지’ 기억하는가. 기능명을 얼마나 많이 기억했는지를 성공 기준으로 삼지 않는다.

## 9. 이번 작업의 위치와 완료 경계

이번 작업은 사용자가 명시적으로 요청한 소개 영상 기획·샘플 제작이다. 로드맵의 제품 구현 관문을 전진시키는 코드 작업이 아니라 §17 제품·사업 준비에 해당하는 커뮤니케이션 산출물이다. 영상 완성을 G1~G9 제품 구현 완료나 G8 ROI 검증으로 계산하지 않는다.

생성물은 이 디렉터리에 격리했다. 기존 공식 문서·로고·제품 소스·운영 DB·다른 작업자의 변경을 수정하지 않았다. 외부 게시와 공유는 수행하지 않았다. 영상 파일 자체의 기술 검증은 `verification.json`과 `media_info.txt`에 기록한다.
