03 · Operating Rhythm

매주 같은 입력·검토·결정·실행 리듬을 반복합니다.

07 · Operation & Scale Boundary

1단계는 최대 10명에 맞추고, 다음 규모는 실측 후 별도 승인합니다.

초기 비용을 최소화하되 복구·감사·데이터 무결성을 희생하지 않습니다. 사용자 증가와 동시 쓰기 요구가 확인되면 PostgreSQL 기반 운영으로 전환합니다.

STAGE 1 · FIELD ADOPTION

최대 10명 · 90일

Naver Cloud 소형 VM, 도메인·TLS, 제한 접속, 자동 백업과 복구 실증으로 운영합니다.

  • 단일 회사 문맥·4개 업무키트
  • 비용 상한과 사용량 모니터링
  • 운영 데이터·합성 데이터 구분
  • 백업 사본 복원 1회 실증
STAGE 2 · CONTROLLED SCALE

평시 30명 · 최대 50명

1단계 효과와 부하 증거를 검토한 뒤 PostgreSQL, 앱·DB 분리, 모니터링과 정기 복구 체계로 전환합니다.

  • 동시 쓰기·응답시간·가용성 기준
  • DB 마이그레이션과 롤백 실증
  • SSO·보안·감사 연계 강화
  • 추가 업무키트와 운영 SLA
TECHNICAL GATE

안정성

응답시간, 동시성, 오류율, 백업·복구, 운영 데이터 무오염

BUSINESS GATE

효과

GOVERNANCE GATE
