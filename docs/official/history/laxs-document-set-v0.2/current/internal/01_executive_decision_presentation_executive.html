01. Crisis & Strategic Choice

현재 접근의 한계와 LAXS-M이 제안하는 전환

Slide 03 / 20
환율·원가·수요가 빠르게 변하는 환경에서는 사후 집계만으로 대응 시점이 늦어집니다. 실행 전에 대안을 비교하고, 결정 이후 실제 효과까지 추적할 수 있는 체계가 필요합니다.
방식 A · 개별 AI 도구
업무별 AI 기능 파편화
챗봇·문서요약이 개별 존재하지만 사내 데이터 및 경영 결정과 연결되지 않아, 과제 종료 후 회사의 잔존 자산으로 축적되지 못하고 소멸함.
방식 B · 프로젝트형 SI
외부 SI 중심 반복 개발
현업 요구가 바뀔 때마다 재설명과 계약 변경이 필요해 리드타임과 비용이 누적되고, 내부에 제품 운영역량이 충분히 축적되기 어려움.
제안 · LAXS-M
현업 주도 자율진화 경영 OS
회사 데이터와 업무지식을 공통 기반으로 활용하고, 현업의 실행 결과와 의사결정 근거를 다음 업무에 재사용할 수 있는 운영체계.
전략적 판단 기준
"우리 회사의 AX 전략은 'AI를 어디에 적용할 것인가'가 아니라, '회사가 환경 변화에 맞춰 필요한 디지털 업무와 경영 판단을 얼마나 빠르게 스스로 만들어낼 수 있는가'를 내재화하는 것입니다."

02. Unrivaled Strengths

LAXS-M이 제공하는 5대 차별화 역량

Slide 04 / 20
STRENGTH 01
기업 지식 주권 확보
MDM, 데이터 카탈로그, 용어 Crosswalk를 회사가 직접 통제하여 모든 AI가 동일한 전사 문맥체계를 공유함.
STRENGTH 02
현업 주도 SW 생산
개발자 없이 Power User 요구 시 AI Agent가 기획·구현·QA를 수행해 사내 권한 상속 App-in-App으로 배포.
STRENGTH 03
사전 시나리오 검증
환율·원가·수요 변동이 손익과 현금에 미치는 영향을 승인된 입력·산식·버전에 결속해 반복 검증할 수 있음.
STRENGTH 04
Decision Closed Loop
시뮬레이션 ➔ 경영 승인 ➔ 실행 ➔ 사후 효과 검증이 피드백되어 회사의 판단 지능이 지속 상향 진화함.
STRENGTH 05
Private RAG 통제
사내 원본은 내부 통제영역에 두고, 권한과 목적에 맞는 최소 문맥만 기업용 모델 호출에 사용하며 사용량을 관리함.
경영진 관점의 핵심 가치
LAXS-M의 본질은 화려한 AI 답변이 아니라, 어떤 데이터·가정·권한·계산을 근거로 결론이 도출되었는지 추적하고 다시 검증할 수 있는 경영 판단 체계를 제공하는 것입니다.

03. Strategic Pillars

현업 실행과 경영 판단을 연결하는 6대 설계 원칙

Slide 05 / 20
01. 기업 데이터·지식 주권
회사구조, MDM, 데이터 카탈로그, 업무표준, 문서, 용어와 관계를 회사가 직접 관리하고 모든 AI가 같은 의미체계를 공유하도록 통제합니다.
02. 현업의 SW 생산능력
Power User가 요구를 설명하면 AI Agent가 기획·설계·구현·검증을 수행하고 결과는 사내 권한을 상속한 App-in-App으로 운영됩니다.
03. 경영 Digital Twin
수요·환율·원료·에너지·고용 변화가 생산·재고·현금흐름·손익에 미치는 영향을 실제 데이터와 결정론 산식으로 실시간 비교 계산합니다.
04. Agentic Operating Model
업무별 AI Agent와 워크플로우를 생성·결합하고 AI 경영비서가 전사 문맥에서 질의, 진행 설명, 품질과 모델 비용 통제를 지원합니다.
05. Decision Closed Loop
시뮬레이션 결과가 검토서·회의·결정·실행과제로 이어지고, 실제 효과와 피드백이 다음 지식과 모델 개선에 반영되는 구조입니다.
06. 전사 데이터·지식 통합
각 부서 앱에서 생성되는 데이터와 지식을 공통 기준과 권한 아래 축적하여 부서 간 단절을 단계적으로 줄입니다.

05. Sandbox Simulation

가상 회사/사업부(Virtual Entity) 기반 신사업 & 경쟁사 시뮬레이션

Slide 07 / 20
"실제 조직 변경 전에 가상의 사업부나 가상의 경쟁사를 생성하여 신사업 투자 손익 및 시장 변화를 사전에 시뮬레이션합니다."
왜 이 기능이 필수적인가? (Why Needed?)
신규 공장, 신제품 라인, M&A처럼 불확실성이 큰 안건은 실제 자원을 투입하기 전에 가정과 민감도를 비교할 필요가 있음.
무엇을 얻을 수 있는가? (What We Gain?)
의사결정 전 대안 비교: 실제 자원 투입 전 가상 파티션에서 손익분기점(BEP), NPV, 현금 소요량을 비교하여 불확실성을 낮춤.
경쟁사 방어 및 검증된 산식
경쟁사 가격 인하 시 당사 마진 영향을 사전 산출하고, 사내 재무·기획 기준의 결정론적 손익 산식으로 계산 근거와 재현 가능성을 확보합니다.
시뮬레이션 적용 예시
• 유스케이스 1 (신규 해외 공장 가상 설립): 인도네시아 가상 법인을 미리 생성하여 투입 CAPEX, 원자재 물류비, 인건비 입력 ➔ 투자 3년 차 BEP 달성 가능 여부 사전 검증.
• 유스케이스 2 (경쟁사 A사 가격 인하 공격): 경쟁사 10% 단가 인하 시 당사 시장점유율 5% 감소 및 영업이익률 차감 추정 ➔ 최적 대응 단가 및 원가 절감 대응안 산출.

06. Legacy Integration

기존 시스템(ERP/MES/LPL) 교체 없는 전사 데이터 통합 3대 원칙

Slide 08 / 20

ERP·MES·LPL, 부서 파일, 외부 지표 등 기존 시스템을 교체하지 않고 연결하여 분산된 업무 데이터를 전사 하나의 경영 언어로 전환하는 3대 연동 원칙입니다.

01. SYSTEM OF RECORD 유지
ERP·MES·LPL 등 원천 거래 및 현장 데이터 시스템의 역할을 그대로 존중합니다. LAXS-M은 필요한 데이터만 복제·가상참조·집계하고 원천 위치와 변경이력을 보존합니다.
02. 외부 참여자 직접 개방 방지
거래처·통관사·운송사는 기존 LPL 포털에 입력하도록 유지하고 결과만 API·MCP·배치로 연계합니다. 경영 플랫폼 자체를 외부 참여자에게 개방하지 않아 사내망 보안을 강화합니다.
03. 목적 기반 논리적 통합
무조건적인 단일 거대 DB 복제가 아닌, 데이터의 성격과 보안 등급에 맞게 복제/가상참조/주기집계 방식을 선택하는 논리적 통합 계층을 형성합니다. 권한·품질·Lineage는 공통 통제합니다.

07. Business Domain Transformation

8대 경영 문제 해결 및 시뮬레이션 질문 예시 (Scenario Test)

Slide 09 / 20
01. 수주 · 판매
수주와 생산·출하 가능성을 연결하여 예상 매출, 지연 위험과 고객별 손익 조기 확인
02. 구매 · 원료
구매조건과 도착계획을 생산·재고·현금에 연결해 최적 발주 시점과 물량 대안 비교
03. 생산 · 설비
공정능력과 제약조건으로 시뮬레이션해 납기, 생산량, 원가와 병목 사전에 확인
04. 품질 · 추적성
원료–공정–제품–고객 관계를 연결하여 영향범위, 잠재 손실과 우선조치 신속 산정
05. 물류 · 재고
ETA와 생산소요, 안전재고를 연결해 지연경보와 재배치·대체조달 시나리오 제안
06. 재무 · 손익 · 자금
가격·물량·원가·재고·회수조건 연계로 Forecast와 Scenario 손익·현금 조기 계산
07. 경영계획
수요·가격·환율·원가·투자·인력 가정을 연결해 기준안·낙관안·비관안을 동일 기준으로 비교
08. 전사 의사결정
시뮬레이션 근거로 검토서를 만들고 결정–과제–실적을 연결하여 다음 판단 재사용
경영진이 직접 조정해 볼 수 있는 질문 예시
1. 환율이 5% 상승하면? 원료 매입 ➔ 재고평가 ➔ 제품원가 ➔ 영업이익 ➔ 현금소요
2. 전기료가 10% 오르면? 공정별 에너지비 ➔ 단위원가 ➔ 제품별 수익성 ➔ 판매전략
3. 원료 입항이 7일 늦어지면? 안전재고 ➔ 생산차질 ➔ 납기·매출 ➔ 대체조달 비용
4. 고용을 30명 늘리면? 인건비·교육기간 ➔ 생산능력 ➔ 추가매출 ➔ 손익분기 시점

08. Execution Proof

1호 권고 과제: 원료 구매·도입계획 ➔ 통관·물류 ➔ 생산 투입 ➔ 손익 영향 Closed Loop

Slide 10 / 20
"첫 적용은 기능 시연이 아니라 부서와 경영을 연결하는 하나의 Closed Loop 완주여야 합니다."
Step 1. 자료·업무기준 등록
계약·계획·실적·입항·재고·원료·환율·운임 자료와 용어를 시스템에 등록
Step 2. Power User 앱 생성
구매 담당자의 자연어 요구로 도입계획·추적 앱을 만들고 실제 업무주기에 사용
Step 3. 경영 시나리오 연결
물류·생산·경영관리 관점의 입력과 영향을 연계하여 대안 비교 산출
Step 4. 결정·실행·효과 학습
검토서와 결정 이후 실제 결과를 측정해 지식과 다음 시뮬레이션에 반영
검증할 운영 효율 지표
현재 수작업 취합시간과 재작업 횟수를 기준선으로 측정하고, LAXS-M 적용 후 동일 업무의 리드타임·오류·승인대기 변화를 비교합니다. 목표치는 실제 파일럿 결과로 확정합니다.

15. Instant Decision Agenda

경영진 의사결정 요청 안건 및 회의 종료 전 확정 사항

Slide 17 / 20
공식 의안 (Formal Agenda)
  1. 회사의 AX 전략을 `기업 데이터·지식 기반의 현업 SW 생성 + 경영 Digital Twin + Decision Closed Loop`로 확정
  2. LAXS-M을 해당 AX 전략의 공식 실행 플랫폼으로 지정
  3. 제안자를 AX & Product Lead로 하고 Power User 3~4명으로 구성한 전사 AX Core Team 승인
  4. 관련 부서에 Power User 지정, 자료·데이터 제공, 공식 업무시간 배정을 Top-down으로 지시
  5. 초기에는 기존 기술환경을 활용하고 추가 자원·비용은 필요성과 근거에 따라 항목별 승인
  6. 당사에서 확립한 AX 표준을 그룹 경영플랫폼으로 확장할 수 있도록 사내벤처 분리독립안을 처음부터 병행 설계
회의 종료 전 확정 항목
  • AX 전략 방향: 현업 실행과 경영 판단을 연결하는 운영체계 전환
  • AX & Product Lead: 제품 책임과 우선순위 조정 권한 지정
  • Power User 대상: 구매·생산·물류·재무 대표 선정
  • 자료·데이터 제공: 보안 범위 내 원천 데이터 접근 지원
  • 첫 Closed Loop: 원료 구매~손익 연계 과제 확정
  • 확산 검토 조건: 실사용·재사용·경제성 근거 충족 시 조직 대안 검토
