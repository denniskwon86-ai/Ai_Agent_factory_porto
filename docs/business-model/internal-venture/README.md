# 내부 사내벤처 제안 자료 패키지

> 목적: 회사의 AX 전략을 `기업 데이터·지식 기반 현업 SW 생성 + 경영 Digital Twin + Decision Closed Loop`로 확정하고, AI Factory Studio를 실행 플랫폼으로 삼아 소수 정예 AX Core Team과 Power User를 운영한다. 당사에서 검증된 AX 표준은 사내벤처 형태의 분리독립 운영체계를 통해 전 그룹사의 경영플랫폼으로 확장한다.

## 작성 원칙

- 최상위 메시지는 “이 제품을 채택하자”가 아니라 “우리 회사의 AX 전략은 이것이어야 하며 AI Factory Studio가 그 전략을 실체화한다”이다.
- 임원에게 `AX 전략방향 + AX & Product Lead + Power User 3~4명 + Top-down 자료/업무시간 지원 + 근거 기반 항목별 자원 + 사내벤처 분리독립안 병행 준비`를 요청한다. 별도의 Sponsor 지정 요청은 하지 않는다.
- 제품조직을 제안하는 이유는 개인의 독립이 아니라 제품 코어, 로드맵, 품질, 권한, IP, 반복 확산의 책임 주체가 필요하기 때문이다.
- 부서별 앱과 업무에서 만들어진 데이터·업무지식·Agent 실행결과는 전사 데이터베이스와 지식허브에 통합한다. 이를 계열사가 그대로 재사용한다는 의미로 설명하지 않는다.
- 사내 민감정보와 원본 문서는 회사 통제영역에서 관리하고 외부 LLM 학습자료로 제공하지 않는다. RAG로 권한·목적에 맞는 최소 문맥만 선별해 기업용 API 호출에 사용한다.
- LLM은 단일 고가 모델에 고정하지 않고 작업 난이도·보안등급·문맥길이에 따라 API로 라우팅한다. 경제적인 모델, 캐시, 결정론적 검증을 우선하고 필요할 때만 상위 모델을 사용한다.
- ERP·MES·외부 참여자 입력 포털·파일·공공 외부지표는 교체 대상이 아니라 원천 시스템이다. API·MCP·Event·Batch·File Connector로 필요한 데이터만 연결하고 Crosswalk·Data Contract·Lineage로 정합성과 추적성을 확보한다.
- 경영효과는 추상적인 생산성 향상이 아니라 수주·구매·생산·품질·물류·재무·경영계획의 현재 문제, 시스템의 지원방식, 손익·현금·위험·의사결정 변화로 구체적으로 설명한다.
- ITO는 초기 AX Core Team에 포함하지 않는다. 실운영 인프라·레거시 연계가 필요해질 때 협의하고, 그룹 확산 단계에서는 구축·운영 파트너 역할을 별도로 설계한다.
- 회사 내부 실제 데이터와 외부 공개용 자료를 분리한다.
- “좋은 아이디어”라는 평가가 아니라 AX 전략방향, AX Lead, Power User, 데이터 제공, 실행권과 사내벤처 준비 지시가 포함된 결정을 목표로 한다.
